# v0.23 review packet — what the owner is actually being shown

Status: DRAFT, sections 1–3 complete and stable. Sections 4–5 wait on the infix
reversal and the remaining case dispositions; their numbers are deliberately
absent rather than provisional. Removed when v0.23 activates or the candidate is
abandoned.

Purpose: a byte approval is a decision made on evidence, and this batch found
repeatedly that the evidence says less than it appears to. This packet exists to
state the gap between the two, so the approval is informed rather than merely
granted. Every claim below carries the command or file that reproduces it.

## 1. What the green signals do not mean

Three figures will be presented alongside the candidate. Each is true, and each
means materially less than its face reading.

### 1.1 "128/128 rules covered" counts NAMING, not exercise

Measured in `tests/conformance/runner.py`: `tagged |= set(c["rules"])` (line
315) and `covered = by_case | annotated` (line 327). **A rule counts as covered
when any case merely names it in its `rules` list** — not when a case's expected
verdict cites it, not when anything would fail if the rule stopped being
enforced, and with no notion of a rule's separate content pieces.

| | |
|---|---|
| reported covered | 128 (110 by case, 30 by annotation) |
| with a positive exercise | 109 |
| with a negative citing them | 45 |
| **with no negative at all** | **83** |
| with neither positive nor negative | 19 |

The runner already computes and prints both exercise sets — `[+109/-45]` at line
365 — but `covered` requires neither.

**The consequence, stated precisely.** A negative case fails when a rule stops
*rejecting*. So for those 83 rules, **a rule that silently stopped rejecting
would not be caught by this corpus**, and "128/128 covered, 0 uncovered" does not
distinguish that from a rule with a real negative.

**83 is not a defect count and must not be read as one.** Many of those rules
have no negative form at all: GRAM-1..5 are grammar productions exercised
positively, the DIAG rules constrain diagnostic shape, EX-1 is a worked example.
The honest claim is about what the metric asserts, not that 83 rules are
unguarded.

### 1.2 The corpus's green is partly unearned

A deliberate sweep found **at least two conformance cases that pass while
testing nothing**, and three more that still fire and cite the correct rule
while testing a different concern than the one they record.

- **Emptied** — subject deleted by the revision, case green:
  `fn2-pos-explicit-instantiation`, `type5-pos-explicit`.
- **Subject shifted** — written about a wrong written type argument, now
  rejecting on an operand domain: `op1-neg-eeq-integer`, `op1-neg-ene-integer`,
  `op1-neg-ineg-unsigned`. These are harder to detect than an emptied case: an
  emptied case can be caught by asking whether its rule still fires, whereas
  these fire *and* cite the correct rule, so a rule-level audit passes them.

**"At least" is load-bearing, for two separate reasons.**

First, the mechanical tell — a case whose doc names a construct its source no
longer contains — cannot see a case whose doc names no construct at all;
`type5-pos-explicit` was found by reading. The true count may be higher.

Second, and disclosed rather than quietly folded in: **the sweep read only one
of two doc surfaces.** It read the manifest's `doc` and `reason` fields and
never the in-language `doc "…"` statement inside each source. That second
surface was swept afterwards: 323 cases carry one, **12 name a construct their
own body no longer contains**, of which four have been read by hand and all four
are genuine — including `op7-pos-name-convention`, the case *about* naming
conventions, illustrating the convention with a name the language no longer has.
The remaining eight are being verified; the honest present figure is 12 hits, 4
confirmed, 1 of those four arguable — **not 12 defects**. Correcting an
in-language doc changes a case's bytes rather than a description of it, so
nothing there has been touched.

The two surfaces share the same blind spot, which is the more useful fact:
`fn2-pos-explicit-instantiation`'s in-source doc says "explicit type arguments"
in prose, naming no construct, exactly as `type5-pos-explicit` evaded the
manifest surface. **The limit is in the tell, not in the surface**, so sweeping
more surfaces does not raise the ceiling.

**The asymmetry is a property of our process, not of the migration.** A case
whose subject died turns red if it was negative and green if it was positive.
The red half was caught one case at a time across four rounds of ordinary work;
the green half surfaced only under a deliberate search, because nothing looks
for a test that passes without exercising its concern.

### 1.3 Rule content with no conformance case — four found, three closed

Three of these were **closed during the batch** rather than merely reported, and
the figures below are stated as found so the change is visible rather than
silently edited down.

A non-copy requires-clause local — the FN-8 copy restriction — was protected
only by a library test. A wrong-kind instantiation argument was FN-2 content
with no case at all, while FN-2 counted as covered on its other four carriers.
**Both now have one** (`fn8-neg-requires-noncopy-cvt-local`,
`fn2-neg-wrong-kind-instantiation-argument`), each a one-token differential
whose control compiles. A third gap found the same way — OP-1's written
argument on a de-argumented row, which had zero carriers — is closed by
`op1-neg-written-argument-on-deargumented-row`.

The fourth is closed by the grammar rather than by enumeration, is the
starkest, and is the one no case can close: FN-8's normative sentence says a
place is legal only as a **non-consuming** operand of an admitted table
operation. That states a *property*; the pass implements three *shapes*.
Under v0.23 the property has **no independent effect** — `atom` has exactly
four forms, each decided before consumption could matter, so every program the
sentence would reject is already rejected by OWN-1 or by a shape check.
Nothing distinguishes a compiler that enforces that sentence from one that
does not. Outcomes coincide, so this is not a soundness hole; it is rule
content that no program can exercise.

Same shape as §1.1: the accounting is per-rule, not per-content-piece. **Four
instances, each found by a different route** — an enumeration, a coverage
measurement, a grammar argument, and a zero-carrier check — which is enough to
say the class is not rare. It is not enough to say how common it is: nothing
here sampled rules systematically, so there is no denominator, and a reader
should resist reading four finds as a rate.

**Closing three of them moved the coverage figure by exactly zero**, and that
is the sharpest available demonstration of §1.1. Measured on a detached
worktree at the parent revision against the tree carrying all three:
`128/128 rules covered (110 by case [+109/-45], 30 by annotation)` on both
sides. The negative set is a set of **rule ids** —
`neg.add(c["expect"]["rule"])` in `tests/conformance/runner.py` — so a rule
that already has one negative cannot gain from another, however much content
it covers. Three real gaps closed, and nothing a reviewer reads changes.

## 2. What changed that the delta does not say

The candidate's §5 accounts for the accepted-program set as "one canonical
respelling plus three deliberate narrowings". Two items are missing from that
account.

### 2.1 A3's premise has one counterexample, and it removes an ability

A3 rests on the premise that a binder's mode and type are exactly what its
right-hand side produces. `tests/conformance/cases/own3-pos-outlives-store.wf`
wrote `let q: &'s i32 = &'r a;` inside `region 'r { region 's { … } }` — the
annotation names `'s`, the right-hand side names `'r`, and the case's own doc
states the subject: "an enclosing region outlives an inner one; a `'r` borrow
satisfies an `'s` **destination**". The annotation *was* the destination.

So v0.23 removes the ability to state a destination region for a local binding.
**OWNER DECISION REQUIRED:** name it as a fourth narrowing in the delta, or
restate A3's premise to cover an annotation that legally named a region its
right-hand side did not.

**The scope is one site, measured.** 1954 annotated `let` bindings scanned; 68
whose annotation names a region; **1** naming a region the right-hand side does
not. The 57 further sites where region sets differ are not counterexamples — in
each, the annotation names no region while the right-hand side's region is a
call's region argument leaving a region-free result. Mode and type were checked
directly: all 197 rejection-expecting cases still reject, 0 now compile clean.

The sweep's own limit, stated with its result: it finds cases whose *violation*
was deleted, because those fail loudly. It cannot find a positive case whose
*subject* was deleted, because that stays green — that is §1.2's population.

### 2.2 A citation moved without being named

OP-9 deletes `buffer_new`'s written argument, so a region-bearing element is now
caught by the flat-element requirement citing **OP-1** before **STOR-5** is
reached. The program is still rejected, so the accepted set is unchanged and
this is not a fourth narrowing — but the delta records the STOR-5 edit and
records `buffer_new` losing its argument, and nowhere states that the two
together move the citation.

A reviewer approving bytes should be told which rule now rejects what, even when
acceptance is unchanged. **This one surfaced only because a test failed, and the
delta is anchored per-rule rather than per-interaction, so it is unlikely to be
the only one.** A check for further unnamed citation moves is owed before
approval.

## 2.3 A diagnostic can direct the writer to something the language forbids

Not introduced by v0.23 and not fixable inside the diagnostic layer, but found
while validating it, and it bears on whether the language is usable by the
writer it is designed for.

OWN-1's mechanical fix reads "write `move p` for the affine place". Inside a
requires clause FN-8 rejects exactly that, because its subset names `move` in
its own prohibition list. Six spellings were measured and none is accepted for a
payload-carrying enum operand, so **the compiler tells the writer to do
something it will then refuse, with no third spelling available.** For an AI
writer following diagnostics mechanically, that is a loop rather than a hint.

No repair exists in the diagnostic layer. DIAG-1 says a fix is included "exactly
where the owning rule requires one", so the content is keyed to the rule and not
the position; OWN-1 states its repair unconditionally in its own bytes; and the
field is `&'static str` with every fix in the compiler a literal, so a
context-aware fix is not representable without a schema change. Both the prose
and the type reach the same conclusion: **this is a joint inconsistency between
OWN-1 and FN-8, and every repair changes rule bytes.**

**A general reading was offered here and is now RETRACTED — the scope is one
rule pair, not a class.** The suggestion was that DIAG-1's document-order
tie-break decides whose repair the writer sees, making this an instance of a
shape that could arise for any rule pair. The checker refutes it: the clause
pass is **purely structural**, rejecting `move`, a borrow, and a subscript by
shape and consulting operand affinity, ownership, and consumption nowhere —
consistent with FN-8's own words, "an early FN-8 **structural** pass". There is
no simultaneous FN-8 rejection to tie-break against, so **the blast radius is
exactly the OWN-1/FN-8 pair**. The retraction is recorded rather than the text
quietly replaced, because the reading was published here and would otherwise
have sent a reviewer auditing every rule that carries a repair.

Worth noting what made the difference, and stated carefully because the first
attempt at it was itself too strong: the claim was filed as "not measured", and
what it actually was is **unmeasurable by running programs but answerable in
minutes by reading the checker**. GRAM-5's `atom` has exactly four forms, each
decided before consumption could matter, so no source program separates the two
rules — but that is a limit of one instrument, not of inquiry. "Cannot be found
by running programs" reads as a deep property and is not one; the honest version
names which instrument fails and which succeeds.

The general question — *could* a document-order tie-break present a repair that
is illegal where the losing rule governs — remains open in principle. It now has
**no instance attached**, and should not be reported as systematic on the
strength of an example that turned out not to be one.

## 3. How to read this packet

Nothing above says v0.23 is unsound or that the corpus is bad. The compiler
gates are real, the corpus is large, and the batch closed every defect it found.
What the sections above establish is narrower and more specific: **three of the
green signals mean less than their face reading, and two changes are not in the
account of what changed.**

The pattern worth carrying past this approval is that all of it belongs to one
class — defects whose failure mode is success. A case that passes without
testing, a rule counted covered on a carrier that does not carry it, a citation
that moved silently: none is visible to anything that watches for failure. Each
was found by asking what a thing *is* rather than what it is *called*.

**The owner's cancellation of the infix comparisons made the change smaller, not
merely different — the first repair in this delta's history to REMOVE sites.**
All six integer comparisons keep their named calls; arithmetic infix is
untouched, so the spelling rule becomes a grammar class (arithmetic is infix,
comparison is a call) instead of the four-of-six subset that was rejected. Two
replacements became byte-identical to v0.22 and therefore stopped being
modifications at all — GRAM-1's compound-token sentence and ENT-3 S1's
comparison-origin clause, each verified by diffing against
`spec/kernel-spec-v0.22.md` rather than by reading.

| | before | after |
|---|---|---|
| modification sites | 64 | **62** (same 34 rules) |
| operator terminal spellings | 20 | **16** |
| grammar productions | 69 | **69** (`infix_op` loses four alternatives, not a production) |
| `DotlessOperationNames` / `ReservedLowerNames` | shrunk by four | **exact v0.22 membership** |

Consequently **R2 is discharged rather than deferred**, and the R2 widening the
delta recorded — four names becoming writer-reusable — dies with it. §2's `expr`
EBNF block and EX-1's program block move for the first time in this document's
history; their new digests are recorded in the candidate's §7.

Verification: `whitefoot-grammar` exit 0 at 69 productions, 84 decisions, 97
terminal predicates; the grammar tables still derive; `cargo fmt`, `clippy -D
warnings` clean.

**Why the site count is worth what it says — evidence about the review method
rather than about this delta.** The two vanished sites were cheap to find only
because every site in this delta is verbatim-anchored, so "what is this site
now?" is a diff rather than a reading. An unanchored prose sweep would have
hidden both, and the shape it would have hidden is the one that goes unnoticed
by construction: **a replacement that quietly becomes the thing it replaced.**
A site count from an anchored delta can be re-derived by a reviewer; one from a
prose sweep cannot, and the difference is not visible in the number itself.
