Decision: A range over storage is a reference formed as the path step `&x[lo..hi]`, written in a signature as the parameter type `&[T]`, a reference kind carrying the measure `len`, formed only from an `Array`, `Slots`, or `Ring` in either its constant-capacity or its runtime-capacity form or from another range reference, and never from a stored value, with `lo <= hi <= x.len` proved where it is formed, because a range named by a path is judged for validity and overlap by exactly the rules every other reference already needs, and because this node is new and carries the successor of the retired decisions in language/ownership/slice-result-provenance, candidate x1 keeping the ability to name part of one storage but as a path step rather than as a value with its own loan strength, region, and origin set, instead of a `Slice` and `MutSlice` pair of value types each carrying a loan strength, a region, and a set of possible ultimate storage origins.

Decision: Two ranges are separated only by the judgment every other pair of paths uses, different roots, or indices or ranges proved distinct, and overlap conservatively otherwise, with a proved separation of two ranges separating everything reached below them, because a range is a step in a path and warrants no second disjointness mechanism, instead of comparing value-carried origin sets at call boundaries.

Decision: A function never returns a range reference; a helper that selects part of a storage returns indices with their bounds relation in `ensures` and the caller forms the range, and a recursive subdivision forms its sub-ranges from the range reference it received and passes them to its own calls, because the caller already holds the path the range is formed from, so one address computation replaces the whole apparatus that made a returned view's origin knowable from a signature, instead of a view result with a declared origin ceiling and a rule giving each result of one call its own formal region.

Rejected:
- `Slice` and `MutSlice` as first-class values that may be bound, moved, stored, or returned: rejected because a value that reaches storage it does not own is a reference in value clothing, which the closure of aggregates under owned values and the no-escape rule for references both exclude.
- A shared child view of an exclusive view, with the parent frozen against element writes while the child is live: rejected because with no permission marker on a reference a second range over the same storage is simply a second path, and the call-site and adjacent-statement checks decide every access from path overlap alone.
- Deciding two ranges disjoint from the runtime wrap of a ring: rejected because a range is formed over logical positions and the wrap is the storage's own business, so the wrap can separate nothing a path does not.
