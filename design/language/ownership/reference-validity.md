Decision: A reference names a path that starts at a local variable or a parameter and continues through fields (a heap cell's content being its field `inner`), the referent of a reference through `deref`, an index, a range, or the payload of an enum variant, and the reference variable is not storage of its own, so forming a reference to a reference variable is refused and extending a reference names the longer path rather than pointing at the reference, because a name for a path holds no address a program could copy or alias and can always be formed again, instead of a pointer value with an identity of its own.

Decision: A payload step in a path is available only under the fact that the enum currently holds that variant, established by a match or a conditional binding in the selected arm and taken away by any write to the enum, because the payload exists only while the discriminant says so, instead of a payload reference that survives the test that justified it.

Decision: An index inside a path is evaluated once when the reference is formed and the path records that value, because a later assignment to the variable that supplied the index must not silently retarget a live reference, instead of rereading the index bindings at every use.

Decision: Whether a reference is usable is an ordinary fact, established when the reference is formed and invalidated when a proper prefix of its path is written, moved out of, replaced, or released by a statement, by a call, or by the derived release at scope exit, when the scope of the path's root ends, or when a variant fact a payload step depends on is invalidated, while a write to the storage at the path or below it leaves the reference usable, because this is the one rule that separates changing a thing from removing it, and re-forming the reference is then the only way to regain validity, instead of a region or lifetime standing in for that storage relation.

Decision: A prefix relation that cannot be decided invalidates: two indexed positions on one storage count as overlapping unless their indices or ranges are proved distinct, and a call whose substituted write paths contain a proper prefix of a live reference's path invalidates that reference, while a reference passed as an argument to that call is the access being performed and not a bystander, because the judgment that decides invalidation is the same conservative path-overlap judgment every other check uses, instead of suspending a holder across the call and resuming it afterwards.

Decision: A move never re-roots an existing reference: after a value is moved to a new owner, references formed through the old place are invalid rather than reinterpreted as references into the new one, because the path they name has ceased to exist even when the bytes did not move, instead of silently retargeting them at the move.

Rejected:
- Keeping a reference usable across a write to a proper prefix of its path when the storage it names is provably untouched: rejected because the prefix write is exactly the event that may replace, reallocate, or release what the rest of the path was interpreted against, and deciding it otherwise would need the contents of the operation that wrote the prefix.
- Invalidating a reference when the storage at its path is written: rejected because changing the value a reference names is the ordinary use of a reference, and a check that ended validity there would leave no writes at all.
