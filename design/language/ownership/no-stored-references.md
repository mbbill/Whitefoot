Decision: No aggregate holds a reference: every struct, enum, tuple, `Array`, `Slots`, `Ring`, `Box`, and generic instantiation holds only owned values, recursively and closed under wrapping, so that no type parameter, wrapper, or variant payload is a position through which a reference can be stored, because a value that contains no reference can be relocated by copying its bytes, which is what lets a storage grow, reallocate, or be moved without any surviving name becoming wrong, and because this node is new, candidate x1's Rule 1 deciding for every type and every position at once the question the retired boundary decision in language/ownership/slice-result-provenance decided for slices alone, with no live node owning it, so it is proposed here while, if the owner prefers the value-semantics half under language/data-model, this first decision belongs there and the second stays in ownership, instead of tracking per-leaf origin metadata through generic arguments and stored values or rejecting only the hiding positions a checker cannot approximate.

Decision: A reference may be bound to a local, passed as a call argument, and used inside the function that formed or received it, and nowhere else: it is never assigned into an aggregate, never returned, and never captured by a function value that is stored or returned, and a function that finds something returns an index or other owned data from which the caller forms the reference, because the caller's one repeated address computation is cheaper than the provenance apparatus a stored or returned reference forces on every signature, and because candidate x1's Rule 4 decides for every position at once the question the retired returned-reborrow and call-result-holder decisions in language/ownership/no-reborrow decided for borrows alone, which no live node owns, instead of a returned reference whose origin the signature must determine.

Rejected:
- Admitting a reference inside a generic argument or an option-like wrapper: rejected because one such position is enough to defeat relocation by byte copy, which is why the closure holds whatever the type argument is.
- A function value that captures a reference and is then stored or returned: rejected because it stores the reference under another name and carries the same obligations out of the forming function.
- Returning an index and treating a later use of it as a memory error when the storage has been reused: rejected because a stale index that is still in bounds names the current occupant of that slot, which is a logic error the program detects with its own data, such as a generation number, if it needs to.
