Decision: The kernel owns the storage shapes together with exactly those operations that move a window boundary, relocate the slots below one, exchange the value held in an owned place, or change a runtime capacity, namely appending and taking at an end, inserting and removing at an index, moving all of one window into another or splitting one into two, growing a heap-resident prefix window, setting at a subscript, swapping two places, and the in-place update that hands a place's value to a function and commits the result, while growth policy, pools, arenas, keyed tables, clearing, truncation, replacing while keeping the old value, swap-remove, deques, and strings begin as source libraries whose costs are checked against the same native operation contract, because those kernel operations provide the authority source needs to preserve initialized storage but composition alone does not establish equal cost, as the [ordered Vector consumption comparison](https://github.com/mbbill/Whitefoot/blob/34ede1dedd278652ce153452fc305caf241c45c0/research/experiments/container-representation/vector-library/RESULTS.md) distinguishes extra source-required movement from lowering costs, instead of a kernel container per policy or a blanket claim that every library composition has no extra runtime cost.

Rejected:
- A source-library swap, insertion, or middle removal written over the same storage: rejected because each requires moving a value out of a slot, which the language does not admit, so each must be one kernel relocation that leaves no slot empty at any program point.
- A kernel container per policy, such as a growable vector, a pool, a keyed table, or a string: rejected because the storage operations supply the authority needed for memory safety while growth, recycling and occupancy policy belong to the program; a measured gap can reopen a particular operation or representation without requiring a kernel container for each policy.
- Treating the kernel's storage transitions as ordinary source functions: rejected because their contracts relate measures that only the storage itself can change, so a source body could neither establish them nor be checked against them.
- Replaced decision, this node's only decision, which placed swap, rebase, clear, truncation and middle removal in source libraries alongside growth policies, pools and keyed tables: rejected because candidate x1 Rule 6 rejects a move out of a window slot or an array element outright, so a source implementation of swap or of middle removal has no way to take the value out, and Rule 6 therefore gives swap, insert-at and remove-at as built-in operations with their own effect rows, each performed as one relocation, and lists swap-remove, truncate, clear, the growable vector, the arena, the pool, the deque, the open-addressing table and the string as zero-cost source compositions of those operations, while candidate x1 Rule 16 supplies the pool and arena half, both being uses of ordinary storage rather than kernel types; the boundary therefore moves, swap, insertion at an index and removal at an index becoming kernel operations while growth policy, pools, arenas, keyed tables, clearing, truncation, swap-remove, deques and strings stay in source libraries, and the replaced decision's original ground is preserved, the kernel taking only what a writer cannot implement over the rest of the language and the policies above it needing no second authority over memory safety, so what changed is which operations fall on which side of that line, not the line's criterion.
- Replaced promise that every listed library composes at no extra runtime cost: rejected because ordered consumption of a prefix window requires additional element transfers with the current operations, so source expressibility establishes safety but not native cost; the operation inventory stays unchanged while a material measured gap is grounds to reopen its representation or operations.
