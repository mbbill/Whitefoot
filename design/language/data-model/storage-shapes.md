Decision: There are three storage shapes and no fourth, an array in which every slot always holds a value, a prefix window whose filled slots run from zero up to its length, and a ring window whose filled slots begin at a head position and wrap at the capacity, and each shape has a constant-capacity form that may sit inline in its owner and a runtime-capacity form that exists only as the content of a heap cell, because the three differ exactly in the metadata they are obliged to store and a program that needs no length and no head should store neither, and because this node is new, owning the storage decisions that candidate x1 Rule 6 introduces, the three shapes with their two placements among them, and that no live node carries, while it elaborates and does not contradict the parent decision in `language/data-model` that the three shapes are distinct states with placement as a separate axis, the parent keeping the coarse choice and this node carrying the detail, instead of one growable representation that every fixed array also pays for.

Decision: A storage's measures, its length, its capacity, its remaining room, and, on a ring window, its head, are read-only pseudo-fields that a program reads the way it reads a field and can never assign, changed only by the operations that own them, because the window boundary is an ordinary runtime number stored with the block and every proof about the storage is a relation over that number, instead of the current family of measure-reader operations, spelled unlike every other read.

Decision: Besides its slots, a window has four named parts, the append slot at its length, the last filled slot below its length, all filled slots, and all free slots, and these exist only as vocabulary for effect rows and for the overlap judgment, no program forming a reference to a part or reading or writing one, because a row that names only the append slot and the length is what lets an appending call be proved not to disturb a live reference to a filled slot, while two neighbouring questions are deliberately outside this node, when a reference into a window stays valid across an operation and how two indexed positions are judged to overlap, both of which belong to the reference and ownership subtree, where validity is a fact and the overlap relation lives, instead of appending counting as a write of the whole storage that invalidates every reference into it.

Decision: A value leaves a slot only through an operation that moves a window boundary or exchanges the value in the place, taking from either end, removing at an index, or swapping two places, and a move out of a slot is rejected, because no slot may ever be observable as empty and none carries a tag that could report it as empty, while what the kernel implements against what a source library composes is deliberately outside this node and belongs to `language/data-model/kernel-minimality`, instead of a take that leaves a hole, or a vacancy type state for a partially emptied storage.

Decision: A subscript admits exactly the three shapes in either form, a range reference into one of them, and a constant table, and no storage type of any kind is a value that can be held in a field, returned, or stored in place of the storage it names, because a range is how a caller names part of a storage for a callee rather than a value a program keeps, which is also what x1's list of mechanisms that are not in the candidate says by excluding a first-class slice value, and because what is indexable and what a range reference is come from candidate x1 Rule 7, while the range reference itself, how `&x[lo..hi]` is formed, what bound it is formed under, and how two ranges are separated, is proposed as its own node under the ownership subtree, so this node states only what a subscript admits and that no such thing is a stored value, and if the owner keeps both nodes the two must not restate each other, instead of a slice value type standing beside the shapes in the type inventory.

Rejected:
- A growth operation on the ring window as well as on the prefix window: rejected because a ring's filled slots can wrap, so growing one is a fresh ring plus one copy that a source library writes, while the prefix window's growth can reallocate in place, which is candidate x1 Rule 6's restriction of the growth operation to the heap-resident prefix window, with the ring's growth by a fresh ring and one copy listed among the source libraries.
- Per-slot tags so that a window could report an individual slot as empty: rejected because no program point can observe a live slot as empty, so the tag would cost storage and a test in every program that never asks the question.
- A single storage type parameterized by whether it has a length and a head: rejected because the metadata a shape stores is the whole difference between the three, and collapsing them would make a full array carry a length it can never change.
