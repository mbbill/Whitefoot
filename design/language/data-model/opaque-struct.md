Decision: A struct declaration may carry the modifier `opaque`, written before `linear` when a declaration carries both, and an opaque struct has ordinary fields and no usable constructor, a constructor call naming it and a destructuring binding naming it both being rejected with the same instruction to build the value with a construction function, while reading a field, writing a field and moving a field out follow the ordinary struct rules, because a type whose representation belongs to the host or to the compiler should still be declared in the form a writer reads and writes, as the prelude's function rows are written in the contract form a source function uses, and the only thing such a type must withhold is the pair of operations that would make a value or take one apart without the function that knows how, instead of a table of built-in nominal types carried in the specification's prose as declaration notation that no source item could state.

Decision: The prelude declares the heap cell `Box<T>` with its single field `inner` and the fourteen host handle types with no fields as opaque structs, while `Array`, `Slots` and `Ring` remain nominal types that no source item declares, because a struct head states the cell and a handle exactly and states neither of a storage shape's two capacity forms, one head being unable to carry both `Slots<T, N>` and `Slots<T>`, nor a shape's elements, which are slots and not fields, instead of one modifier covering every built-in nominal so that the three shapes would carry declarations claiming a shape the language does not have.

Decision: A source writer may write `opaque struct`, and because no function can return a value of a type whose construction the language withholds, no value of a source-declared opaque struct is ever formed, an emptiness admitted rather than refused, because a modifier the prelude may write and a source item may not would restore by the back door the separate system declaration domain the prelude is deliberately not (`language/system-interface/declaration-home`), instead of restricting the modifier to prelude declarations and reading a declaration's origin to decide whether it is accepted.

Decision: The modifier is admitted on a struct alone and there is no opaque enum, because the types that need it, the cell and the host handles, are products of fields and nothing else in the language asks for the modifier, instead of admitting it on both declaration forms for symmetry.

Rejected:
- Marking the three storage shapes `Array`, `Slots` and `Ring` with the same modifier so that every built-in nominal carries a written declaration: rejected because no struct head states them truthfully, one head cannot carry both the constant-capacity `Slots<T, N>` and the runtime-capacity `Slots<T>`, and a shape's elements are slots rather than fields.
- Refusing the constructor call while admitting the destructuring binding: rejected because a host handle has no fields, so `let TcpSend() = move s;` would bind nothing and still discharge the must-consume obligation of a linear resource without closing it.
- The spellings `sealed`, `abstract` and `builtin` for the modifier: rejected because the specification already calls these types opaque, so a second word would name a property the reader can already name.
