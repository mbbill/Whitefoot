Decision: Struct-of-arrays is the taught default layout for bulk data while array-of-structs stays a genuine need, served by a storage shape whose element type is the struct itself, held by value under ordinary ownership, because struct-of-arrays is usually the faster layout and owned elements already serve the record-by-record case without a copy-struct mechanism the language does not have, instead of forbidding array-of-structs or keeping a separate flat heap-buffer type to hold records.

Decision: A pool or an arena is a use of ordinary storage, a window plus indices used as handles, appending as allocation and truncating to zero as reset, and identity across slot reuse is a generation number the program stores as data, because a stale index that is still in bounds names the current occupant of that slot, which is a logic error and not a memory error once no slot can be uninitialized or raw, instead of a language-level pool contract that either forbids recycling to keep identity stable or charges every pool for identity metadata.

Decision: Any operation that moves owners between slots, such as a compaction or a removal shift, is an ownership relocation in which every retained owner reaches exactly one destination and a moved-from slot is never read or dropped, because treating such a move as a metadata update or a copy would duplicate or lose owners, and this decision is kept unchanged, consistent with candidate x1 Rule 1, under which a value containing no reference relocates by copying its bytes, and with Rule 6, whose insert and remove operations are exactly such relocations, instead of metadata-only updates.

Decision: Full arrays, prefix windows, and ring windows are three distinct storage shapes, and placement is a separate axis with no mandatory handle or indirection on dense values: each shape has a constant-capacity form that lives inline in its owner and a runtime-capacity form that lives only as the content of a heap cell, because variable length and a head position are not universal array metadata and only a capacity fixed at run time needs the heap, instead of one universal dynamic-array representation.

Decision: What a source function signature promises is its parameters' ownership classes together with its declared effect row, fixed independently of how parameters and results are represented, because a representation choice must not widen or narrow what a signature promises, instead of deriving access permission from representation or from a permission marker written on a reference.

Decision: A type's identity carries no region, store, or brand component, and no type anywhere names the store its storage came from, because there is one heap and a reference is a local name for a path that never escapes the function holding it, so no value carries a lifetime that a type would have to name, instead of region parameters as an axis of nominal identity reconciled by a region-erased structural equality before lowering.

Decision: Bool is a two-variant prelude enum matched by the same tag-only mechanism as every user enum, and the primitive set is the fixed-width integers and floats of 8, 16, 32, and 64 bits with unit, because one mechanism then serves equality, match and if selection, and tag-width lowering for Bool and user enums alike, and this decision is kept unchanged, the question being outside candidate x1, instead of a dedicated primitive boolean with its own literals and comparisons, or address-width and 128-bit integers.

Decision: A single heap-resident value has its own compiler-owned cell type, the box, which is the only heap marker in the language, carries no measure and no store or region brand, and is the only place a runtime-capacity storage shape may live, because a one-element window costs three descriptor words against a cell's one pointer and would owe a nonempty-length proof at every read of a container the language already knows is never empty, while a shape with no compile-time size has nowhere else it could be placed, instead of representing a boxed value as a window of capacity one or branding the cell with the store it came from.

Decision: Allocation never fails as a source-visible outcome and carries no result wrapper, exhaustion of the heap being a failure of the trusted base that terminates the program outside the language, and a program may declare that it uses no heap, in which case the heap cell and the runtime-capacity storage shapes and every capability built on them are unavailable to it, because a result wrapper on every allocation would put an error arm and its handling on every push and every node, virtual memory makes exhaustion a whole-program failure rather than a per-site outcome, and the domains that cannot tolerate exhaustion are the ones that forgo the heap entirely, instead of a fallible allocation returning its payload inside an error value, or an allocation that traps into a handler.

Decision: Full arrays admit owned elements and consuming conversions to and from prefix windows, while every mutating helper takes the storage as a reference parameter, declares in its effect row what it writes, and returns only outcomes or removed elements, because completed fixed storage needs no window metadata and an owned mutation boundary copies the entire inline capacity, instead of forcing a completed array through a partial-window state or returning a mutated storage value.

Decision: Ordinary enum slots remain the owning sparse-map baseline, because the matched growth and refusal witnesses execute and their measured gap does not isolate a benefit sufficient to select compiler-known projected storage, and this decision is kept unchanged, confirmed by candidate x1 Rule 12, whose tables keep occupancy as data in ordinary option or tag storage, instead of introducing projected sparse authority from an unseparated interface and layout cost.

Decision: Occupancy that is decided by data is kept by the program as data, in a tag array or an option payload it declares itself, because no slot carries a compiler-maintained tag and no program point can observe a slot inside a window as empty, and this decision is new to this node, taken from candidate x1 Rule 6, under which no slot carries a tag and no program point can observe a slot inside the window as empty, from Rule 11, which carries no per-slot occupancy facts, and from Rule 12, under which structures whose occupancy is decided by data keep that occupancy as data, instead of compiler-maintained per-slot occupancy or a vacancy type state.

Decision: Ordinary opaque nominals retain a uniform allocation-fit ceiling independent of their linked representation, because a native catalog's size must not choose whether the same source allocation is accepted, and this decision is kept unchanged, the static allocation-fit obligation being the ordinary integer-overflow proof on the arithmetic that computes an allocation size, which the runtime-capacity constructors carry exactly as every other allocation site does, while exhaustion of the heap is not a proof obligation at all but a trusted-base failure that terminates the program, instead of deriving allocation proof from link-selected native sizes or making opaque allocation-fit queries unavailable.

Rejected:
- Store brands, providers, and region parameters carried inside types: rejected because one heap serves every allocation and a reference never outlives the function that formed it, so a store name in a type protects nothing.
- Compiler-maintained per-slot occupancy tags or a vacancy type state: rejected because a program that needs occupancy stores it as data it can read directly, and every other program would pay for the tag.
- Reference or slice values held in aggregates: rejected because a value that contains an interior pointer can no longer be relocated by copying its bytes.
- Replaced decision, the array-of-structs decision that named a flat heap-buffer of structs as the array-of-structs carrier: rejected because the flat runtime-length buffer type is withdrawn and array-of-structs is now carried by an ordinary storage shape whose element type is the struct, candidate x1 Rule 6 listing the three shapes and its closing list retiring the name `buffer` while Rule 1 makes a struct element ordinary owned content; its successor is the struct-of-arrays decision above.
- Replaced decision, the append-only stable identity decision, which made stable identity a language-level pool contract and refused recycling so that a slot-recycling use-after-free stayed unrepresentable: rejected because a pool is now a use of ordinary storage and a stale in-bounds index reaches the slot's current occupant, a logic error rather than a memory error, with generation numbers kept as ordinary data (candidate x1 Rule 16); this overlaps the pending ruling x1 Rule 16 itself names on `language/ownership/affine-replacement`, and both must be ruled on together, while the same pool-and-arena successor is also proposed as a separate node under the ownership subtree and the successor belongs in exactly one place, so if the owner puts it there, this node retires its identity decision without a successor line and the retirement still stands.
- Replaced decision, the distinct-states decision: rejected because the three distinct shapes are kept while the second axis is restated, placement now being constant capacity inline against runtime capacity inside a heap cell and stable identity no longer being an axis of the data model at all (candidate x1 Rule 5 confines the runtime-capacity forms to box content, Rule 6 names the three shapes and their two forms, and Rule 16 removes identity as a type-level axis); its successor is the distinct-shapes decision above.
- Replaced decision, the signature-representation decision, whose wording promised that access modes supply no loan origin, lifetime, or aliasing permission: rejected because loans and lifetimes no longer exist and what a signature states about access is exactly its effect row (candidate x1 Rule 2 removes any permission marker on a reference, Rule 9 puts access in the effect row, Rule 15 makes every result owned); its successor is the signature-promise decision above.
- Replaced decision, the region-identity decision, which made a nominal's region parameters an axis of its check-time identity reconciled by region-erased structural equality: rejected because no region or store parameter exists anywhere to participate in identity (candidate x1 Rule 14); its successor is the type-identity decision above.
- Replaced decision, the mutation-helper decision: rejected because owned array elements and the consuming conversions are kept while exclusivity is restated, a helper taking the storage as an ordinary reference parameter and declaring its writes, with exclusion decided at the call site rather than by an exclusive-borrow mode on the parameter (candidate x1 Rule 6 for the conversions, Rule 9 for the declared row, Rule 10 for the call-site disjointness check); its successor is the full-array helper decision above.
