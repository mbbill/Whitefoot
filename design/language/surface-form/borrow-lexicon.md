Decision: Surface names label checked invariants defined in the specification and never borrow backend vocabulary, because a name like noalias names a lowering consequence rather than the invariant the checker enforces, instead of backend terms at the surface.

Decision: A reference is written `&place` and carries no permission, exclusivity, or storage-lifetime marker of its own, and whether a callee may write through a reference parameter is read from that parameter's entry in the declared effect row, because a reference is now only a local name for the path it was formed from, while exclusivity is decided call by call by comparing the substituted effect paths of that one call, so a marker on the reference would restate more weakly what the row already states exactly, instead of a uniqueness marker such as `&uniq`, Rust's `&mut`, or any other permission or region marker attached to the reference.

Decision: A reference naming a run of positions in one storage is spelled with the reference marker and the element type in square brackets, `&[T]`, and bears no nominal type name of its own, because the surface name must say what the checker enforces, which here is that the thing is a reference naming a path and not a value carrying a loan strength that a program could hold, copy, or store, instead of the nominal names `Slice<T>` and `MutSlice<T>`, whose two spellings named two loan strengths that a reference no longer carries.

Rejected:
- Spelling the exclusive reference mode `&uniq`, the decision this node previously carried on the ground that the mode's invariant is uniqueness rather than mutation: rejected because references no longer carry any mode at all; write permission is declared once per parameter in the effect row and exclusivity for a call follows from the pairwise comparison of that call's substituted effect paths, so retaining the marker would create a second place where the same permission is stated; the ground is the reference and effect rule set recorded in research/investigations/access-effects/CANDIDATE-X1.md, Rules 2, 9 and 10.
- The nominal view type names `Slice<T>` and `MutSlice<T>` for a range of storage: rejected because those names belong to a value with two loan strengths that could be copied, stored and returned, and none of that survives: a range reference is a local name that cannot be stored in any aggregate, returned, or captured.
