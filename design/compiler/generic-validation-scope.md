Decision: Symbolic generic validation analyzes entailment only for the bodies of the canonical generic instances and of every function reachable through their calls, leaving the other bodies of its scratch inventory unanalyzed, because only those instances are judged and a judged body reads another function's analysis solely through the postcondition summaries of its callees, while the [flow-analysis follow-up](../../research/investigations/proof-certificate-architecture/CHECKING-COST.md#flow-analysis-closure-follow-up) finds the validation repeating the complete analysis of nongeneric bodies that the concrete phase then performs again, instead of analyzing the whole scratch inventory.

Decision: Symbolic publication starts from each canonical generic instance and admits every clause expressible at its selected shape, including measured results and exit-only clauses whose result type remains symbolic, because a generic caller needs its callees' verified summaries just as a concrete caller does. A compiler-owned window parameter alone waits until an operand supplies its shape, even if that shape's element or capacity is still symbolic; allocation layout queries likewise distinguish known results, known oversized ceilings and unresolved parameters, instead of deferring every obligation or clause merely because its enclosing function is generic. Each inhabited concrete instance still receives its own ordinary check.

Decision: Operand-directed generics use a fixed declaration table identifying which operand supplies each parameter and which type component it selects, with a type-only place walk followed by ordinary argument checking and existing deferred signature materialization, because the chosen window defines its element type and using a mismatched value argument to infer it would change the intended instance. The inventory walk includes newly materialized signatures, instead of adding a second ownership-sensitive type inference pass or keeping anonymous per-call signatures that lowering cannot resolve.

Decision: Keep written TYPE-9 placement checking distinct from post-substitution inline-storage checking: an explicit runtime-capacity shape must occupy the direct Box type argument, and formed own parameters and nominal fields or payloads are checked again for inline storage, because generic indirection can introduce a forbidden representation without writing that shape at the storage site. Reference parameters do not store their referent, and compiler-owned boxed row clauses receive only their specified implicit content projection, instead of using either written syntax or formed types alone to enforce both boundaries.

Decision: FN-4 refinement reuses S4/MSR-4/AUTO in isolated declaration-local queries with distinct entry, exit, result and routed-payload identities, retaining the premise and goal occurrences and each query's own derivation inventory, because implication needs the ordinary fixed proof families but its hypothetical premises must not become callable-body facts. Bound calls separately retain the actual executable target and instantiated formal acceptance/publication boundary; stronger actual clauses are visible only through the verified refinement of that boundary, instead of clause-set equality, identity sharing between independent queries or recovering the caller contract from the executable FunctionId.

Rejected:
- Reusing the validation's analysis of a nongeneric body in the concrete phase: rejected because the scratch inventory's function and nominal identities are discarded at its checkpoint, so its analysis is not the concrete program's.
- Excluding every nongeneric function from validation: rejected because a judged generic body can discharge an obligation only through a reachable callee's published postcondition.
- A second declaration-contract implication solver: rejected because S4/MSR-4/AUTO already fixes the admitted proof family; query-local identities permit reuse without sharing hypothetical premises with callable bodies.
- Enumerating every operand-directed instance over every shape named by a unit: rejected because multi-window operations create an unused cross product, while the ordinary body checker already discovers the selected operand types.
