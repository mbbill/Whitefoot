Decision: A `--par` module carries two lowerings of every function on a path from the entry to a handed-out call, the overlapped world and a sequential clone whose code is the sequential lowering byte for byte, with the default policy selecting one world once per process at bootstrap by whether a pool was asked for and neither world calling into the other, because the hand-out's rejoin takes the callee's result out of tail position and forecloses tail-recursion elimination, so no single lowering serves both worlds, measured as a 2.96 times pool-off tax that fell to 1.00 with the clone world, instead of one lowering with a per-task demand switch.

Decision: The clone set is the functions reachable from the entry that can reach a hand-out, derived from the call graph and the permission table, because only those functions have a lowering that differs between the two worlds, instead of cloning every function or marking clones by name.

Decision: `--par-sequential-refusal` enters the callee's existing sequential clone when a compute offer is refused and the callee cannot suspend, and `--par-recursive-frontier N` emits `N` ordinary parallel call levels for a recursive component and then enters its sequential clones, both keeping the ordinary signatures, joins, and result ABI, adding no hidden parameters or runtime depth counters, and declining the compute offers beneath the clone they enter, because refusal reuses the failed-acquisition edge every offer already has and the frontier is chosen statically after private call layers, so neither adds the per-task demand query whose contention cost was rejected, instead of a runtime demand signal read on each call.

Rejected:
- A per-task demand signal switching to a sequential clone per subtree when no idle capacity is reported: rejected because the signal cost contended read-modify-writes measured at 0.49 to 0.93 seconds on the fine-grain cell, while pool-off selection needs one decision per process.
