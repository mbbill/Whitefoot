Decision: Every payload string that names a source construct names it in its canonical source spelling through the one checker renderer for that kind of construct: a resolved place as the place expression the caller would write, with a reference parameter under `deref`, fields and payload steps by name and each index by the value it captured; a function or type instance as a call or declaration writes it, with its type and const arguments; and a literal value as its FORM-5 literal, because the main reader is an agent that repairs the source it wrote and cannot map an internal binding number, field ordinal, instance symbol or bit pattern back to it, instead of printing the checker's identities or `Debug` values, or special-casing each rejection that happened to leak one.

Decision: A suggested repair is one the language admits wherever it is applied: EFF-2's `expected_row` is the exhibited row with every read a write of the same path subsumes dropped and every pair of entries on one parameter that a call refuses whatever its arguments merged into one write of their common path, so EFF-1 admits it, EFF-2 admits it for the body, and no call refuses it against itself under EFF-5, because an agent applies a suggestion literally and a suggestion that fails at the declaration or at every call costs compile rounds and teaches nothing, instead of printing the raw exhibited set.

Rejected:
- Listing the exhibited set as the suggested row: rejected because it can pair a read with the write that subsumes it, which EFF-1 never writes, and a whole-parameter read with a write below it, which EFF-5 refuses at every call, as the counter example `reads(stats.count), writes(stats.count)` did.
- Merging two indexed positions of one parameter into a whole-parameter write: rejected because whether they select one element depends on the values a call supplies, which EFF-5 asks the call site to prove, and the merge would widen the row's writes for every caller.
- Rendering a computed index as an invented expression: rejected because the checker captures the value's identity and not the argument's text, so any expression it printed could name a different value; it renders as `?`.
