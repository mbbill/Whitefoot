Decision: A parallel range split descends to a leaf that is still a loop over a subrange, never to a leaf of one iteration, because a one-iteration leaf destroys the body's own optimization, measured at 3.6 to 7.6 times slower on light bodies against the 3.1 times a subrange leaf preserves, and a leaf that is still a loop keeps the sequential world's code byte for byte, instead of an iteration-leaf split.

Decision: Native queues, helper lanes, wakeups, and completion ports are target-private protocol state and never Whitefoot shared storage, because the source model has no scheduler and a runtime structure visible as source storage would need ownership and effects it cannot honestly carry, instead of exposing runtime queues as language values.

Decision: On Windows a module with compute offers requires the compiler-owned runtime at link time, so a missing runtime fails to link, and on every target an invalid worker configuration fails before the program body, a host that starts fewer workers than asked keeps the ones that started, and a startup that yields none runs the parallel body through its ordinary-call fallback, because a silently sequential build would hide a broken configuration behind correct output, whereas fewer threads than asked is not a broken configuration and the refused-offer path already computes the same result, instead of failing the process on any incomplete startup.

Decision: Under `--par`, a scalar leaf with at most 16 nonconstant operations is left out of compute offers by default, and `--par-scalar-leaf-limit` raises, lowers, or removes that threshold per compilation, as offer selection after checking that changes no acceptance or proof work, because offering a leaf that performs a handful of arithmetic operations costs more than running it inline, measured on the adaptive quadrature program at four workers as a median of 34 milliseconds with the default against 83 with suppression off and identical output, instead of offering every eligible compute call.

Decision: Sequential refusal is off unless asked for, the scalar-leaf threshold is provisional, and no universal grain policy is selected, because one exploratory result on one workload supports the provisional default and establishes neither that every workload benefits nor that refusal should be on by default, instead of a default grain policy chosen from that one measurement.

Decision: Provisionally price an independent range's iterations using available captured counted-loop extents and helper-argument lengths, with saturating scheduling arithmetic and the previous static estimate for unavailable work, preserving the runtime work unit and chunk cap, the sequential world, and all acceptance and proof behavior, because a fixed inner-loop factor assigns the same price to blocks of very different sizes and leaves the measured prefix and histogram blocks unoffered while restricting wide stencil to a few chunks, instead of lowering the global runtime work floor, asking writers for grain annotations, or timing source work to adapt its price. The choice remains provisional because the [first runtime-extent trial](../../research/investigations/compute-model/DESIGN.md#runtime-extent-trial-result) improves the primary kernels but fails the protected chain-pull case and exposes substantial CPU tradeoffs, so captured extents alone do not establish a broadly suitable grain policy.

Decision: A permitted run is lowered into contiguous call-rooted groups within one IR block, with a non-call, unavailable call result, or addressed-result promotion ending the current group and later members allowed to start another; already-permitted adjacent pairs may supply a group across a greedy run boundary when neither call is already grouped, because every resulting group retains an existing PAR-1 proof while the leading-prefix-only policy loses the recursive calls after an ordinary scalar statement and the permitted call before an if condition in the maintained parallel programs, instead of bridging a non-call, redoing permission analysis in lowering, enumerating larger candidate windows, or discarding the rest of a permitted run after its first unusable member.

Decision: Keep optional permission evidence separate from mandatory call acceptance: the PAR-1 planner records exact ordered statement-pair range questions and the flow proves them at the first statement's state, intersecting repeated visits and retaining the captured pair, selected ordering and ordinary derivation. Permission compares every prospective member with every earlier member using only that pair's evidence, because a union footprint loses the origin statement and adjacent independence is not transitive, instead of a permission-private solver or function-global EFF-5 ledger. General index mapping through the first member's ensures and proof-planning cost remain deferred; unavailable evidence retains sequential lowering.

Decision: Permission uses complete statement footprints, including every arm of a call-rooted match, and refuses exit-bearing or unclassified control flow; non-call members confer no hand-out and do not widen the two-world clone set, because source order must execute and join the same work and the existing clone rule depends on handed-out calls, instead of a scrutinee-only footprint or cloning every function containing any permitted adjacency. PAR-2 range partition checks are driven by written origins, preserving overlapping read-only inputs while checking all accesses against written ranges.

Rejected:
- Splitting a parallel range down to leaves of one iteration with grain left to the runtime: rejected because it destroys the body's own optimization, measured at 3.6 to 7.6 times slower on light bodies.
- Passing `-falign-functions=64 -falign-loops=32` to clang for the emitted module and the runtime sources: rejected because the flags did not remove the code-placement sensitivity they were meant to remove, a padded twin still moving a median 1.7 percent against 0.8 unaligned, and their own A/B held every line within one to five percent, less than the same instrument does to arms that execute identical code.
- Denying every call-rooted match after the reference-only port: rejected because the existing if-condition compute call can still be the last member of a group that joins before dispatch. Permission includes all arm footprints and refuses an unclassified or exiting arm, so it does not recover the former scrutinee-only exception or ignore arm interference. Lowering retains its single-block boundary and never moves an arm into the overlap group.
- Keeping only a run's leading call-rooted prefix: rejected because every contiguous part has the same pairwise permission, and this policy suppresses the recursive fold after its independent scalar seed; starting a later group preserves adjacency without changing the judgment.
- Treating adjacent-pair permission as transitive: rejected because a larger group needs every ordered pair proved independent; adjacent-pair recovery therefore creates only two-member groups and never extends them using adjacency alone.
