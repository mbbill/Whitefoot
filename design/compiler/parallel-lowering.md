Decision: The default lowering actualizes eligible finite completion operations while leaving compute-call outlining off, and `--par` additionally actualizes eligible compute groups, maps, and reductions, because permission is a fact about the program while actualization is a cost choice, and the default should not change a program's code shape without being asked, instead of actualizing every permitted overlap by default.

Decision: A parallel range split descends to a leaf that is still a loop over a subrange, never to a leaf of one iteration, because a one-iteration leaf destroys the body's own optimization, measured at 3.6 to 7.6 times slower on light bodies against the 3.1 times a subrange leaf preserves, and a leaf that is still a loop keeps the sequential world's code byte for byte, instead of an iteration-leaf split.

Decision: Native queues, helper lanes, wakeups, and completion ports are target-private protocol state and never Whitefoot shared storage, because the source model has no scheduler and a runtime structure visible as source storage would need ownership and effects it cannot honestly carry, instead of exposing runtime queues as language values.

Decision: An emitted Windows module with compute offers requires the compiler-owned runtime through external ABI obligations, so a missing runtime fails to link and an invalid worker configuration fails before the program body, while on every maintained target a partial startup keeps the workers that did start and a complete startup refusal makes every acquisition return null so the parallel body runs through its ordinary-call fallback, because a silently sequential build would hide a broken configuration behind correct output, and the world was selected once from the pool request, so a startup outcome cannot reselect the clone and the refused-acquisition path already computes the same result, instead of failing the process on an incomplete startup or reselecting the sequential world at run time.

Decision: Under `--par`, a scalar leaf with at most 16 nonconstant operations is left out of compute offers by default, and `--par-scalar-leaf-limit` raises, lowers, or removes that threshold per compilation, as offer selection after checking that changes no acceptance or proof work, because offering a leaf that performs a handful of arithmetic operations costs more than running it inline, measured on the adaptive quadrature program at four workers as a median of 34 milliseconds with the default against 83 with suppression off and identical output, instead of offering every eligible compute call.

Decision: Sequential refusal and the recursive frontier are off unless asked for, the scalar-leaf threshold is provisional, and no universal grain policy is selected, because one exploratory result on one workload supports the provisional default and establishes neither that every workload benefits nor that refusal or the frontier should be on by default, instead of a default grain policy chosen from that one measurement.

Rejected:
- Splitting a parallel range down to leaves of one iteration with grain left to the runtime: rejected because it destroys the body's own optimization, measured at 3.6 to 7.6 times slower on light bodies.
