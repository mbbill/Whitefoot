Summary: A generic bound is a capability filter, read as what the argument must be able to do: `<T>` requires nothing, admits every type, and obliges the body to consume a value of T exactly once, `<T: drop>` requires a droppable argument and `<T: copy>` a copyable one, and the bound is optional and never inferred. The owner's ground is that a bound after a type parameter naturally reads as what the argument must be able to do, so the type with the fewest capabilities writes nothing, where the class-named `T: linear` read as "T must be linear" while it accepted every class; keeping `T: linear` and `T: affine` was refused as reading backwards, and a word for the no-capability case such as `T: any` was refused because absence already says it. This closes the bound-spelling search the entry below recorded, and the prelude heads return to `Box<T>`, `Option<T>` and `Result<T, E>`, so language/system-interface/declaration-home retires its decision that prelude generic heads write the widest bound, an unbounded head now being exactly what a source writer writes. A declaration removes a capability with a modifier on the same word root as the bound that asks for it, `nodrop`, which replaces the modifier `linear`, and the new `nocopy`, at most one per declaration, `nodrop` removing copy with drop; the owner chose `drop` and `nodrop` over `discard` and `nodiscard` because the root parallels Rust, nothing being destroyed by default and a consuming function having to be written, and refused `release` and `norelease`, which reads as never released, and `forget`, which means a leak in Rust. Copy is structural, a coloring in the manner of Rust's auto traits: a type has a capability exactly when every part it owns has it and its declaration does not remove it, so a struct of copy fields and a tag-only enum are copy, the prelude declares `Box`, `Slots`, `Ring` and the fourteen host handles `nocopy` or `nodrop`, and an `Array` follows its element. The class names copy, affine and linear stay as prose terms defined once over the two capabilities, and retiring them from the specification's prose is a follow-up recorded in docs/todo.md. A dead binding may be reinitialized by a `set` whose target is the complete binding, while a place projected, dereferenced or subscripted from a dead root is never writable: the loop rule already admits a body that moves an outer binding and reinitializes it before the backedge, a fallible step inside a loop cannot use the atomic update form, and a wholly dead binding is not a hole. Every fact the checker has proved may be supplied to the backend, as attributes, instruction flags, metadata or assumptions, covering disjointness, independence, reference validity and extent, discharged subscript bounds, and discharged integer-domain obligations as no-wrap flags, because the project pursues performance on top of correctness and a proved fact is correct to state; only a discharged fact is supplied, never one a writer states, and no runtime behavior changes. The language root records only that the specification permits this supply; which facts the compiler emits and in what form is a compiler-tree subject, where the pending amendment for compiler/backend-facts still forbids an assumption and awaits its own ruling.
