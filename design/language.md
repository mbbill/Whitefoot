Decision: Every required source fact is machine-checked before acceptance and erased before lowering, with no writer-accessible unsafe, trusted theorem, or runtime trap of any kind, because any writer-reachable escape becomes an unauditable failure edge in generated code, instead of Rust-style unsafe policed by convention or panics admitted as a language feature.

Decision: Compilation and proof checking never require work that grows exponentially with program or written-proof size, because the target projects must stay practical to iterate on and guaranteed termination alone does not make a checker usable, instead of admitting exponential families and relying on timeouts or budgets to keep them practical.

Decision: An accepted program has one observable behavior, fixed by the language: no build mode, compiler flag, optimization choice, or backend changes what it does, and whatever the compiler hands its backend, such as aliasing attributes or inlining, is an implementation detail the language never sees, because a source that behaves one way when checked and another way when built, as a debug build and a release build that differ on integer overflow do, means the program that was checked is not the program that runs, instead of build modes or switches that trade behavior for speed.

Decision: The specification stands on its own and the design tree carries the reasons, with no index or ledger connecting rules to their grounds, because the tree already records each decision with its reason and refused alternatives, and a second record that nothing consumes drifts, instead of a rule-to-ground ledger the specification requires.

Decision: A language choice is made on its merits and not on cost, on the current corpus, or on how writers fare today: before real project adoption the cost of migrating existing designs is not a ground, the tests and small programs on hand are not evidence of how often anything occurs in real use, the effort a change would take is not a reason to make or refuse it, and a trial in which a model writes programs under some assistance describes that model and that assistance rather than a ceiling on the language, because there are no users to migrate, the corpus was written to exercise the compiler rather than to represent real programs, and the language deliberately trades human writing convenience for performance and checked correctness, instead of compatibility-driven, corpus-driven, or convenience-driven design.
