Decision: 所有权体系由单一所有者的仿射值构成，具备显式的普通移动（move）、词法上具名或匿名的区域（region）、在承载模式的位置上显式标注的借用模式，以及一个在无法确立安全性时就拒绝的检查器，因为复制一个 Rust 那一类会做推断的借用检查器，其实现工作量是不可接受的，一个普通规模的编译器前端是可以接受的，而 rustc 那种规模的推断则不行，因此这套演算立足于显式区域和"不确定就拒绝"，而不是采用推断出的生命周期、对控制流敏感的借用存活性分析，以及隐式重借用。
> 通俗解释：这条决定规定了所有权（ownership，也就是"谁负责管理和释放一个值"）的具体规则：一个值只能有一个所有者，这种"最多用一次就必须交出去"的值叫仿射值；把值交给别人叫"移动（move）"，必须写清楚；临时借用（borrow）一个值时也要在特定位置显式写出借用方式；作用域（region，即一段代码的生存范围）要么有名字要么就是花括号围出来的一段，不靠编译器自己去猜。如果检查器无法证明某处操作是安全的，就直接拒绝，不会含糊通过。这样做是因为，像 Rust 那样自动推断生命周期、追踪借用是否还存活等复杂机制，实现成本太高，超出了一个普通规模的编译器前端所能承受的范围。被否决的做法是采用 Rust 那种自动推断生命周期、按控制流判断借用存活性、以及隐式重新借用的方式，而是改为让编写者显式写出一切，遇到不确定就直接拒绝。

Decision: 重叠（overlap）是依据完整的、已解析的路径来保守地判断的，不同的字段和不相等的字面量索引可确立不相交性（disjointness），因为一个检查器能够直接判定的保守判断，胜过一个它必须靠推断才能得到的精确判断，而不是采用对控制流敏感的别名分析。
> 通俗解释：判断两个借用是否可能"重叠"（即是不是在操作同一块内存）时，编译器只看完整写出的访问路径，比如 `a.b` 和 `a.c` 因为字段名不同就肯定不重叠，`arr[0]` 和 `arr[1]` 因为下标是不同的字面量数字也肯定不重叠；除此之外一律保守地当作可能重叠处理。这样规定是因为，编译器需要的是一种自己就能直接算出答案的简单判断，而不是需要靠复杂推理才能得到的精确判断——精确判断能放行更多其实安全的代码，但代价太高。被否决的做法是使用对控制流敏感的别名分析（跟踪代码执行过程去判断两个引用是否指向同一块内存），因为那种分析太复杂。

Rejected:
- 采用 Rust 实际发布的那种推断式借用检查，具有省略的生命周期、非词法的存活性分析，以及隐式重借用：被否决，因为复制 rustc 的借用检查器，其实现工作量是不可接受的，因此所有权设计仅立足于一套简化过的、显式区域、"不确定就拒绝"的演算。
  > 通俗解释：这是指完全照搬 Rust 目前实际使用的那套借用检查器，其中生命周期大多可以省略不写、存活性判断跟着实际执行路径走（而不是简单按代码书写顺序）、而且借用可以被隐式地重新借用。这个方案被否决，原因是照搬 rustc 的借用检查器实现工作量太大，所以所有权设计只能立足于一套简化过的、要求显式写出区域、遇到不确定就拒绝的方案。
