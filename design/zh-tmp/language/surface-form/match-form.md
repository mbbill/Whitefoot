Decision: 条件形式由被检验值（scrutinee）的类型来选定，绝不由编写者来选定，一个 Bool 条件采用 `if`，而一个枚举被检验值则采用 `match`，因为一个 Bool 被检验值的两个分支标签，永远都是固定顺序下的 `True()` 和 `False()`，因此这套分支仪式并没有携带任何条件本身尚未携带的信息，而不是把 match 当作唯一的条件结构。
> 通俗解释："被检验值"（scrutinee）就是拿来做判断的那个东西，比如 if 后面的条件、match 后面被匹配的值。这条决定规定：如果拿来判断的是一个真假值（Bool），就必须写 `if`；如果是一个枚举（enum，即"只能取几种预先列好的值之一"的类型），就必须写 `match`，编写者自己不能挑选用哪种写法。原因是，一个真假值只有两种可能，对应的两个分支永远是固定的"真"和"假"，如果强行也用 match 写，就得多写一层分支标签，但这层标签根本没告诉你任何 if 条件本身没告诉你的新信息，纯属多余的形式。被否决的方案是让 match 成为唯一的条件结构，连判断真假值也要用它。

Decision: 一个条件值是一个 `let` 初始化器，其每一个分支都以恰好一个 `give` 结束，或者发散（diverge），因为条件式初始化是 AI 编写者最常需要用到的模式，而直接交付这个值，能省去每一个条件值都要配一个机械式辅助函数的麻烦，而不是把它提取成一个从每个分支返回的辅助函数。
> 通俗解释：这条决定是说，可以直接用条件判断（if/match）的结果给一个变量赋初始值，写法是 `let value = ...`，其中每一个分支要么用 `give` 交出一个值，要么"发散"（diverge，意思是这条分支根本不会正常走完，比如提前返回或让程序中止）。这样规定是因为"根据条件算出一个值再赋给变量"是 AI 写代码时最常遇到的场景，如果不支持这种写法，就得每次都单独定义一个小函数，在每个分支里 return 一次，光是为了绕开这个限制就要多写很多重复的辅助函数。被否决的方案正是这种做法：只让条件语句本身存在，初始化逻辑必须提取成一个从各分支分别返回的辅助函数。

Decision: 被检验值可以是一个完整的表达式，因为把它限制为一个位置（place），会给这唯一的条件惯用法增加负担：每次使用都要有一个机械式的临时变量，还给能力较弱的编写者增添命名负担，而不是先把值绑定下来，再对这个名字进行匹配。
> 通俗解释："位置"（place）在这里指的是一个已经存了值的变量或存储单元，而不是临时算出来的表达式。这条决定允许直接把一整个表达式（比如一次函数调用的结果）放在 if/match 后面做判断，不要求先把它存进一个变量里再判断。原因是，如果非要求先存成变量，那么每次做条件判断前都得多写一行"先声明一个临时变量"的代码，这纯粹是走形式，而且还要求写代码的人（尤其是能力较弱的 AI）多想一个变量名，纯属额外负担。被否决的方案就是要求先把值绑定到一个临时位置，再对这个位置做匹配。

Decision: 不带 else 的条件语句，是"空的备选分支"这一情形的唯一拼写方式，一个空的 `else` 块是被拒绝的，而一个恰好只包含一条条件语句的 `else`，会被拉平成 `else if`，因为一种结构只有一种拼写方式，而不是允许"空的备选分支"存在两种拼写方式。
> 通俗解释：如果条件不成立时"什么也不做"，唯一合法的写法就是干脆不写 else 部分；写一个内容为空的 `else { }` 是不允许的。同样，如果 else 里面恰好只放了另一条 if 语句，就必须直接写成 `else if`，不能再套一层花括号。这样规定的理由很简单：同一件事只能有一种写法，不允许"不写 else"和"写一个空 else"这两种写法同时合法，否则编译器和阅读者都要多分辨一种等价但多余的形式。

Rejected:
- 把 match 当作唯一的条件结构，包括作用于 Bool 之上：被否决，因为一个 Bool 被检验值的两个分支标签，永远都是固定顺序下的同样两个，因此这套仪式并没有携带任何条件本身尚未携带的信息。
  > 通俗解释：这个被否决的方案是让所有条件判断都用 match 写，哪怕判断的只是一个真假值。它被否决是因为真假值的两个分支永远只能是"真"和"假"这两种、顺序也固定，用 match 硬套上去多写的那层分支标签完全不提供新信息，纯粹增加了书写负担。
- 把被检验值限制为一个位置，即先把计算出的值绑定到一个临时变量上：被否决，因为它会给这唯一的条件惯用法增加负担：每次使用都要有一个机械式的临时变量，还给能力较弱的编写者增添命名负担。
  > 通俗解释：这个被否决的方案要求，凡是要做条件判断的表达式，都得先存进一个临时变量，再拿这个变量去判断，不能直接判断表达式本身。它被否决是因为这会让每一次条件判断都多出一步机械操作（起个变量名、赋值），对能力较弱的编写者来说尤其是多余的负担。
- 仅作语句使用的 match，把条件式初始化提取成一个从每个分支返回的辅助函数：被否决，因为条件式初始化是 AI 编写者最常需要用到的模式，这种辅助函数惯用法唯一记录在案的理由，只是它在规范撰写上最省事，而直接交付值，能省去每一个条件值都要配一个机械式辅助函数的麻烦。
  > 通俗解释：这个被否决的方案是不允许 match 直接产出一个值，只能当普通语句用；如果想根据条件算出一个初始值，就必须另外写一个函数，在每个分支里各自 return 一次。它被否决的原因是，这种"用条件算值"的需求在 AI 写代码时非常常见，而当初选择"必须写辅助函数"这个做法，唯一的理由只是它让规范写起来更省事，并不是它本身更好；直接让条件结构交付值，能省掉大量这种重复的辅助函数。
