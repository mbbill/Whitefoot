Decision: 一个循环前事实会在循环头处存活下来，除非循环体内部有一次清除（kill）能够在不离开循环体的情况下到达之后的某个循环头，因此一次 return、一次被传播的错误，或一次 break，都不会在循环头处清除任何事实，因为退出作用域规则会在任何包含 return 的循环中丢弃全部循环前事实，并且这是导致 DEFLATE 解码器在其 29 处证明义务位点中只证出 5 处（而预期本应证出 17 处）的主要原因，而不是把每一条离开作用域的边都当作循环头处的一次清除。
> 通俗解释：这里的"循环头"指的是循环开始处、每次绕回来都要重新核对一遍不变式（invariant）的那个位置。这条规定说：一个在进入循环之前就已经成立的事实，会在循环头处继续保留下来，除非循环体内部真的有一步操作会"清除"（也就是让这个事实不再成立）它，并且这一清除动作是绕回到后面某次循环头、而不是直接跳出循环体才发生的；因此循环体里的 return（直接返回）、把错误往外传播，或者 break（跳出循环），都不会被当成在循环头处清除了任何事实，因为它们根本不会再绕回到循环头。这样规定是因为，此前的规则是"任何离开当前作用域的路径都算清除"，结果只要循环体里出现一次 return，整个循环进入前已知的事实就会被全部丢弃；这正是真实测试中 DEFLATE（一种压缩数据的解码算法）解码器程序原本预计能证出 29 处证明义务中的 17 处，实际却只证出了 5 处的主要原因。被否决的做法就是把每一条离开作用域的路径都当作在循环头处发生了一次清除。

Rejected:
- 每一条离开作用域的边，都会在循环头处清除每个绑定的事实：被否决，因为循环体内的一次 return 就会丢弃全部循环前事实，而同一个程序，当 return 在循环之外时能够履行证明义务，当 return 移到循环内部时却会被拒绝。
  > 通俗解释：这个被否决的方案是，把每一条离开当前作用域的路径都当成在循环头处把每个变量的已知事实清空一次。它的问题很直观：哪怕循环体里只有一次 return，也会把进入循环前所有已知的事实全部丢光；结果就是同一段程序，如果把这个 return 挪到循环外面就能顺利完成证明，一旦放回循环里面却会被拒绝，明显不合理。
