Decision: 每一种语义结构都只有一种拼写方式和一种字节级别的格式，非规范的输入会被拒绝，而不是被重新格式化，而一个元素是否需要写出来，仅由它的语法类别决定，因为一条依据"检查器能否在某处推断出某个元素"来决定的规则，会迫使编写者去模拟检查器才能知道到底什么是可以写的，并且会让规范每放宽一个位置就多出一条条款，而不是按位置逐一放宽。
> 通俗解释：这条决定的意思是，每种语法结构只有一种写法、一种排版格式，写得不规范编译器会直接拒绝，而不是自动帮你改好。某个元素要不要写出来，只看它属于哪种语法类别，不看编译器在这里能不能自己猜出来。这样规定是为了让编写者只需要记住"这类东西该怎么写"，不用先在脑子里模拟一遍编译器的推断过程才知道某处能不能省略，也不用让规范为每一个可以省略的位置都单独加一条规则。被否决的做法是"按位置逐一放宽"：只要编译器在某个位置能推断出该元素，就禁止写出来，其余位置才要求写出来。

Decision: 不存在注释；文档存在于声明的 doc 字段中，因为注释是检查器看不见的文本，而一个 doc 字段则是声明中经过检查的一部分，而不是采用自由格式的注释。
> 通俗解释：这门语言不允许写普通的代码注释，想写说明文字只能放进声明自带的 doc 字段里。原因是普通注释只是给人看的文字，编译器完全不检查它，容易和代码脱节、写错也没人发现；而 doc 字段是声明的一部分，编译器会检查它是否合规。被否决的做法是像大多数语言那样，允许自由格式、不受检查的注释。

Decision: 计算采用扁平的三地址（three-address）形式，每个表达式只有一个运算，每一个中间结果都由一个绑定命名，因为实测表明这种形式对性能是中性的，并且它把优先级、嵌套与前瞻（lookahead）都从这门语言中去掉了，而不是采用带优先级的嵌套表达式。
> 通俗解释："三地址形式"是指每个表达式只做一次运算，任何中间结果都要先用一个名字存起来，不能把好几个运算嵌套写在一行里。这样规定是因为实际测量表明这种写法不会拖慢程序性能，同时还能让语言不用处理运算符优先级、表达式嵌套，以及解析时要向前多看几个符号才能确定怎么读这些麻烦事，编译器和读代码的人都更省心。被否决的做法是像大多数语言那样允许按优先级书写嵌套表达式，比如把 a + b * c 直接写在一起。

Decision: 一个函数体内绑定符（binder）的模式与类型，是从它的右侧表达式推导出来的，绝不需要写出，每一个右侧表达式都能自行确定类型，推导过程不会去读取之后的语句或某个使用点，因为检查器能从同一条声明中唯一地重建出它们，所以写出一份副本只是没有信任边界的冗余，而签名中的模式、类型、具名字段与实参标签则仍需写出，因为处在那个边界上的读者无法重建出它们，而不是在每一个函数体内绑定符处都写出模式与类型。
> 通俗解释："绑定符"就是给某个值起名字的那个写法，比如 `let x = ...` 里的 x；"模式"大致是指这个绑定的形状（比如是不是可变、是不是拆包出来的一部分）。这条决定规定，函数体内部起名字时，不需要另外写出它的模式和类型，因为编译器只看它右边的表达式，就能唯一确定这些信息，就像看到 "3 + 4" 就知道结果是整数一样，再让人手写一遍类型纯属多余，还容易和实际不一致。但函数签名（也就是函数对外的接口，包括参数模式、参数类型、具名字段、调用时的实参标签）仍然要写清楚，因为看这段代码的人站在"函数外面"这个边界上，看不到函数内部的表达式，没法反推出这些信息，所以这里的书写不是多余的，而是必要的。被否决的做法是要求每个函数体内的绑定符都显式写出模式和类型。

Decision: 迭代有两种源码形式：一种是带有可选标签（label）与 break 的普通 loop，另一种是在只捕获一次的端点上进行的、步长为一的递增半开区间计数循环，其绑定符由编译器更新，源码层面则不可变，因为只保留单一形式的做法，会迫使每一次有界遍历都各自拼写出自己的计数器、守卫条件和自增操作，而这些遍历所携带的事实，随后会在循环头处被丢弃，而且三次真实的 SHA-256 索引遍历，加上四次对抗性编写者探测中的三次，都各自独立地选择了同一种递增半开区间计数形态，而不是把 loop 加 break 当作唯一的迭代形式。
> 通俗解释：这条决定保留了两种写循环的方式：一种是最普通的 loop（可以带标号、可以用 break 提前跳出），另一种专门用来"从起点数到终点、每次加一"，这种计数循环的起止点只在一开始取一次值，循环变量本身由编译器自动更新，程序员不能在循环体里改它。之所以要单独设一种计数循环，是因为如果什么都用普通 loop 写，每次数东西都得自己手写计数器、判断有没有到头、再手动加一，编译器还没法在循环入口保留住这些量之间本该成立的关系（"事实"），等于每次都白白丢掉这些信息。团队观察到三个真实的 SHA-256（一种哈希算法）代码里的索引遍历，以及四次模拟编写者故意刁难编译器的测试中的三次，都不约而同写出了同一种"递增、左闭右开"的计数循环，说明这确实是一种值得单独支持的常见模式。被否决的方案是只保留 loop 加 break 这一种形式，让所有有界遍历都自己拼计数器、判断和自增。

Rejected:
- 按位置逐一放宽，即在检查器能够重建出某元素的地方就禁止书写该元素，其余地方则强制要求书写：被否决，因为合法性必须仅凭语法类别就能判定，而一条依据"某处的推断是否成功"而定的规则，会让编写者去模拟检查器，并让规范每多一个位置就多出一条条件性条款。
  > 通俗解释：这个被否决的方案是，只要编译器在某处能自己推断出某个元素该是什么，就不允许在那里写出它，推断不出来的地方才必须写出来。它被否决是因为合法不合法应该只看语法类别就能确定，不该靠"编译器在这个位置能不能推断成功"来决定，否则编写者得先在心里跑一遍编译器的推断逻辑才知道某处能不能省略，而且规范里每多一个可以省略的位置就要多写一条对应的规则，越滚越复杂。
