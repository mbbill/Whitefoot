Decision: The compiler is a research instrument for iterating the language, one safe-Rust crate with private interfaces that change as experiments demand, simple implementations over ordinary collections, and no stable artifact format, replay, release machinery, or product-scale resource controls, because the goal is to test language and performance ideas quickly on real programs, product structure built before a real consumer exists only slows that down, and forbidding unsafe code makes the compiler's own memory safety Rust's guarantee rather than a review burden, instead of a product-grade toolchain with stable crate boundaries and checked artifacts.

Decision: The compiler admits and lowers source by the specification's rules alone, through one semantic path and one lowering path, and never by recognizing a function's name, signature, or shape, a project, a corpus, or a test, so no conformance case, staging plan, or profile can select acceptance, because a capability implemented by recognizing a particular program is a special case the language does not have, and it would let tests and corpora define the language in place of the specification, instead of shape-matched special cases or corpus-driven acceptance.

Decision: Valid specified source that the compiler has not implemented stops as an explicit unsupported capability and is never reported as invalid source, because a compiler gap reported as a language rejection rewrites the language from the implementation side, instead of misreporting unsupported source as invalid.

Decision: A rejection names the numbered rule it violates and the location, one compiler executable rejects the same source the same way every time, and no acceptance path depends on a timeout, fuel, a work budget, heuristic early failure, or hash-iteration order, while which of several violations is reported first is not part of the language, because a writer acts on a rule and a location, acceptance that depends on time, budget, or iteration order is acceptance by accident, and two correct checkers may legitimately meet different first violations, instead of a portable first-error order or budgeted checking.

Decision: The runtime every compiled program links, the compute scheduler, the completion runtime, and the exhaustion floor, is plain C reviewed by hand and lies outside the crate's safe-Rust guarantee, because it is target code that speaks the host's threads, rings, and ports directly, and this research compiler and its runtime will be replaced by self-hosted ones, so a checked runtime language or a confinement policy now is work that buys nothing while ordinary engineering quality stays required, instead of a memory-safety-checked runtime language or a stated unsafe-confinement policy.

Rejected:
- A product-grade checked-artifact toolchain with stable crate boundaries, serialized artifacts, and replay: rejected because it multiplied crates and gates before a resolver or backend existed and imposed protocols that had no consumer.
- Hardening the frontend against hostile input and re-verifying a previous stage's result inside the trusted path: rejected because this compiler exists to iterate the language and will be replaced by a self-hosted one, so defense in depth here is work that buys nothing, while ordinary engineering quality stays required for fast iteration.
- Superseded system-inventory states kept reachable behind compile-time switches so that a differential test can show an earlier program's module unchanged: rejected because the compiler implements exactly one specification, the active one, so a switch that reconstructs a superseded inventory has no consumer and only adds code paths to maintain.
