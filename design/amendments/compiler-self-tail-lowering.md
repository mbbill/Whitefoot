Node: compiler/self-tail-lowering

Decision: Retain a checked self-tail selection on the ordinary checked call through proof checking, then lower a selected return to argument capture, its checked releases, and a jump to a parameterized body-entry block, because the existing call judgment must still check requirements and effects while the existing SSA block parameters express simultaneous reassignment without a target ABI dependency, instead of relying on LLVM tail-call optimization or building a second recursive-call checker. The entry block receives fresh values on each transfer, and addressed storage is reused under the same physical-frame rules as an ordinary loop.

Decision: Select an unmarked direct self call in the sole return position when it satisfies the same incoming-reference-root and pre-transfer release conditions as a marked call, retaining an ordinary call when any condition is unavailable and recording an FN-10 rejection only for a written `musttail`, because those conditions establish the same safe activation replacement independently of the writer's demand for a guarantee, instead of requiring a marker to receive the optimization or making optimization eligibility a new source acceptance rule. The selection uses the checker information already needed by the guaranteed transfer, and both forms share one lowering; the source marker remains the way to require the transfer.

Rejected:
- Lowering self recursion with LLVM `musttail`: rejected because a self transfer needs no inter-function ABI and the compiler's own control-flow lowering guarantees the transfer on every target, including without optimization.
- Sequentially overwriting source parameters while evaluating the remaining arguments: rejected because swaps and aggregate moves must read the previous activation's values before any replacement.
