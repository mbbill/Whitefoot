Decision: The checker carries a reference as the resolved path it names, its root binding, its ordered steps, and the immutable value each index or endpoint captured when the reference was formed [REF-1], together with the validity fact that path currently has [REF-2], and that pair is what survives a copy of the reference name, a control-flow join and a call, a join taking the union of the incoming path sets so that every check on the reference must hold for every member, because a reference is not storage and has no formation record to recover it from, an incoming reference parameter arrives already carrying the caller's path by substitution [EFF-5], and a copy of a reference name copies a name for a path rather than anything that could drift from it, instead of identifying a reference by its storage origin or by a descriptor's local formation, as the retired compiler/view-loans decision did.

Decision: The fixed point that bounds a reference variable's join path set closes over the static path shapes and falls back on reject-when-unsure [OWN-8] for the index components, because [REF-1] bounds the shapes, a loop-carried rebinding being forbidden to extend a path through itself, so the shape closure terminates, while the captured index values have no such bound across iterations and an index the closure cannot fix is exactly the case the language refuses rather than approximates, instead of widening an unfixable index to an unknown index that then overlaps everything silently or searching for a bound on the captured values.

Decision: Reference validity [REF-2] is a lattice threaded through the checker's ordinary statement walk, not a separate pass and not a side table consulted at use sites, because that walk already visits every invalidating event the rule enumerates, a write, move or release of a proper prefix, a call's substituted write paths, the scope exit of the path's root binding, and the invalidation of a payload refinement, and because each use must be judged against the state at that point and must be able to name the invalidating event in its diagnostic, instead of a second traversal that would have to reconstruct the same order or a lazy table that cannot say which event killed the reference.

Decision: A borrowed-match payload binder carries an origin-distinct, flow-sensitive witness for each `(enum place, variant)` refinement its arm establishes, witness validity meets by occurrence at control-flow joins, and an arm exit preserves a payload reference only when another valid witness for every dependency survives that scope, because syntactic nesting alone cannot distinguish an unchanged enclosing refinement from an enclosing occurrence invalidated by an enum write followed by a nested match that establishes the same fact again, and because reference rebinding must neither revive nor discard the control-flow fact, instead of treating active arm spellings as the refinement state or attaching the witness to the rebindable reference path.

Decision: The checked place-access inventory marks which entries are the enclosing expression's selected storage and which are storage read while evaluating an index or another carried operand, while retaining both in source order for effects, because a borrowed match needs the complete selected path set as its payload origin but treating an index operand's unrelated storage as another enum root can both lose the true invalidation and invent one on an operand write, instead of recovering selected members from tail position or a variant-specific access count that would couple semantic identity to expression layout.

Decision: The pairwise call-site check [EFF-5] lives in the checker and the entailment flow queries it rather than repeating it, because clauses 2 and 3 need the actual argument spellings and the live reference state, which only the checker holds, and the substitution and the kill-and-extend filter already exist on both sides, so one of them must own the answer or the two will drift, instead of a second implementation of the substituted-row comparison inside the flow.

Decision: The path-overlap relation may query the entailment fragment on demand for the index and range separations [OWN-7] asks for, and every discharged separation is carried in the ordinary proof-flow state and intersected across reachable predecessors at a join, while overlap itself is evaluated against the current state's ledger without a context-insensitive result memo, because [OWN-7] now decides two index or range steps by the fixed [ENT-6] families under [MSR-4]'s disposition rather than syntactically, so a purely syntactic relation would have to deny every provable case, and although a resolved path carries immutable captured values that no later assignment can change [OWN-7, REF-1], the proof that relates two such values is available only on edges dominated by the judgment that established it, so branch, sibling-arm and zero-trip-loop paths that never established the proposition must not acquire it, instead of a relation that answers from syntax alone or a per-function memo that turns one branch's proof into a function-wide fact.

Decision: [PAR-1]'s adjacent-statement permission is computed as runs over a running union footprint, a statement joining the current run when its write paths miss the union's read and write paths and its read paths miss the union's write paths and otherwise starting a new run whose paths are read in the state before that statement, and the runs are the overlap groups the checked program hands the backend, because disjointness from a union is the conjunction of disjointness from each member, so the running test accepts exactly the runs the rule's every-ordered-pair condition accepts, at a cost linear in the statements of the block rather than quadratic, and because the permission is never an obligation, so a greedy partition can lose an opportunity but can never change a verdict, instead of enumerating every ordered pair of a candidate block or approximating the composition by adjacent pairs with a transitive extension.

Decision: A run's members that are not calls carry no hand-out and leave the parallel lowering's clone set derivation untouched, the clone set remaining the functions reachable from the entry that can reach a hand-out as compiler/parallel-lowering/two-worlds decides it, because only a handed-out call has a lowering that differs between the two worlds, so a permitted adjacency among ordinary statements is information for the backend's scheduling and alias metadata rather than a new hand-out site, instead of widening the clone set to every function containing a permitted run or refusing to export a run because one member is not a call.

Decision: A counted-loop element map [PAR-2] recognizes `deref(b)[a*i + c]` through a `deref` step of a live `Box` binding exactly as it recognizes an inline subscript, the `deref` being an ordinary path step that resolves to one root [REF-1, TYPE-7], because [TYPE-9] admits a runtime-capacity shape only as `Box` content, so every runtime-width kernel writes its element map through a `deref`, and a recognition that stopped there would permit the constant-capacity loops and deny exactly the loops whose width makes overlap worth taking, instead of restricting the element map to a subscript whose root is a local binding.

Decision: The allocation fact [EFF-3] needs, whether a call allocates, is carried as a flag in the checked function metadata the checker produces, because [STOR-8] gives allocation no effect entry, so the row cannot carry it, while [EFF-3] still excepts an allocating call from deduplication and reordering, and [DIAG-2] makes the checked program the only input that may grant lowering authority and requires it to represent explicitly what lowering acts on, instead of rederiving the fact at lowering from the callee set, which would put a program property outside the checked program, or reviving an `allocates` effect spelling the row grammar no longer has.

Rejected:
- Enumerating every ordered pair of statements in a candidate block to compose [PAR-1] permission: rejected because the running union answers the same question, disjointness from the union being the conjunction over the members, so the enumeration buys nothing for a cost quadratic in the block.
- Approximating [PAR-1]'s composition by adjacent pairs with a transitive extension: rejected because permission is not transitive: a statement writing a place, a statement touching neither, and a statement reading that place pass both adjacent tests while the rule denies the run, so the approximation would admit an overlap the specification refuses.
- A purely syntactic path-overlap relation that never consults a proof, so that every consumer sees one answer without a query: rejected because [OWN-7] now decides index and range steps by proofs from the fixed [ENT-6] families, so a syntactic relation would deny every case the language admits and would make the disjointness the parallel and call-site rules are built on unreachable.
- A per-function overlap-result memo keyed only by resolved paths: rejected because immutable captured values make the proposition stable but do not make its proof available before or outside the branch that established it; a proof obtained under one guard otherwise leaks through a sibling or join and can preserve a stale fact after an overlapping write. The flow-state ledger above retains reuse on dominated edges and intersection removes evidence absent from any reachable predecessor.
- Rederiving the allocation fact at lowering by inspecting the callee's own body or effect set: rejected because lowering would then establish a program property the checked program does not state, which is the second acceptance path [DIAG-2] and this tree's single-semantic-path decision forbid.
- Stopping element-map recognition at a `deref` step so that only inline shapes keep permission: rejected because it would leave every runtime-capacity kernel unpermitted while permitting the constant-capacity ones, which inverts the cases the permission exists for.
