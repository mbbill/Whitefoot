Decision: Every written place whose trailing member names one of [MSR-1]'s four measures is resolved by the one place walker that already takes a `deref` chain, whatever the base spelling is, so that `a.len`, `deref(p).len` and `b.inner.len` are one read with one implementation, because [OP-15] makes a measure read a property of the measured place rather than of how its base was written, and the ordinary field walk that the bare-IDENT path used has no step for a measure at all and reports the reserved spelling as a missing struct field, instead of teaching the measure rows to a second walker, which would leave two implementations of [MSR-1]'s table, [MSR-2]'s descriptor-only support and [EFF-2]'s attribution to drift apart.

Decision: A measure over a place rooted in a named constant is read on that constant's own storage path and yields the `own u64` value with no liveness, ownership or move judgment, because [CONST-1] states that a const table is read "via a subscript, a measure member [OP-15], a field suffix, or a `&` reference" and [CONST-2] makes the storage immutable and static, so there is no owner whose state the read could change and the only effect it can exhibit is what its own subscript offsets exhibit, instead of routing a constant base through the binding place walker, which has no root for a constant and would have to invent one.

Decision: A [FN-9] clause result datum carries the same projection path a parameter datum carries, and a measure member written over one becomes the [MSR-1] row over that projected result place, because [CALL-4] admits a measure over a result place as a relation term and [OP-15] writes that measure as a member of the place, which is exactly how the [PRE-1] construction records state `ensures result.len == n` and `ensures result.inner.len == count`, so a result datum without a path cannot represent the contracts the specification itself writes, instead of keeping the result datum pathless and refusing every boxed construction record's own postcondition.

Decision: A result datum carrying a projection path is an admitted relation term only under a measure, and a bare projected result stays the ordinary [FN-9] refusal, because [CALL-4]'s admitted operand set is the result datum and measures over result places, and a member path below a result names storage inside the result rather than the result itself, instead of admitting every projected result datum, which would publish facts about storage the relation language has no term for.

Decision: A `Box`'s member `inner` is a dereference step in every place walker, not a struct field selection, and a written path that reaches box content is resolved by the walker that has that step, because [TYPE-9] states that a `Box`'s content is the field `inner` reached by the ordinary field step while the storage below it is the box's referent, so a field-index path cannot express the step at all and the walker that only has field indices rejects `b.inner` as a field of a type with no fields, instead of giving the field walk a synthetic field index for box content, which would make a box's content and a struct's first field the same path and would let [OWN-7] treat two different storages as one.

Rejected:
- Routing every suffixed place through the explicit-place walker rather than only the measure and box-content paths: rejected because that walker answers a read with its own [OWN-1] and [WIN-3] judgments, and moving every field read onto it would re-decide the move, copy and read-out verdicts of paths that have nothing to do with a measure or a box, which is a change to acceptance rather than to where one read is implemented.
