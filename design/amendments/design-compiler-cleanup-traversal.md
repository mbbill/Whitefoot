Node: compiler/cleanup-traversal

Decision: The compiler-derived release of an owned chain runs in bounded machine stack, threading its worklist through the cells it has already emptied so that the walk allocates nothing, and a release action's self tail call is eliminated, because [STOR-8] makes allocation total in the source, so a `Box` chain deep enough to exhaust the machine stack is ordinary buildable data rather than a program that had to ask for it, a release whose machine depth is the released value's depth would end such a program in a failure its writer never wrote, and a cell that is about to be freed is storage the walk already owns, so linking the remaining work through it costs no allocation and no extra field, instead of native recursion whose depth is the released value's depth.

Decision: Both the bounded stack and the eliminated self tail call are this compiler's obligations and are stated in no language rule, because the specification promises one walk and reverse declaration order [STOR-3, PROV-6] and says nothing about depth, so a writer can neither read the bound nor depend on it, and the domains that need determinism about resource use will get it from proved totality and proved recursion depth as obligation families rather than from an implementation habit, instead of publishing the release depth as a language promise or leaving the obligation unowned.

Decision: A type whose release graph closes on itself is released by the same bounded walk rather than refused, and the stack ledger reports that release as one bounded entry instead of a recursion row, because a release cycle can arise only where a heap is allowed and a heap-allowed program's resource behavior is a runtime quantity already, while a walk whose machine depth no longer follows the value gives the ledger a fixed number to report, instead of refusing such types or reporting a value-dependent depth.

Rejected:
- Retired decision, one release action per node type calling itself where the release graph closes, so that the walk's machine depth is the released value's depth rather than the type's: rejected because allocation is now total in the source [STOR-8], so a chain long enough to exhaust the stack is data an ordinary loop can build, and ending the process on its release is exactly the runtime failure the writer never wrote that this node was written to avoid.
- An explicit worklist allocated beside the structure being dismantled, decided by strongly connected components over the cleanup graph: rejected because an allocation on the release path is a runtime trap the writer never wrote; this refusal is kept and does not reach a worklist threaded through the cells being freed, which allocates nothing and needs no component decomposition.
- Refusing types whose release graph has a cycle: rejected because a cycle can arise only where a heap is allowed, and a heap-allowed program's resource behavior is a runtime quantity already.
