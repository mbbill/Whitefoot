Decision: The source occurrence that names a captured index or range endpoint [REF-1] is the index of the syntax node of the offset atom that produced it, because the pending compiler/checker-facts captured-values decision fixes that a capture names an evaluation rather than the binding it read, and the offset atom is the artifact the checker can use to give the same evaluation one identity when it is walked twice, as when a commit target is resolved before its right-hand side and read again when the commit is judged, instead of a counter minted as the walk proceeds, which would give that one evaluation two identities and make the target fail to compare equal to itself. The occurrence is not by itself proof that two evaluations in different flow states hold one value; the captured term class and the local proof-flow state decide every such use.

Decision: One written occurrence inside a loop body, whose evaluations across iterations may produce different values, is still one capture identity because the checker does not unroll dynamic iterations and [REF-1]'s fixed point is over static path shapes. The identity therefore authorizes only repeated walks of the same evaluation; whether a previously formed path, affine image or separation remains available at a loop header or exit is decided by the ordinary local flow state and its predecessor intersection, not by occurrence equality, instead of minting a capture per iteration or treating the shared occurrence as permission to carry one iteration's value fact into another.

Rejected:
- A monotonically increasing counter over the checker's walk: rejected because the same written offset is walked more than once -- a commit target is resolved before its right-hand side and re-read at the commit -- and two identities for one evaluation would make a place fail to compare equal to itself.
