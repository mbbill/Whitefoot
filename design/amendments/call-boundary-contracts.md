Node: language/checks-and-proofs/requires-entry-contract

Decision: An ordinary function may carry one erased contract block after its signature, with shared definitions and individually checked requires and ensures clauses, because a shared, explicitly erased block distinguishes proof clauses from executable code and permits shared abbreviations, instead of a single final requirement block ending in one Boolean check or an entry-only contract exclusion.

Decision: A define is a proof-only abbreviation that is substituted textually into every clause using it and never runs, stores a value, or takes a snapshot, because the same abbreviation is read at two different moments, before the call for requires and at the callee's return for ensures, and no single stored value could be right at both, instead of evaluating it once into a hidden slot.

Decision: Callable headers state ordered result types, and a contract may declare `results (...)` once to name every result ordinal for its ensures clauses, because result names are proof-only aliases and callable identity already uses ordinals and types, as the [binding comparison](https://github.com/mbbill/Whitefoot/blob/3b2d1b6f41aeecd70d664b63e57f4cc235f7cdaf/research/investigations/contract-surface/CALL-BOUNDARY.md#result-naming-alternatives) distinguishes, instead of mandatory header names or implicit built-in result names.

Decision: A postcondition about a Result's success value uses an `Ok(value: name)` route to bind its payload separately from the whole-result alias, because the admitted integer facts describe the payload and not the enum value, instead of treating a result name as an implicit payload selector.

Decision: Each requires clause is proved on its own at the call site in the caller's state just before the call, with no fallback runtime check and no callee prologue, and two clauses are the same goal when they name the same operations, types, constants, parameters, and literals after definitions expand, because a goal proved once must be recognized wherever it appears again, and a callee prologue let a helper hide a protected leaf behind a runtime trap, instead of matching goals by spelling or by an algebraic normal form, or checking requirements in a callee-entry prologue.

Decision: A function instance whose requirements contradict each other is legal and simply uncallable: the compiler still checks its structure, ownership, effects, and return shape, lowers an unreachable stub with the right calling convention in place of its body, and publishes no postcondition, because such an instance is harmless dead code that no call site can ever reach, while rejecting it would require the checker to detect every contradiction, which a deterministic no-search checker cannot promise, instead of rejecting such an instance as a source error.

Decision: An exclusive parameter's bare measure in ensures denotes its exit state and entry(parameter) selects its entry state, using ordinary dereference and field projections, because a mutating helper must relate the caller's unchanged storage location before and after the call without equating both sides of an increment to the same moment, instead of an owned run round trip or a separate kernel-only spelling.

Decision: One side of a contract clause carries one datum, so an operation publishes what that admits and no more: the operation that moves a whole window into another publishes that the source is left empty and that the destination's length is at least its entry length, the operation that splits a window at an index publishes that the source's length is that index and the same lower bound on the destination, and a caller needing the exact total reads the destination's length after the call, because the exact sum names three data at once, the destination's entry length, the source's entry length and the result, so publishing it would mean admitting two data on one side of a clause, and what that does to the determinism and termination of the fixed families is an argument that has to be made before the widening and not after it, instead of publishing an exact sum the fact language cannot hold, or widening a contract side to two data to carry it.

Decision: Linked declarations and source definitions have the same call-site requirement boundary, including a build-selected entry, because native linkage cannot justify a proof the ordinary caller lacks, instead of a launcher exception or an executable requirement check.

Rejected:
- A single final requirement block with local bindings and one Boolean check: rejected because it was spelled like executable code so its erased status was invisible, an abbreviation used by both requires and ensures had to be written twice.
- Widening a contract side to carry two data so that moving or splitting a window could publish the exact sum of the two entry lengths: rejected because the determinism and termination of the specification-fixed families rest on the present fact form, re-arguing them is work of its own, and a caller that needs the total can read the destination's length after the call.
- Callee-entry prologue evaluating the requirement on every invocation: rejected because it let a helper hide a protected leaf behind a runtime trap and added the prologue's reads to the callee effect row.
