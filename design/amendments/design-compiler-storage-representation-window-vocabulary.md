Node: compiler/storage-representation

Decision: The checked model and the IR name [TYPE-9]'s six storage cells with one window type carrying a shape, an element and an optional capacity, `Slots` and `Ring` being the two shapes and a written capacity being the constant-capacity placement, while a constant-capacity `Array<T, N>` keeps its own array type and a runtime-capacity `Array<T>` keeps the flat-element run type the port already used, because this node's layout decision gives the two window shapes two emitted types and gives each shape one layout across both placements, so a vocabulary that separates the shapes but joins the placements is exactly the distinction the layout needs and no other, and an `Array` has no window at all [WIN-1] so it shares nothing with either shape beyond its slots, instead of one type per cell, which would spell the shared layout six times and make every window judgment a six-way match.

Decision: [MSR-1]'s table is keyed by seven measured identities, one per written row, so that the two placements of one shape answer `cap` differently without any consumer asking the type again, because a constant-capacity row reads the type constant and stores nothing while a runtime-capacity row reads a word its block stores, and a single key per shape would force every `cap` reader to recover the placement from the type it was handed, instead of one key per shape with the placement recovered at each reader.

Decision: The checked types that carried a region -- the two view types, the store-resident run, the general-store provider and the bump extent -- are deleted outright rather than retained unconstructible, because [STOR-8] gives the language one heap provided by the trusted base and no region parameter, so no written type forms one and every match arm over them is dead, and a dead arm in an exhaustive match is where a later reader looks for behavior that does not exist, instead of keeping them beside the live types until some later package deletes them.

Rejected:
- Keeping the v0.59 fixed-window type for a constant-capacity `Slots` and minting new types only for the cells it cannot hold: rejected because the fixed-window type carries a window origin that [WIN-1] gives a `Ring` alone, so a `Slots` would keep a word no measure of it needs and this node's own no-dead-word decision would be violated by the checked model while the emitted type obeyed it.
- Carrying the placement as a separate boolean beside a capacity that is always present: rejected because a runtime-capacity block has no capacity at compile time at all, so the boolean and the number would have to be kept consistent by every constructor rather than by the type.
