Node: compiler/backend-facts

Decision: `swap` [OP-11] is the one row whose reference parameters carry every emitted fact except `noalias`, because [OP-11] states that its two arguments may name the same place and that nothing happens when they do, so the callee-side promise the parent node derives from [EFF-5]'s pairwise check -- that every surviving caller passes disjoint paths -- is exactly the promise [OP-11] withdraws for this one row, instead of emitting `noalias` uniformly, which would let the optimizer reorder the two stores of a self-swap.

Decision: The no-capture attribute's spelling is probed once at build time by handing a one-function module carrying the new spelling to the assembler the build's C toolchain provides, and the old spelling is used when that is refused or when no assembler can be run, because LLVM 21 renamed `nocapture` to `captures(none)` while no LLVM version is pinned for this project, and every LLVM that accepts the new spelling still auto-upgrades the old one, so the fallback is always valid, instead of pinning a version, which no part of this project does, or parsing a version string, which reports the vendor's marketing number rather than what the assembler accepts.

Decision: `dereferenceable(N)` states the selected target's own size of the referent type, computed by the same layout pass that validates every other generated object, because the attribute is a lower bound on the bytes the callee may read and the language layout ceiling [OP-9] is an upper bound, which is the wrong direction, and because a runtime-capacity block's statically typed header is the part the compiler is sure of, instead of stating the language ceiling, which would claim more bytes than a smaller target representation provides.

Decision: The `nuw` and `nsw` flags are emitted on exactly the `exact` integer family and never on the `wrap` family, because [OP-2] gives the `exact` family a domain obligation the checker discharged before lowering while the `wrap` family is defined at every operand and has no such obligation to state, instead of emitting the flags on every arithmetic instruction, which would state a fact for operands the language defines to wrap.

Rejected:
- Deriving `memory(argmem: read)` from a declared row with no `writes` entry: rejected because the attribute also asserts that no memory outside the arguments is accessed, which a function reading a `const` item [CONST-2] or allocating a `Box` violates, and the IR carries neither the declared row nor the allocation fact today, so the derivation is missing and a fact whose derivation is missing is not emitted.
