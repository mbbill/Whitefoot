Decision: The words of every repair a rejection carries are the compiler's and live in one module, written for an agent that applies them as written: each alternative names one source change at the rejected construct, is selected by that construct, its position and, for a goal, its disposition and what the goal reads, and names the instance from the payload (the goal, residual, binding, argument or row), because the specification fixes which rejections carry a repair and what an alternative may direct but not its words [DIAG-1], and because every repair that compiled in one round in the probes of the [repair-wording investigation](../../research/investigations/repair-wording/DESIGN.md#2-disposition-and-literal-application) fitted the case in hand while the rejections without a concrete repair were the ones that cost the blind writer time; the second ground is provisional, from minimal probes and one writer, and reopens with the investigation's writer trial, instead of one sentence per rule for every position, disposition and instance.

Decision: A refuted goal's repair changes what reaches the construct (its operands or arguments, the returned value, or the statements and requirements that fix them) or the operation or clause that poses the goal; an unproved goal's repair offers the routes what it reads admits: a requirement on the enclosing function when it reads only parameters that no event on a path to it writes, taken from the kill events the entailment walk applied before the judgment; for a goal over computed values or admitted element reads, a proved invariant with `use` steps or a callee relation, each stating the condition it needs, and a guard whose false edge is intended behavior, which declares in the row any read its condition makes through a reference; and for a value only its occurrence identifies, binding it with a `let` first, because establishing a refuted goal leaves the refuting facts in place, so both signs become derivable and the point contradictory [ENT-4], because a requirement over a parameter written before the goal no longer describes it there, because a condition naming an admitted element read establishes the same goal while no condition can name an occurrence-local value [ENT-3], and because the pinned pairs found the guard over a reference parameter's measure rejected by [EFF-2] until its read was declared, instead of asking to establish the fact for both dispositions or offering one set of routes for every goal.

Decision: Every repair is pinned in the pinned-sentence corpus by its rejected source together with a source for each alternative carried out as written, and each repaired source must be accepted with no judgment in its functions succeeding only because the state it is asked in is contradictory, because a sentence compared only with the compiler's own output is a fixed point that cannot see a repair fail when applied, while a repaired source written from the words is an independent oracle that survives rewording, and the contradiction check catches the dead code a guard around a refuted goal compiles to without running the program, instead of pinning the sentence alone or running each repaired program for an exit status.

Rejected:
- One repair sentence per rule for both dispositions: rejected because every probed refuted goal given the establish repair was rejected again elsewhere or compiled to dead code, while the unproved goals given a requirement compiled in one round.
- Pinning only the repair sentence: rejected because the EFF-2 add-and-remove repair stayed pinned while applying it produced a row every call rejects [EFF-5].
- Offering a requirement whenever the goal reads only parameters: rejected because a parameter the body writes or consumes before the goal no longer holds its entry value there, so the requirement would not establish the goal.
- Deciding the requirement route from every write in the body: rejected because a parameter consumed by the call that asks the goal, as `free_empty` consumes its window, would lose the one route that works for it.
