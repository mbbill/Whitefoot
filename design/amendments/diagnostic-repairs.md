Decision: The words of every repair a rejection carries are the compiler's, written for an agent that applies them as written: each alternative names one source change at the rejected construct, is selected by that construct, its position and, for a goal, its disposition and the kind of terms the goal reads, and names the instance from the payload (the argument, operand, value, residual or row), because the specification fixes which rejections carry a repair and what an alternative may direct but not its words [DIAG-1], and the repair an agent completes in one round is one that is true of the case in hand and says which case that is, instead of one sentence per rule for every position, disposition and instance.

Decision: A refuted goal's repair changes what reaches the construct (its operands or arguments, the returned value, or the statements and requirements that fix them) or the operation or clause that poses the goal, while an unproved goal's repair establishes the goal through a route its terms admit: a requirement when the goal reads only parameters, a proved invariant or a callee relation when it reads computed values, or a dominating branch whose false edge is intended behavior, because establishing a refuted goal leaves the refuting facts in place and so makes that point contradictory [ENT-4], and an invariant over parameters that nothing constrains is itself unproved, so in the probes of the [repair-wording investigation](../../research/investigations/repair-wording/DESIGN.md#2-disposition-and-literal-application) the refuted repairs moved the rejection to a caller or an invariant or left the construct dead, instead of asking to establish the fact for both dispositions.

Decision: Every repair is pinned in the pinned-sentence corpus by its rejected source together with the source after applying each alternative as written, and the repaired source must be accepted with the rejected construct still executed, because a repair the compiler then refuses, or one that deletes the construct's behavior, costs the agent a round, and a repaired source written from the words is an oracle independent of the compiler's own output that survives rewording, instead of pinning the sentence alone.

Rejected:
- One repair sentence per rule for both dispositions: rejected because every probed refuted goal given the establish repair was rejected again elsewhere or compiled to dead code, while the unproved goals given a requirement compiled in one round.
- Pinning only the repair sentence: rejected because a sentence compared with the compiler's own output is a fixed point that cannot see a repair that fails when applied, which is how the EFF-2 add-and-remove repair stayed pinned while applying it produced a row every call rejects [EFF-5].
