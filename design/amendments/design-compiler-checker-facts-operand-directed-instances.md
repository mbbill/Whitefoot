Decision: The twelve [PRE-1] rows whose type parameters an operand supplies  -  the nine window operations [OP-10], `swap` [OP-11] and `free_empty` [OP-14]  -  select their concrete instance from the selected type of one designated value operand rather than from a written argument list, and each such row is described by a fixed table giving, per declared type parameter, the operand ordinal it reads and whether it takes that operand's own type or the element type of the shape it names, because [OP-10] states that such a parameter "is supplied by the operand and never written" and fixes the element type as "that shape's own element type", so the element parameter `T` of `place_back` is decided by the window argument and never by the `value` argument, instead of deriving the substitution by unifying every argument type against every parameter position, which would make an ill-typed `value` argument change the instance rather than be refused against it.

Decision: An operand-directed instance is discovered while the body that calls the row is being checked and is built by the existing deferred-materialization loop  -  the `&self` body check records the substitution it derived and stops with the deferred signal, and the `&mut self` driver builds the signature, admits its declared `ensures` selectors, and re-checks the same function  -  because the instance is keyed on the operand's own type, which no walk over the written syntax can know before the body's bindings are typed, and that loop already exists for a derived nominal discovered the same way, instead of adding an argument-type oracle to the pre-body discovery walk, which would need a second, partial body type inference beside the checker's own.

Decision: The phase that checks every concrete function reads its cursor against the live signature list instead of a length captured before the walk, so a signature appended by an operand-directed discovery is itself checked and enters the inventory later phases read, because those phases are indexed by dense function identity and a signature present in the list but absent from the inventory would leave that identity unbacked, instead of deferring the new signatures to a second pass, which would separate the inventory's order from the signature list's.

Decision: A window operand outside the shapes its row admits is refused at the complete `call`, citing OP-10 for a window operation, OP-11 for `swap` and OP-14 for `free_empty`, and an argument whose written form carries no place at all is refused the same way, because [OP-10] states exactly that refusal and location for its own rows while [OP-14] states its wider admitted set  -  the four window shapes plus `Box<Slots<T>>` and `Box<Ring<T>>`  -  without stating a rule of its own for an operand outside it, so the citation follows the rule that states the set the operand failed, instead of citing one rule for all twelve, which would attribute `free_empty`'s admitted set to a rule that does not write it.

Decision: The operand's type is read by a walker that resolves only what a type needs  -  the binding or named constant at the root, a `deref` step, a field step, a `Box`'s `inner` content step, and a subscript's element type  -  and makes no ownership, liveness, validity or effect judgment, because the ordinary argument check makes every one of those judgments immediately afterwards against the instance this walker selected, and repeating them here would either double-count a consuming use or report one rejection twice, instead of typing the operand by running the ordinary argument check on a copy of the binding state, which would also consume the one-shot commit read-outs and obligation records that check writes.

Rejected:
- Enumerating an instance of every operand-directed row over every window type the unit names, so the pre-body walk can build them all: rejected because `append` and `split_off` each take two independent shapes, so the enumeration is a cross product over the unit's window types, and every unused member still reaches signature checking and lowering.
- Keeping the rows generic at the call and substituting their parameters only locally, without entering the signature inventory: rejected because a checked call carries a function identity that lowering resolves to a callee, and a locally substituted signature has none.
