Decision: Extend captured-extent work summaries with the runtime Array length behind an original read-only Box reference formal, carrying the checked absence of writes to that formal root through exact direct chunk captures and using the ordinary typed Box/header projection at the split site, because a helper over `&Box<Array<T>>` otherwise loses the runtime extent that an equivalent range helper retains, while the original formal's checked call lifetime and EFF-5 separation from other formal writes make its header available even when the priced loop is empty, instead of interpreting every nominal address as a descriptor, reading through captured owners that may already be consumed, or adding a separate lifetime analysis to work estimation. This is an optimization boundary: mutable formals, rebound reference values, local owner captures, enum payloads and indexed projection paths retain their existing static estimate; no source acceptance, reference lifetime, output, sequential lowering or runtime constant changes.

Rejected:
- Requiring an already captured scalar measure at the outer loop: rejected as the repair because it already works but the affected source observes its length only inside the helper, so it leaves the demonstrated whole-Box helper gap in place.
- Dereferencing any captured Box or following arbitrary aggregate paths while pricing: rejected because capture-all may retain consumed owners, and enum or indexed paths may require facts unavailable at the speculative split-site read.
- Inferring source-reference validity in the work estimator: rejected because the checker owns that judgment; lowering can copy the established no-write fact for original formals and transport it through exact captures without a second validity analysis.
