Decision: The base case of the allocation fact [EFF-3] is the declaration identity of the five [PRE-1] records that take from the heap by definition (`box_new`, `box_array_filled`, `box_slots_new`, `box_ring_new`, and `grow`), recognized by name where the record's signature is built, and every other boundary's fact is the union of the facts of the calls its body exhibits, because [STOR-8] gives allocation no effect entry so no row can declare it, [EFF-3] still excepts an allocating call from deduplication and reordering, and [STOR-1, EFF-1] make the other [OP-13] constructors frame-resident or pure conversions rather than heap takes, instead of reviving an `allocates` effect spelling the row grammar no longer has or rederiving the fact at lowering, which the pending compiler/checker-facts decision already refuses.

Decision: Allocation is not an [FN-4] refinement dimension: function-kind compatibility compares the written parameter, result, row and contract surfaces alone, while the checked bound call retains the selected actual's allocation fact for [EFF-3], [STOR-8] and `no_heap` judgments, because the source interface has no allocation spelling and the selected implementation is still the operation that runs, instead of rejecting an allocating actual against a non-allocating formal or falsely assigning the formal's non-allocation metadata to the selected implementation.

Decision: After each complete concrete or symbolic checked-function inventory is built, allocation metadata reaches its least transitive closure over the inventory's retained ordinary call edges by propagating each directly exhibited allocation fact to every caller until no false bit becomes true; the completed bits replace the corresponding function and signature metadata before bound-call metadata is installed, because forward calls and recursive components cannot soundly inherit [EFF-3] from the source-order signature snapshot used while their bodies were first checked, instead of replaying bodies, depending on the postcondition schedule, or leaving a bound actual's retained allocation bit stale.

Rejected:
- Deriving the base case from the callee's body rather than from the record's identity: rejected because a [PRE-1] record has no source body, so there is nothing to derive it from.
- Rejecting an allocating actual when the formal interface does not allocate: rejected because [FN-4] compares source-expressible interface dimensions and [STOR-8] gives allocation no row or contract spelling; the actual fact remains available independently as checked implementation metadata.
- Reusing the postcondition component schedule for allocation closure: rejected because that schedule is intentionally empty when no function writes a postcondition, while [EFF-3] applies to every ordinary call graph; the retained call walker already supplies the complete finite dependency edges independently of [FN-9].
