Decision: The immutable value an index step or a range endpoint captured when its path was formed [REF-1] is carried in the checker as the pair of the source occurrence that evaluated it and the term the entailment fragment reads it as, a written literal, a binding read there, an in-scope const, or nothing nameable, so that two steps carrying one occurrence hold one value by construction, because the pending compiler/checker-facts decision makes the per-function overlap memo sound on the claim that a resolved path's captured values cannot move under it, and only an identity minted at the evaluation carries that claim: naming the index by the binding it read would make two reads of one binding that straddle a write to it compare equal, which is the one way the memo could hand back an answer for a pair it was never asked about, instead of keying an index step on the spelling of the expression that produced it or on the binding that spelling happened to read.

Decision: Two index steps of one base that the fixed [ENT-6] families do not prove distinct leave the overlap walk running rather than answering "overlapping" at that step, so a later field, payload or part step still separates the two complete places, because both steps select the same storage, so the later separation holds in both worlds, if the two indices name one element the later step separates two parts of that element, and if they name two elements the places were already apart, and because [OWN-7] states the opposite rule only for two range steps, whose descendants are relative to two different frames and therefore genuinely undecidable below, instead of treating an unproved index pair as a stop that makes `a[i].x` and `a[j].y` overlap and so refuses every pairwise [EFF-5] comparison over two fields of an indexed aggregate.

Rejected:
- Identifying a captured index by the binding or expression it read, so that two paths spelled alike compare equal: rejected because [REF-1] makes the captured value immutable while the binding is not, so the two are the same identity only when no write separates the reads, and the checker would have to prove that before every memo hit, which is the invalidation work the memo exists to avoid.
- Answering "overlapping" at an unproved index pair, by symmetry with the range rule: rejected because the range rule's reason does not reach it, a range step rebases every step below it, while two index steps of one base leave the coordinate system alone, so the symmetry is a spelling coincidence and the answer would deny a separation [OWN-7] admits.
