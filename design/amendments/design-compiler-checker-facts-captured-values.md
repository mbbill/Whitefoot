Decision: The immutable value an index step or range endpoint captured when its path was formed [REF-1] is carried as a capture-generation identity together with the term the entailment fragment can read there: a written literal, a binding read, an in-scope const, or nothing nameable. An ordinary evaluation uses its source occurrence; a loop-carried arbitrary header uses the structured loop, holder, path and position identity owned by the capture-identity amendment. Two steps from one evaluation therefore hold one value while two reads of one mutable binding that straddle a write remain different, because the evaluation generation is the fact [REF-1] makes immutable for [OWN-7], [ENT-5] and permission, instead of grounding identity in a function-global overlap memo, the expression spelling, or the mutable binding that happened to supply the value.

Decision: Two index steps of one base that the fixed [ENT-6] families do not prove distinct leave the overlap walk running rather than answering "overlapping" at that step, so a later field, payload or part step still separates the two complete places, because both steps select the same storage, so the later separation holds in both worlds, if the two indices name one element the later step separates two parts of that element, and if they name two elements the places were already apart, and because [OWN-7] states the opposite rule only for two range steps, whose descendants are relative to two different frames and therefore genuinely undecidable below, instead of treating an unproved index pair as a stop that makes `a[i].x` and `a[j].y` overlap and so refuses every pairwise [EFF-5] comparison over two fields of an indexed aggregate.

Rejected:
- Identifying a captured index by the binding or expression it read, so that two paths spelled alike compare equal: rejected because [REF-1] makes the captured value immutable while the binding is not, so only the evaluation generation establishes identity; a later proof may relate two other captures without retargeting either one.
- Answering "overlapping" at an unproved index pair, by symmetry with the range rule: rejected because the range rule's reason does not reach it, a range step rebases every step below it, while two index steps of one base leave the coordinate system alone, so the symmetry is a spelling coincidence and the answer would deny a separation [OWN-7] admits.
