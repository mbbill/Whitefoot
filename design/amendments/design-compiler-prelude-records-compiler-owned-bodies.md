Node: compiler/prelude-records

Decision: A [PRE-1] record the compiler itself owns -- a window operation [OP-10], `swap` [OP-11], a construction function [OP-13] or `free_empty` [OP-14] -- is emitted as an ordinary out-of-line function body built at the row's own monomorphized instance, so a call to one is the ordinary call the checker already lowered, because the checker discharged every bound, contract and effect obligation at the call site [OP-4, FN-8, EFF-5] and the body therefore performs no check of its own, one body per instance keeps one implementation of each row where an expansion at every call would put a copy of the window arithmetic at every subscript that touches a window, and the existing capability stop was already made at the point the body would be built, instead of expanding each row inline at its call sites, which would make the number of copies of `place_back`'s boundary arithmetic the number of `place_back` calls in the program and would give the optimizer no single definition to reason about.

Decision: An allocating construction or growth row keeps one out-of-line body per monomorphized instance, while each ordinary call retains the numeric source-length upper bound from that call's accepted [OP-9] derivation in its own checked-call and IR-call metadata, because [STOR-6] qualifies an allocation site's bound against the selected target while one shared body has no one caller's bound; target qualification therefore walks every call of the shared row, resolves the row's concrete boxed content, computes the exact emitted `header + bound * stride` with the selected target's padding, and refuses an unrepresentable call before emitting target output, instead of putting the weakest caller bound in the shared body or specializing the body per call site.

Decision: `free_empty` [OP-14] reclaims the block's own storage and walks no element -- nothing at all for a frame-resident constant-capacity shape and one cell free for a boxed runtime-capacity one -- because the row's `requires window.len == 0_u64` was discharged at the call, an empty window holds no element [WIN-1], and a linear element type must keep its linearity [PROV-6] so no compiler-derived element release may appear in this body at all, instead of reusing the ordinary release walk, which would emit an element loop that provably runs zero times while making the emitted body read as though the compiler releases linear elements.

Decision: `insert_at` and `remove_at` shift `window.filled` by one walk over the window's logical indices, using the same `(head + i) mod cap` coordinate the subscript already emits, and `append` and `split_off` move their run by the same kind of walk, because a `Slots` window and a wrapped `Ring` window are both admitted operands of all four rows [OP-10] and a wrapped window is two extents, so a single byte move is wrong for the ring case and a shape-split implementation would be two copies of one boundary rule, instead of one memmove for `Slots` and a second walk for `Ring`, which is the optimization to make once a measurement shows the walk costs something.

Decision: The `append` [PRE-1] record publishes `deref(destination).len >= deref(entry(source)).len` alongside its destination-retention and source-empty relations, because the operation's exit destination length is the sum of the two entry lengths and lengths are nonnegative, so this source-entry lower bound carries a known nonempty run across the call using [FN-9]'s existing one-datum-per-side relation fragment, instead of omitting every cross-window relation, which loses the bound needed by an immediately following `split_off`, or publishing the exact sum, whose two entry data on one side are outside that fragment.

Decision: The shared body retains [OP-9]'s language ceiling only to validate the concrete element representation and allocator alignment, while its callers retain the site-specific numeric bound used for the byte-domain check, because multiplying the language maximum by an actual stride would stop every runtime-capacity construction and selecting one caller's tighter bound for a shared body would underdescribe the other callers; absence of a per-call allocation record is malformed IR and never silently authorizes the allocation, instead of skipping target qualification for boxed construction and `grow` or adding a runtime guard [OP-9] forbids.

Rejected:
- Expanding the compiler-owned rows at their call sites as IR operations, the way the pre-v0.60 `place_back` and `fixed_vector` operations were expanded: rejected because those rows were operations of the operation table and had no callable boundary, while v0.60 makes every one of them an ordinary [PRE-1] record with a signature, a row and a contract, so a call to one is an ordinary call and the [FN-2] generic-argument, [EFF-5] effect-substitution and [FN-8] requirement machinery all run on it; expanding it would need a second path that reproduces those judgments' consequences in the lowering.
- Declaring the compiler-owned rows to the trusted base so that the runtime C supplies their definitions, as the host rows are supplied: rejected because their bodies are generic over the element type and the window shape, so the trusted base would need one definition per monomorphized instance, which is exactly what the compiler already produces.
