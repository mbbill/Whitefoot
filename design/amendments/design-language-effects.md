Node: language/effects

Decision: An effect row is checked for exactness in both directions, an exhibited but undeclared effect and a declared but unexhibited effect are both errors, and a row stays exact even where a later proof could remove the effect, because an exact row is a statement a reader and the checker can rely on without reading the body, padding a row would be a place to smuggle effects, and the later-proof clause keeps acceptance decidable from the signature alone, instead of rows as upper bounds.

Decision: An effect row is declared only on reference parameters and carries only `reads` and `writes`, where `writes` covers writing, replacing, moving out of, and freeing the storage at the named path and everything below it, while a by-value parameter carries no entry at all and its consumption or its copy is recorded at the call site from the argument's own place, because a row exists to tell a caller which storage it still owns a callee may reach, and the fate of an owned argument is already visible where it is written, instead of rows over owned parameters, separate external categories, or effect roots recovered from an owner's value history.

Decision: An effect path starts at a reference parameter and continues through fields, `deref`, enum payload steps, and whole-index or range positions supplied as arguments, and a signature never contains an index expression, because a callee reaches heap content and the one element its caller selected, and an index that is evaluated once at the call is a fixed object the overlap judgment can compare, instead of a struct-field-only path grammar that cannot name heap content or one element, or signatures carrying index expressions a checker would have to re-evaluate in the callee's state.

Decision: Contracts and invariants are erased proof syntax and introduce no effect, because a proof-only statement that changed a row would be observable, instead of proof statements contributing effects.

Decision: `pure` states that a function has no state effects and promises nothing about termination, because the language has no termination checker, and a promise the checker cannot verify would be a trusted theorem, instead of `pure` as totality.

Decision: Allocation and release carry no effect entry, no provider parameter, and no category of their own, because there is one heap supplied by the trusted base and its addresses are not observable, so an allocation tells a caller nothing about storage the caller can reach and constrains no ordering, instead of provider parameters named in an `allocates` category or an ambient-heap exemption beside branded stores.

Decision: A callee's declared `writes`, after its paths are substituted with the actual argument paths at the call, kills exactly the caller facts whose storage support overlaps those paths and invalidates exactly the live references outside the call whose path has one of them as a proper prefix, before the callee's verified `ensures` publishes replacement facts, because preserving a fact or a reference across a write that may have reached its support is unsound while killing anything the write cannot reach destroys modular proofs, instead of killing by the syntax of an actual argument, killing the whole argument, or leaving an unknown replacement unchanged.

Rejected:
- Rows as upper bounds that a padded declaration may overstate: rejected because a row a caller cannot read exactly is not a boundary, and unexhibited entries are a place to smuggle effects.
- Separate external, blocks, and traps effect categories: rejected because system resources are ordinary state under ownership and scheduling belongs to lowering, so the categories described mechanisms rather than state.
- Following owned values through locals, results, or replacements to derive additional effect roots: rejected because a by-value parameter carries no entry at all and reference paths with explicit contracts supply the complete callable boundary, while ancestry makes that boundary depend on implementation bodies.
- A permission marker on a reference parameter, such as an exclusive or mutable mode, as the statement of whether a callee writes through it: rejected because the effect row already states that path by path, and a second statement of one fact can disagree with the first.
- Replaced decision "Effects describe resolved parameter storage, including ordinary opaque values, while moves into local storage create no effect root from an earlier owner": rejected because x1 Rule 9 gives a by-value parameter no effect entry at all ("A by-value parameter has no effect entry: the call site records the consumption (for `move`) or the read (for a copy) of the argument's place"), so the boundary is now reference parameters only rather than resolved parameter storage generally, while the no-ancestry half of the old decision survives inside the replacing decision above and in the refused alternatives.
- Replaced decision "An exclusive helper's projected declared writes kill exactly the caller facts whose storage support overlaps, before verified exit contracts publish replacement facts": rejected because x1 Rule 2 removes the exclusive-borrow marker the decision's subject names ("There is no `uniq` or `mut` marker on references"), so the trigger must be restated as a declared `writes` on a reference parameter, and x1 Rule 3 and Rule 10 clause 3 add the second consequence the old line did not carry, that the same projected write invalidates live outside references whose path it prefixes.
- Retired decision "Store-branded allocation through Heap or Arena requires the provider as an ordinary parameter and names it in the effect row, while the legacy unbranded box and buffer operations retain ambient allocation": rejected because x1 Rule 14 removes the mechanism entirely ("There is one heap, provided by the trusted base, internally synchronized. Allocation and release carry no effect entry and never prevent two statements from overlapping ... There are no store or region parameters anywhere"), and x1 lists `allocates` effects, store brands, `Heap<'s>` and providers under "Not in this candidate".
