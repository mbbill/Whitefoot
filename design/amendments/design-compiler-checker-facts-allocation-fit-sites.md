Decision: [OP-9]'s static allocation-size obligation is carried on the checked call itself, as a record naming the operation's stored type, that type's language layout ceiling and which declared argument supplies the count, and is judged by the entailment walk at the call rather than inside the compiler-owned row's lowered body, because [OP-13] attaches the obligation to "each runtime-capacity construction" and [OP-10] to `grow`, "over that operation's own stored type and count", and only the caller holds a fact source for the count: [OP-9] admits a selected branch, a proved invariant or a verified postcondition and no written conclusion, all of which exist at the call and none of which exist inside a signature-only [PRE-1] record; leaving the obligation where the retired `buffer_new` node carried it left every `box_slots_new::<T>(capacity: n)` with an unconstrained `n` accepted, instead of giving each row a `requires` of its own, which would state the ceiling as a writer-callable spelling the rule says the predicate has none of.

Decision: The obligation is judged after the argument expressions' own obligations and before the callee's written requirements, because an unproved count is a refusal of the allocation and not a report about a clause the row happens to write, and [DIAG-1] gives the event to the rule the operation violates.

Decision: A generic schema carries every allocation-fit record whose stored-layout ceiling is known, and defers only a layout still depending on an unresolved type or const parameter; a real ceiling beyond u64 remains known and admits only count zero, while an unresolved layout in a concrete instance is a compiler failure, because [ENT-1] requires every expressible OP-9 schema judgment and [FN-2] independently rechecks every inhabited concrete instance, and a scalar, `Box<T>` or a fixed aggregate of known-layout fields can have a known ceiling even inside a generic body, instead of skipping all symbolic callers or fabricating an overflowing ceiling for an opaque stored `T`. No deferred schema record supplies `BufferFits` evidence, a callable summary or lowering authority; the concrete replay must establish its own exact bound.

Decision: The layout-ceiling table the checker computes is [OP-9]'s own: `Box` is one pointer `(8,8)`, a runtime-capacity `Array<T>` `(16,8)`, `Slots<T>` `(24,8)` and `Ring<T>` `(32,8)`, a constant-capacity `Slots<T, N>` is T's pair repeated N times followed by one `(8,8)` length word and a `Ring<T, N>` by two, because the rule writes each pair out and the accepted count at a boundary is `floor((2^64 - 1) / stride_ceiling(T))` exactly; the v0.59 table gave a cell `(16,16)`, every window two descriptor words and a runtime shape `(32,16)`, which made the admitted count at `Slots<u64, 2>` and at `Box<Slots<u8>>` wrong by a factor of the stride, instead of retaining a conservative over-estimate, which is not conservative here because the ceiling bounds the count from above.

Decision: An undischarged obligation renders the defining comparison, the count against the largest count its stored type admits, because [OP-9] states that the predicate "has no writer-callable spelling", so the residual cannot name a row the writer could call, instead of the retired `buffer_fits::<T>(n)` rendering, which named exactly such a row.

Rejected:
- Treating one call's proved count ceiling as a fact inside the shared lowered row body: rejected because the row is lowered out of line and one instance's body serves every call site, so that caller's bound cannot authorize another call's allocation; the checked call and its own lowering metadata retain the site-specific bound for target qualification.
