Node: compiler/backend-facts

Decision: The backend emits the checker's already-proved facts as target attributes and metadata instead of leaving the optimizer to rediscover them, every emitted fact reading a derivation the checked program retains and none of them adding a runtime branch, a lock, a dependency, or a scheduling edge, because [DIAG-2] now permits exactly this supply and fixes its cost at zero, the facts' absence changing no source verdict and no emitted behavior, and because a compiler that proves disjointness and then hands the optimizer a module from which that disjointness must be inferred again pays twice for one fact and usually loses it, instead of emitting a plain module and relying on the backend's own alias analysis.

Decision: The emitted set is `noalias`, `captures(none)`, `nonnull` and `dereferenceable` on every reference parameter, `memory(argmem: ...)` derived from the declared effect row, `inbounds` on element addresses and `nuw` or `nsw` on arithmetic whose bounds and overflow obligations are discharged, scoped alias metadata for disjointness proved inside one body, and `llvm.loop.parallel_accesses` on a loop carrying a retained [PAR-2] permission derivation, because each one names a fact some rule already required for its own reasons, a reference being a name for a path that is live where it is used [REF-1, REF-2] and therefore non-null and dereferenceable, [REF-3] keeping it from escaping so that nothing in the callee captures it, the row stating exactly which memory a call may touch [EFF-1, EFF-2], a discharged [OP-4] or integer-domain obligation being the wraparound-free fact `inbounds` and `nsw` state, and a retained permission derivation being the loop independence the metadata names, instead of choosing an ad hoc subset or deriving any of them in the backend from a shape the checker never proved.

Decision: `noalias` goes on every reference parameter, including one the row only reads, because the callee-side promise it makes holds for every caller that exists: [EFF-5]'s pairwise check runs at every call, proves the substituted paths disjoint wherever at least one of them writes, and rejects the program otherwise, so the surviving callers are exactly the ones where the promise holds, while the attribute's own guarantee covers only the locations modified during the call, which is the same read-against-read admission [EFF-5] makes, instead of withholding the attribute because a call-site proof and a parameter attribute are stated at different places.

Decision: No emitted fact takes the form of an `llvm.assume`, an optimizer fact the checker did not prove, or a second lowering path, and a fact whose derivation is missing is simply not emitted, because [DIAG-2] permits attributes and metadata whose absence changes nothing and forbids exactly those three forms, and because a build that must emit a fact would make the optimizer a consumer the checker owes an answer to, instead of asserting a fact to the optimizer or making emission a condition of lowering.

Rejected:
- Starting with `nsw` from discharged integer-domain obligations alone and deferring `noalias` on the ground that [EFF-5] proves disjointness at a call while `noalias` promises something about every caller: rejected because the checker performs that call-site proof at every call and compiles no call whose proof fails, so the callee-side promise is the conjunction of proofs the language already demands, and the attribute constrains only locations modified during the call, which is precisely where [EFF-5] demands disjointness.
- Emitting the same facts as `llvm.assume` calls or as an alternate lowering the optimizer may select: rejected because [DIAG-2] withholds lowering authority from anything but the checked program and states that neither a discharged call goal nor a proved body-entry fact authorizes an `llvm.assume`, an optimizer fact, or a second lowering path.
- Treating the emitted attributes as a source-visible guarantee, or naming them at the surface: rejected because they are lowering consequences of invariants the specification states in its own vocabulary, and a surface name that borrows backend vocabulary labels the consequence rather than the invariant.
