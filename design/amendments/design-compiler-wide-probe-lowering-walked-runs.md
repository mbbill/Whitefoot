Node: compiler/wide-probe-lowering

Decision: The recognized byte walk is admitted over either `Array` placement [TYPE-9] -- a boxed runtime-capacity `Array<u8>` reached through its cell's content step, and an inline `Array<u8, N>` named by a binding -- and over no window shape, because both `Array` placements are one contiguous extent that begins at their own first element, which is the whole of what the probe's address computation and its window guard need, while a `Slots` or a `Ring` is `len` slots beginning at `head` modulo `cap` [WIN-1], so `base + index` is the wrong address unless `head` is proved zero and the extent can wrap in the middle of a sixteen-byte load, instead of the single runtime-capacity form with an empty root path the recognizer previously matched, which no v0.60 source spells because [TYPE-9] admits that form only as `Box` content and its path therefore always carries the content step.

Decision: The probe operand is the walked run's own place -- the block address for the boxed form, the value or storage address for the inline form -- and the emitter reads each form's length where that form keeps it: the `len` word heading the block, or the type constant, which a constant-capacity run stores nowhere, because the probe's guard needs a length and an element base and nothing else, and reading each from the form that has it keeps one probe operation rather than one per placement, instead of materializing a pointer-and-count descriptor for both, which would reintroduce for the inline run the second word compiler/storage-representation refused for the boxed one.

Decision: The run's root binding is exempt from the addressed-binding exclusion the induction binding, the exit bound and the needle bindings carry, because those three are read here as scalar values that an address could have made stale, while the run is read through its own place at the header and carries no such hazard, instead of refusing every walk over a run the body also writes through an address, which would exclude the ordinary case of a run filled before the walk.

Rejected:
- Extending the probe to `Slots` and `Ring` by proving `head == 0`: rejected because the proof is a new obligation with its own cases and the wrap would still have to be excluded at the load, and no current program needs a windowed byte scan.
- Keeping the recognizer on the boxed form alone: rejected because the constant-capacity `Array<u8, N>` is the shape a no-heap unit and every stack-resident scan must use, so the probe would be unreachable in exactly the programs that have no allocation to amortize.
