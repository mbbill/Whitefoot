Decision: Publish the signed nonnegativity of the actual normalized physical index at the shared Slots/Ring payload projection through `llvm.assume`, beside the existing `inbounds` address, only after ordinary complete-object target qualification, because the checked padded header, positive element stride and allocation extent bound that index below the signed address limit, zero-stride projection already substitutes zero, and the bounded Deque comparison recovers descriptor promotion with this portable spelling, instead of requiring GEP `nuw` syntax that older supported LLVM consumers do not accept. Logical window coordinates and wrapping arithmetic receive no additional assertion; withholding this optional fact changes neither acceptance, target qualification nor ordinary address materialization. The complete mapping and the limits of the measured benefit belong to the [Ring address investigation](../../research/investigations/containers-and-resources/X1-LIBRARY.md#ring-payload-address-qualification).

Rejected:
- Selecting direct GEP `nuw` from a build-time compiler probe: rejected because the emitted module can be consumed by a different supported native compiler, while the nonnegative-index spelling obtains the observed local benefit without that additional producer/consumer dependency; reconsider only with a measured advantage and a qualification of the actual consumer.
- Asserting nonnegativity of the original logical index before zero-stride normalization: rejected because admitted zero-byte storage can have logical coordinates beyond the signed address domain even though its actual payload displacement is zero.
- Adding no-wrap flags to the Ring head arithmetic along with the address fact: rejected because wrapping coordinates and the unused subtraction alternative have different arithmetic domains from the final physical element address.
