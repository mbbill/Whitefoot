Decision: A `struct_decl` is opaque when it carries the written `opaque` modifier, and the prelude-file test that stood alone is kept only beside it, because [TYPE-2] and [GRAM-2] admit the modifier on a source declaration exactly as on the prelude's own opaque structs and give a source-declared opaque struct the same refused constructor entry, so deciding opacity by the file a declaration came from made every source `opaque struct` an ordinary struct whose constructor the checker then admitted, instead of reading the modifier only for the prelude and leaving [TYPE-2]'s refusal unreachable from source.

Decision: An opaque struct's constructor refusal is made from its nominal template before any constructor lookup, in the instance pre-scan as well as in the construct judgment, because such a declaration contributes no constructor template at all, so a lookup reaches a missing entry and reports a compiler resolution failure where [TYPE-2] states a hard error at the complete `call`, instead of registering a constructor template for an opaque struct so the ordinary path can find and then refuse it, which would make the entry usable everywhere the refusal is not re-made.

Decision: A destructuring `let_stmt` whose TYPEID names an opaque struct, including the prelude's cell `Box`, is refused as [TYPE-2] at the complete statement, because the rule states that refusal in the same sentence as the constructor one and [TYPE-9] gives a cell's content the member `inner`, so taking a cell apart is not how its content is reached, instead of reporting the shape mismatch the ordinary destructuring walk finds, which names a type rather than the rule that forbids the form.

Decision: The constructor refusal of an opaque struct and of the three storage shapes is made before the written-argument shape checks of a `construct`, because [TYPE-2] and [TYPE-9] site a hard error at the complete `call` whatever the writer wrote inside it and their rule numbers precede [TYPE-5]'s under [DIAG-1], so `Box::<u64>(inner: 7_u64)` is the refused constructor it names and not a complaint about where its type arguments were written, instead of judging the argument spelling first, which reports a fixable spelling for a form that can never be written at all.

Rejected:
- Refusing the construct where the constructor's declared fields are read, by matching the opaque nominal kind there: rejected because the instance pre-scan runs first and stops on the same missing template, so the refusal would never be reached and the case would stop as a compiler failure instead of the rule's rejection.
