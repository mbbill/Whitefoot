Decision: [EFF-2]'s row judgment is the two-way covering relation the rule states and not equality of path sets: every declared entry must have some exhibited access at or below its path, and every exhibited access must lie under some declared entry, with "below" being the prefix order on an effect path's step list under one root formal, because the rule says in those words that "a declared entry is exhibited when the body accesses storage at or below its path" and that rows "are checked both ways against this complete exhibited set", so a function declaring `reads(values)` whose body reads the measure `deref(values).len` [OP-15] and an element of the same parameter exhibits two paths under one declared entry and is correct, instead of comparing the declared and exhibited path sets for equality, which demanded that the writer spell every path below a declared one and rejected the specification's own worked example.

Decision: The covering relation crosses the two row categories in one direction only: a declared `writes` entry covers an exhibited read at or below its path and an exhibited write answers a declared `reads` entry, while a declared `writes` entry is answered only by an exhibited write, because [EFF-1] states that "`writes(p)` subsumes `reads(p)`, so the pair is never written for one path", so a function declaring `writes(out)` that reads `deref(out).len` before writing an element declares its row exactly once, instead of judging each category against its own declarations alone, which forced the writer to spell the pair the rule says is never written.

Decision: The [EFF-2] diagnostic names as missing each exhibited access lying under no declared entry and as extra each declared entry the body never accesses at or below, because those are the rule's own two failures and the reader's fix differs between them -- add a covering entry, or delete one nothing exhibits -- instead of naming every set difference, which listed a path already covered by a declared ancestor as though it had to be written.
