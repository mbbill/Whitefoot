Node: language/name-resolution

Decision: Exactly one declarative .wfm descriptor owns a source module's name, member files, namespace assignments, direct imports and explicit local export selections, while .wf files contain definitions without a second module, import or pub mechanism, because a module needs one inspectable publication boundary and source ownership must not expand through directory discovery or implementation annotations, instead of per-file module headers, scattered exports, descriptor includes or overlapping publication controls.

Decision: A namespace is a descriptor-assigned path within one module, several source files may contribute to it, and other namespaces and modules are referenced by explicit qualified names with a unique selected owner, because naming organization must remain independent of compilation granularity and namespace paths should not follow filesystem layout, instead of making every naming group a module or permitting different modules to inject declarations into one shared namespace.

Decision: All top-level declaration names are available throughout their namespace independently of source-file and item order, while local binders keep lexical scope and constant/group dependencies, finite instantiation and layout remain separately checked, because arranging files must not change the meaning of a module and a complete name inventory grants neither a value nor a proof, instead of retaining declaration-before-use for non-function top-level names or inferring declaration validity from forward visibility.

Decision: The descriptor selects exported declaration and field identities while each ordinary WF definition remains the single source of its types, effects and contracts, with dependency identities chosen by explicit build bindings, because centralized visibility does not require copying semantic declarations and an unchanged export list does not establish an unchanged API, instead of duplicated handwritten headers, wildcard exports, implicit transitive imports or unrequested facade forwarding.

Decision: Source privacy does not hide verified contract projections, physical layouts or implementation bodies from the compiler, and public enums expose their complete variant schema while struct construction and destructuring respect private fields and the existing opaque rule, because ordinary proof transport, exhaustive matching, release checking and optimized by-value representation still need those descriptions, instead of granting source access from optimizer visibility or making privacy require boxing or dynamic dispatch.

Rejected:
- Replaced decisions that top-level functions are visible throughout one closed unit and that all other declarations retain their lexical visibility points: rejected because descriptor-owned namespace inventories avoid global spelling collisions and make top-level meaning independent of file organization while preserving lexical scope for local binders.
- Requiring both a descriptor export entry and a pub modifier on its implementation: rejected because two editable publication controls obscure which file owns the boundary.
- Repeating public signatures and contracts in both descriptor and implementation: rejected because one ordinary declaration and a generated interface already serve the selected consumer; a full-declaration descriptor with body-only implementations remains a distinct alternative requiring its own binding rules and authoring evidence.
- Treating module imports as ordinary function calls or trusted theorem imports: rejected because membership and visibility grant no postcondition evidence.
- Hiding a private field from compiler contract substitution merely because client source cannot select it: rejected because a verified accessor can publish a relation over that field without granting source access or adding a new fact constructor.
