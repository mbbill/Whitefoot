Decision: Public function implementations bind to the interface identity and must have the same normalized signature, bounds, labels, effects and contracts before their bodies establish those obligations, while public concrete type and constant definitions are reused directly from the interface, because checked declaration repetition preserves a readable public contract and ordinary self-describing function definitions without creating two competing APIs, instead of unchecked header drift, automatic contract refinement or a separate body-only binding form.

Decision: Every public source expression closes over its interface and explicit dependency interfaces, while the compiler separately retains checked implementation, generic and layout information and preserves existing opaque and release rules, because self-contained source contracts cannot rely on hidden representation paths but optimized by-value code still needs private physical descriptions, instead of using a generated private-field projection as a missing public contract definition or making privacy require boxing; abstract nominal capability correspondence and composable logical views remain qualification work in the modular-compilation investigation.

Rejected:
- Replaced decisions that top-level functions are visible throughout one closed unit while other declarations retain lexical visibility: rejected because shared per-module inventories make top-level meaning independent of file organization and prevent unrelated module names from colliding while keeping local scope lexical.
- Thin descriptors selecting public definitions whose complete signatures and contracts live only in .wf: rejected because the clarified consumer needs the handwritten .wfm itself to contain the full API; avoiding checked repetition no longer meets that requirement.

- Treating interface declarations as trusted theorem imports: rejected because declaration correspondence, body proof and current recursive summary availability remain necessary.
