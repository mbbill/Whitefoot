Decision: The call-site pairwise comparison [EFF-5] runs in the checker and hands the entailment fragment the pairs it cannot settle by syntax, as a list of substituted-path pairs recorded on the checked function and discharged where the flow walks that call, because the pending compiler/checker-facts decision already places the comparison in the checker on the ground that clauses 2 and 3 need the actual argument spellings and the live reference state, while the index and range separations [OWN-7] admits are exactly the fixed [ENT-6] families under [MSR-4]'s disposition, which only the flow can run, and because a pair that reaches no submission site would be a refusal the language states and the compiler cannot produce, instead of a second implementation of the substituted-row comparison inside the flow or a syntactic comparison that denies every separation the language admits.

Decision: The overlap relation's separation oracle answers from a per-function ledger of separations already proved, and a pair with no entry answers "not separated", because [OWN-7]'s own default is that a pair no admitted family discharges overlaps, so an empty ledger only refuses and never admits, and because the per-function overlap memo is sound only if an answer does not depend on the program point it was asked at, which a ledger of proved facts over immutable captured values satisfies and an on-demand proof from a `&self` consumer does not, instead of proving each pair where the question is asked, which would need the proof state at every consumer of the relation and would give two consumers two answers for one pair.

Decision: The pairs the checker hands over are exactly those whose first disagreeing step is two index steps or two range steps; every other overlap with a write on one side is refused at the complete `call` with EFF-5's own restructuring, without reaching the fragment, because no admitted family separates a field, payload, part or measure disagreement, so submitting one would produce a goal that is refused rather than undischarged and a diagnostic that names a proof the writer cannot supply, instead of submitting every overlapping pair and reading the refusal out of the residual.

Rejected:
- Discharging the separation where the overlap question is asked, so that no record crosses from the checker to the flow: rejected because the relation is asked from `&self` consumers that hold no proof state, and because the per-function memo would then cache an answer that depended on the asking point.
- Leaving the range-separation obligation family with no submission site after the retired view-formation site was removed: rejected because the family's refusal is one [EFF-5] states, so a family no program can reach would silently drop it.
