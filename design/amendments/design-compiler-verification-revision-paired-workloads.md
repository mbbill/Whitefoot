Replaces the paired-performance decision in `compiler/verification`.

Decision: Paired performance regression compiles each revision's corresponding formal implementation of the same identified workload with that revision's compiler and ordinary runtime, while one current timing instrument checks complete results, validates the expected sample matrix and decides with unrounded paired ratios; workload names, fixtures and oracle interfaces must match before construction, because a language revision can preserve an algorithm and input while necessarily changing its accepted source spelling and owned-value ABI, so compiling only current source with the merge-base compiler can measure no baseline at all, instead of requiring byte-identical source across syntax-breaking language revisions or treating build failure as a passing performance result. Every measured invocation first compares identical candidate images and reports inconclusive evidence if that host control fails, while instrument changes additionally receive explicit slowdown controls under criteria stated before measurement, because the [identical-image failure](../../research/investigations/test-economy/redesign.md#identical-image-host-control-failure) demonstrates that qualification on one runner does not establish another invocation's conditions. Qualification controls do not establish a statistical false-alarm rate, and a one-width suspect or CPU-only regression remains visible without claiming the carried-forward rule detects every slowdown.

Rejected:
- Compiling current sources with both revisions' compilers: rejected because a syntax or ABI revision can make the merge-base compiler unable to construct an otherwise equivalent workload, producing no comparison evidence.
- Silently skipping a mismatched or unbuildable workload: rejected because absence of comparable evidence is not a passing regression result.
