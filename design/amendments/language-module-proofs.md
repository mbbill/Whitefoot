Node: language/checks-and-proofs

Decision: An ensures clause may name a measure reached from a result place through an owned descendant projection of struct fields and Box contents, instantiated at the result destination as the bare result's measures already are and carried by MSR-3's existing construction and binding placements, because a constructor must be able to state its returned value's measures, as a queue factory stating that its ring is empty, and the transport already exists, instead of admitting only the bare result or its Box content, a new projected-datum family or hidden identity fields; enum-payload steps stay excluded because no route selects a variant of an unrouted result.

Decision: When a module's bodies call an instance of another module's generic callable, recursive-component formation treats that instance as calling every function-kind actual and bundle member supplied to it, whether or not the callee's body calls them, because a module's proof availability must follow from its own bodies and its dependencies' interfaces so that an implementer's body edit cannot withdraw a postcondition another module's proof used, and enlarging components only withholds summaries and never admits a circular proof, instead of forming cross-module components from the callee body's concrete call edges.

Decision: Contracts, invariants and proof premises name only accessible paths and establish no fact by naming them, ordinary getters retain runtime calls and written normal-return postconditions while calls remain excluded from contract expressions, and privacy adds no implicit type invariant, because published readonly fields give callers the state their proofs need and verified written guarantees are the only facts crossing a call, instead of observe modifiers, generated getter equations, use view expansion, an added termination checker or treating private representation as a proved invariant.

Rejected:
- The finite observe and use view proposal: rejected because published fields give external contracts and proofs direct names for the state they need, with no logical function kind or termination requirement.
- Checker-only private terms with no external annotation spelling: rejected because an external wrapper, loop invariant or explicit certificate must be able to state its required condition, so hidden terms alone are not a complete authoring interface.
- Annotation-only access to private fields: rejected because contracts would then depend on fields the interface does not publish; the field a contract needs is published instead.
- General mathematical functions as a prerequisite for modules: rejected because direct structural contracts cover the selected witnesses; reconsider abstraction for a concrete representation-evolution or algorithmic-contract consumer.
- Replacing operations with one setter per private field: rejected because separate setters do not establish a relation between fields or a checked invariant protocol.
- Forming cross-module components from the callee body's concrete call edges: rejected because a callee body edit that starts calling a supplied actual would change the caller's verdict without any interface change.
