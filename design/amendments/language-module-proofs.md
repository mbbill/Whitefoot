Decision: Erased contracts, invariants and explicit proof premises may name well-formed private field paths described by a complete module interface, while ordinary runtime field access still requires publication and the checker imports only verified written guarantees and existing normative facts, because the [private-path boundary](../../research/investigations/modular-compilation/LANGUAGE.md#runtime-access-and-annotation-visibility) gives external wrappers, generic formals and manual certificates the vocabulary already present in that interface without executing or assuming a getter, instead of making proof visibility identical to runtime visibility, carrying only unnameable hidden checker facts or requiring a new logical function kind.

Decision: Private and public projections use the same context-scoped value/state images and support versions, frozen entry datums, and checked owned-input/result transport while references keep ordinary invalidation, because mutable state and by-value factories need distinct pre-state, post-state and returned-value meanings without runtime snapshots or resurrected storage, instead of facts keyed only by field spelling, hidden identity fields or extending reference lifetime through a proof relation.

Decision: Ordinary getters retain runtime calls and written normal-return postconditions while calls remain excluded from erased proof expressions, because a checked result-to-private-field relation supports call-site reasoning without assuming that an unexecuted function terminates or importing its body, instead of observe modifiers, generated getter equations, use view expansion or an added termination checker.

Decision: Owned input and named aggregate-result roots admit well-formed structural projections ending in the existing integer proof domain, with ordinary relation shapes and current recursive-component availability, while privacy adds no implicit type invariant, because constructors and consuming operations need to state explicit private-field guarantees across ownership transfer without a separate construction/callback restoration protocol, instead of arbitrary aggregate equality, general new result routes or treating private representation as a proved invariant.

Rejected:
- The earlier finite observe and use view proposal: rejected because its premise that public annotations must hide private paths no longer holds; direct erased field paths cover the selected witnesses with fewer mechanisms.
- Checker-only private terms with no external annotation spelling: rejected because an external wrapper, loop invariant or explicit certificate must be able to state its required condition, so hidden terms alone are not a complete authoring interface.
- General mathematical functions as a prerequisite for modules: rejected because direct structural contracts and ordinary getter postconditions cover the selected witnesses; reconsider abstraction for a concrete representation-evolution or algorithmic-contract consumer.
- Replacing operations with one setter per private field: rejected because separate setters do not establish a relation between fields or a checked invariant protocol.
