Node: compiler/cleanup-traversal

Decision: A `set` target carries the checker's post-right-hand-side `displaces_live_value` judgment into lowering, and the commit emits the target type's ordinary release exactly when that bit is set, because [WIN-3] releases an old affine value only when one remains at the commit while [SET-1] also admits reinitialization of a complete dead binding and [OP-12] may read the selected old value out atomically, cases whose liveness cannot be recovered from the target's type or path in lowering, instead of inferring displacement from whether the target is a binding, reference or element, which leaks a live named owner or double-releases one the right-hand side consumed.

Decision: The displaced value is read after the right-hand side's effects and released after the write, because [SET-1] evaluates the complete right-hand side before any target is written and [WIN-3] sites the release at the commit, so the old owner stops being reachable exactly there, and running the walk after the store leaves the place holding its new owner for the whole of it, instead of releasing before the write, which would leave the place naming freed storage for the length of the release walk.

Decision: Whether a commit owes a release at all is decided from the target's own lowered type through the same release-derivation the scope-exit walk uses, because [STOR-3] makes the release action a function of the type and a type with no release action owes no instruction, instead of emitting a release record at every commit and letting the emitter discard the empty ones, which would put an empty cleanup instruction in the IR of every scalar assignment.

Rejected:
- Deriving displacement from the target type or from a directly named binding path: rejected because a live named binding owes its old value's release, while `set p = f(move p, ...)`, reinitialization of an entry-dead binding, and an admitted atomic read-out reach the commit with no displaced value; the same type and path class therefore occur on both sides of the judgment.
- Recomputing post-right-hand-side liveness in lowering: rejected because [DIAG-2] requires the checked program to carry the authority lowering acts on, and lowering has neither the source ownership state nor [OP-12]'s checked call relation with which to reproduce that judgment.
