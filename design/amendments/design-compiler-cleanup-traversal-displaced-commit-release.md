Node: compiler/cleanup-traversal

Decision: A `set` commit emits the displaced value's ordinary release when its target is reached through a reference or is an element position, and emits none when its target is a directly named binding path, because [WIN-3] states that assigning over an owned place releases the old affine value while the checked program records no liveness for that place, and the two target classes differ on exactly that point -- a reference names a valid path [REF-1, REF-2] and an element inside a window's filled prefix or an array's slots always holds a value [WIN-1], whereas a binding whose owner was moved out is re-initialized by an accepted `set` that displaces nothing -- instead of releasing on every commit, which would free an already-consumed value at the one shape the checker accepts as re-initialization.

Decision: The displaced value is read after the right-hand side's effects and released after the write, because [SET-1] evaluates the complete right-hand side before any target is written and [WIN-3] sites the release at the commit, so the old owner stops being reachable exactly there, and running the walk after the store leaves the place holding its new owner for the whole of it, instead of releasing before the write, which would leave the place naming freed storage for the length of the release walk.

Decision: Whether a commit owes a release at all is decided from the target's own lowered type through the same release-derivation the scope-exit walk uses, because [STOR-3] makes the release action a function of the type and a type with no release action owes no instruction, instead of emitting a release record at every commit and letting the emitter discard the empty ones, which would put an empty cleanup instruction in the IR of every scalar assignment.

Rejected:
- Deriving the release for a directly named binding path as well, from its type: rejected because `set p = f(move p, ...)` and the re-initialization of a moved-out binding are both accepted programs whose target holds no value at the commit, so the derivation would emit a second release of a value already consumed, which is a double free rather than a missed one.
- Leaving every displaced release to the checker and emitting none until a checked record exists: rejected because the reference and element targets are the ones [WIN-3] is written about, their liveness is fixed by [REF-2] and [WIN-1] rather than by flow, and leaving them unreleased leaks one heap object per commit in every program that writes through a reference. The directly named binding path is left open by this decision and still leaks its displaced owner; closing it needs the checked-program liveness record [STOR-3] already requires and `CheckedStatement::Set` does not carry.
