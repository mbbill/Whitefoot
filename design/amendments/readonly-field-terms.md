Node: language/checks-and-proofs

Decision: A place reached through one or more subscripts is a term of the fact language exactly when its last step selects a readonly integer field, the storage measures and a writer's own readonly fields alike, because a readonly field changes only when a place containing it is written (its element or owner replaced or exchanged, its window's elements moved, or the field itself under a row that writes it), so the ordinary overlap kill already ends every fact about it, while an ordinary field below a subscript changes under every write to that field of an element whose index is not proved distinct, which would kill its facts on almost every such write and widen the set of terms the fixed families close over before anything has measured what that closure costs, instead of admitting every subscripted integer place as a term, admitting only the prelude's measures, or keeping subscripts out of terms entirely and leaving a nested storage unprovable. This replaces the node's decision beginning "A place reached through one or more subscripts is a term of the fact language": the choice is unchanged, but that line's ground (the readonly fields are the quantities the storage operations publish) covers only the measures, while the same sentence admits a writer's own readonly field; the [readonly-field term investigation](../../research/investigations/readonly-field-terms/DESIGN.md#soundness-every-change-is-an-overlapping-write) lists the killing events and the conformance evidence.

Rejected:
- Admitting only the prelude's measures below a subscript: rejected because a writer's readonly field changes by exactly the events that change a measure, so the restriction is a special case with no soundness difference, and an index-based structure such as an arena tree could state no relation about one element's field in a requirement and could not bound a loop by it.
- Relying on a let-bound copy of the field instead of a term: rejected because a copy is detached from the storage it was read from, so a requirement cannot relate an element's field to another storage and a caller's fact about the element cannot reach the callee.
