Decision: Parsing, lookup, type formation, body checking, proof components, concrete instances, allocation summaries, lowering and optimization are deterministic dependency-recording queries with stable module/declaration identities and compiler-private persistent results, because only the actual values consumed by a query determine whether an edit changes its result, instead of whole-module source hashes, timestamps, or dense compilation-order IDs selecting reuse.

Decision: Semantic boundaries and implementation evidence have separate identities, and a retained caller derivation may be rebound to the selected implementation only after equality of its consumed claims and current proof availability is established, because a new valid implementation proof need not change the proposition the caller used, instead of retaining stale witnesses or repeating every caller proof when the callee's proof bytes change.

Decision: Preserve current FN-6 instantiation and FN-9 recursive-component rules on incrementally maintained template, binding and call graphs, retracting deleted dependencies and recomputing affected fixed-point components from their specified initial state, because source module cycles do not justify circular postcondition assumptions and changed graph structure can invalidate proofs without signature changes, instead of an acyclic-module restriction or an add-only cache.

Decision: Keep semantic and optimization dependencies distinct, expose checked bodies and justified facts across source module boundaries, and retain separate IR fragments, optimization plans and native objects, because inlining and specialization create implementation dependencies that do not necessarily require source reproof, instead of either permanently opaque independent objects or reassembling the entire program into one LLVM module on each edit.

Decision: Final native linking may run in full over selected cached or rebuilt objects and cached runtime units, with exact composition and target/ABI matching checked before executable publication, because ordinary optimized linking satisfies the selected endpoint without incremental-link padding, indirection or a new linker implementation, instead of requiring incremental image patching or mistaking native symbol resolution for WF verification.
