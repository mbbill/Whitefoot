Decision: [FN-4]'s contract refinement is checked as premise membership — every requirement the actual states must already be one the formal states, and every relation the formal promises must already be one the actual publishes — until the declaration-level proof context the fixed finite check needs is wired, because the check this replaces was structural equality of the two clause sets and fails closed, the natural implementation bug in a refinement check is to read an undischarged query as "no constraint" and so to accept, and membership is the one case of [MSR-4] discharge that needs no proof context at all: the goal is literally one of its own premises, so the check admits a strict subset of what the language admits and admits nothing it refuses, instead of calling a refinement query that is not yet connected to a proof context and defaulting its unanswered results to success.

Decision: The direction checked is that the actual's `requires` set is contained in the formal's and the formal's `ensures` set is contained in the actual's, which is [FN-4]'s stated "weaker precondition, stronger postcondition", because a caller of a function-kind binding establishes the formal's requirements and frames the formal's promises, so a supplied function that required more than the formal would be called without its requirement established, instead of the literal reading of [FN-4]'s discharge sentence for `requires`, which names the actual's set as the discharging side and so states the opposite direction from the sentence above it; that contradiction is reported as a specification defect.

Rejected:
- Following [FN-4]'s `requires` discharge sentence literally, so that the actual's set discharges the formal's goal: rejected because it inverts the substitution property the same rule's preceding sentence states, and would admit a supplied function whose precondition no caller of the interface establishes.
- Keeping structural equality of the two clause sets until the proof context is wired: rejected because [FN-4] newly states that a supplied function *may* refine rather than match, so equality denies every refinement the language admits, which is the case the rule was amended for.
