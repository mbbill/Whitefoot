Node: language/ownership/no-reborrow

Decision: This node is retired with no node text after the change, the node file being deleted, because candidate x1 removes the holder, loan, child-reborrow, and region machinery that every decision of this node governs, and the one question x1 still answers, whether a reference name may be rebound and how a reference reaches a callee, moves to the new node language/ownership/reference-rebinding, proposed in the same revision.

Rejected:
- Replaced decision, every borrow holder has one immutable resolved root, binds once, and never rebinds or retargets at a control-flow merge: rejected because x1 Rule 2 decides the same question the other way, stating "A reference may be rebound. At a control-flow join, a reference variable's target is the set of paths it may name; every check on it must hold for every member of the set", and the simplification the old reason bought, collapsing lval-set borrow types to singletons, is obtained differently, by a reference being a local name for a path rather than storage of its own, so a join checks each named path and needs no retyping machinery; the successor decision is in language/ownership/reference-rebinding.
- Retired decision, a bounded family of reborrows is admitted (statement-scoped argument child, candidate-position child, mode-preserving returned reborrow, arm-scoped match-binder child, shared or exclusive child views): rejected because x1 has no holders, loan strengths, or child views to admit, since under Rule 2 "a reference extends a path, it does not point at p", so writing `&p.x` is an ordinary longer path and not a reborrow of `p`, Rule 4 forbids returning a reference at all, Rule 2 states "There is no `uniq` or `mut` marker on references", and x1's "Not in this candidate" list names returned references, permission markers on references, and slice types as first-class values.
- Retired decision, a call result may be bound as a borrow holder only when the signature alone determines its provenance: rejected because x1 Rule 15 states "A function returns owned values only" and Rule 4 requires a function that "finds" something to return an index or other owned data with the caller forming the reference, so no call result is ever a borrow and no provenance candidate exists to name.
- Retired decision, a completed owned-enum match header or exact owned-Boolean conditional header ends only the call-scoped temporary loans that header created: rejected because x1 has no call-scoped temporary loans and no loan endpoints, a reference into an enum payload being a path step available under x1 Rule 2's refinement fact "that the enum currently holds that variant", with Rule 3 making its death an invalidation of that fact rather than the expiry of a loan.
- Retired decision, an argument child's local region may contain statements before and after its receiving statement while its temporary loan retains the existing statement or completed-header endpoint: rejected because x1 removes regions entirely, Rule 14 stating "There are no store or region parameters anywhere" and the "Not in this candidate" list naming lifetimes, regions, and `region` statements, while Rule 3 replaces the endpoint question with validity as a fact invalidated by named events (a prefix write, move, replacement, or release; the scope end of the path's root local; or the loss of a refinement fact).
- Retired refusal of confining an argument child's local region to one receiving statement, an alternative inside a removed mechanism: rejected because there are no regions or argument children.
- Retired refusal of strict no-reborrow, with exclusive access flowing only by linear threading or restructuring, an alternative inside a removed mechanism: rejected because the dilemma it settled is gone, under Rule 2 handing a reference to a callee forming no child and suspending no parent, and Rule 9 with Rule 10 deciding what the call may touch from the callee's effect row and the pairwise comparison of substituted paths.
- Retired refusal of shared-only child views through borrowed holders, an alternative inside a removed mechanism: rejected because child views are gone, recursive subdivision of output storage now being two range references under x1 Rule 7 whose disjointness is judged by Rule 10.
- Retired refusal of every header-created child reborrow living through the complete enclosing statement including every arm, an alternative inside a removed mechanism: rejected because header loans are gone.
