Node: compiler/rejection-payloads

Decision: A suggested repair is one the language admits wherever it is applied: EFF-2's `expected_row` is the exhibited row without the entries another of its entries covers, a read or write at or below an exhibited write's path and a read below another exhibited read, so every entry is a path the body accesses, EFF-1 admits the row as written, EFF-2 admits it for the body, and `missing` names exact entries, because an agent applies a suggestion literally and a suggestion that fails at the declaration or at every call costs compile rounds and teaches nothing, while every pair such a row leaves on one parameter either overlaps whatever its positions are, which EFF-5 does not compare, or depends on positions that each call's own proof decides, instead of printing the raw exhibited set or merging entries into a wider write. This replaces the node's decision beginning "A suggested repair is one the language admits wherever it is applied": that decision merged every pair of one parameter's entries that a call refused whatever its arguments into one `writes` of their common path, which can name storage the body never writes and so widens every caller's kills (review item O2); the [one-argument rows investigation](../../research/investigations/one-argument-rows/DESIGN.md#the-rule) states the EFF-5 and EFF-1 change that removes the need for the merge.

Rejected:
- Listing the exhibited set as the suggested row: rejected because it can pair an entry with a write at or above its path, as the counter example `reads(stats.count), writes(stats.count)` did, which EFF-1 refuses at the declaration. This replaces the node's rejected alternative of the same name, whose reason also cited a whole-parameter read beside a write below it, which EFF-5 no longer refuses.
- Merging entries of one parameter into one `writes` of their common path: rejected because the merged write can cover storage the body never writes, which widens every caller's kills and reference invalidations beyond what the body does, and because whether two indexed positions select one element depends on the values a call supplies, which EFF-5 asks the call site to prove. This replaces the node's rejected alternative "Merging two indexed positions of one parameter into a whole-parameter write", extending it to every merge.
