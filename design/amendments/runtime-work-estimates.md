Decision: Price an independent range's iterations using available captured counted-loop extents and helper-argument lengths, with saturating scheduling arithmetic and the previous static estimate for unavailable work, preserving the runtime work unit and chunk cap, the sequential world, and all acceptance and proof behavior, because a fixed inner-loop factor assigns the same price to blocks of very different sizes and leaves the measured prefix and histogram blocks unoffered while restricting wide stencil to a few chunks, instead of lowering the global runtime work floor, asking writers for grain annotations, or timing source work to adapt its price. This proposed addition remains unselected: the [first runtime-extent trial](../../research/investigations/compute-model/DESIGN.md#runtime-extent-trial-result) improves the primary kernels but fails the protected chain-pull case and exposes substantial CPU tradeoffs, so captured extents alone do not establish the replacement policy.
