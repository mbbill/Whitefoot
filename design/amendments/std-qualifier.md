Decision: The fixed pkg qualifier denotes the source's owning selected root, with the primary root located by the sole graph, and the fixed std qualifier denotes the standard library package shipped with the toolchain, whose modules a graph row lists beside its own package's modules and a source bundle may name without a row, because one package-oriented spelling works for applications and libraries while library-internal paths must survive an importer's choice of dependency name, and a library shipped with the compiler needs neither a binding nor a version of its own, instead of user-selected app/lib/project prefixes, interpreting every imported source against the primary root, searching for another graph, a graph-level binding for the standard library or an implicit standard prelude; binding other external dependencies and composing third-party libraries remain deferred beyond the standard library.

Rejected:
- Replaced decision beginning "The fixed pkg qualifier denotes the source's owning selected root": rejected because deferring all library composition left the host declarations injected into every check, where they cost 36 to 62 percent of a check's instructions ([library-modules E1](../../research/investigations/library-modules/DESIGN.md#measurement-e1-what-the-host-rows-cost-every-check)), and left reusable libraries reachable only as source text concatenated into a bundle.
- Every standard library declaration visible without a name in every module: rejected because it bypasses the graph's single dependency authority and the refusal of glob imports, and makes every check pay for declarations it never names.
- A general external-package binding in the graph for the standard library now: rejected because its identity, version and renaming rules answer third-party libraries the owner has not selected, while a library shipped with the compiler needs none of them; a later binding form can treat std as one pre-bound name.
