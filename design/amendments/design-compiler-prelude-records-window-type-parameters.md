Node: compiler/prelude-records

Decision: A compiler-owned window type parameter is recognized by two facts together, the parameter spelling `W` or `X` and the prelude origin of the declaration that introduces it, because [OP-10] names the parameter by exactly those two spellings and states in the same breath that no source declaration can write such a parameter, so the spelling alone would capture a writer's own `fn helper<W>(...)` and the origin alone would capture the element parameter `T` of the same records, instead of marking the parameter in the prelude text with a modifier the grammar does not have.

Decision: A [PRE-1] row whose window type parameter is still unsupplied has no symbolic instance judgment: its `requires` and `ensures` clauses are checked only at the concrete instances an operand fixes, while every other generic row, prelude or source, keeps its symbolic judgment, because [OP-10] states that such a parameter is supplied by the operand and never written, so there is no call whose meaning the unsubstituted parameter describes, and the unsubstituted parameter is not one of [MSR-1]'s measured types, which makes `deref(window).cap` in `place_back` a measure of a type the table has no row for and stops every compilation in the prelude, instead of admitting a measure on the unsubstituted parameter, which would need a measure-table row for a type that names no storage and would give `head` an answer for a `Slots` the table denies it.

Rejected:
- Adding a measured identity for the unsubstituted window parameter so the symbolic instance can be judged: rejected because [MSR-1]'s table keys are the written measured rows and each cell is exactly one of exact, bounded or absent, and a key standing for four shapes at once would have to answer `head` both absent and bounded, which is not a cell the table can hold.
- Rewriting the prelude's window records to name concrete shapes instead of a window parameter: rejected because the records are the specification's own text, one record per operation across every admitted shape, and replacing one record with four would change what [OP-10] declares rather than how the compiler reads it.
