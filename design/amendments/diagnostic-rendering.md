Node: compiler/diagnostic-rendering

Decision: A compiler stop is printed as one record of labeled fields: the rule, a kind name, the category and stage, the location as `file:line:column` with its byte range and the source line marked under the span, then every payload field under its own name; the default text form opens with a `file:line:column: error[RULE]: Kind` summary line followed by one `label: value` line per field, and `--diagnostic-format json` prints the same field names as one JSON object per line, because the main reader is an agent in a compile-fix loop that reads text directly, recognizes that summary shape, and must compare the quoted source and prose unescaped, while exact tooling needs fields a list separator cannot split ambiguously, and the [readable-diagnostics investigation](../../research/investigations/readable-diagnostics/DESIGN.md#default-format-text-with-json-on-request) cites a writer trial in which rejections carrying named payload fields gave the construct and the fix while those carrying only `Debug` coordinates cost compile rounds, instead of the stage payload's `Debug` text, JSON by default, or hand-written prose per kind. Stops that are not source rejections keep their stage value's `Debug` text as one `payload` field, and the driver's own invocation, output and toolchain stops keep one sentence in text; the JSON form renders the current record and is not a stable artifact format.

Decision: Each payload type lists its fields once, in the driver's diagnostic module, by exhaustive destructuring that takes each label from the field name and each kind from the variant name, and a node a payload names travels with its coordinate from the checker that holds the tree, because a field added to a payload then fails to compile until it is listed, a label cannot drift from its field, and no child-ordinal path, source ordinal or byte offset can reach the default output, instead of rendering from parsed `Debug` text, a serialization dependency, or keeping the resolved tree alive in the driver after a rejection.

Rejected:
- JSON as the default rendering: rejected because it escapes the source lines and prose the agent compares with its program, drops the marker, and costs more tokens per record, while the text form's labeled lines already parse by label.
- Parsing each payload's derived `Debug` output into a generic tree: rejected because `Debug` is not a stable format, three hand-written implementations already diverge from the derived shape, and a parsed node path still cannot be resolved without the tree.
- A serialization derive from an external crate: rejected because the compiler is one dependency-free crate built offline, and a proc-macro dependency set is a larger change than the field listing it replaces.
- Hand-written prose per rejection kind: rejected because about a hundred maintained sentences would restate fields and mechanical fixes the payload already carries exactly.
- Returning the resolved unit with every semantic failure so the driver can resolve node paths: rejected because it changes every failure variant and its test patterns, while the checker already holds the tree at the few sites that build a payload naming another node.
