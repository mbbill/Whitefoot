Node: compiler/storage-representation

Decision: Whether a compilation unit carries `program no_heap;` is computed once in the checker by scanning the unit's items for a `heap_decl`, and [STOR-8]'s two refusals -- naming `Box` or a runtime-capacity shape at a written `type`, and calling one of `box_new`, `box_array_filled`, `box_slots_new`, `box_ring_new` and `grow` at a complete `call` -- are made from that one flag, because [GRAM-2]'s placement rule for the declaration is already resolution's admission, so a `heap_decl` reaching the checker at all is the admitted first-item one and the checker needs no second placement judgment, while both refusals are about types and calls the checker alone resolves, instead of exporting the fact from resolution, which would add a unit-level field to the resolution outcome that only the checker reads.

Decision: Both refusals skip every node whose source file is one of the fixed [PRE-1] prelude records, because the prelude declares `Box` and the runtime-capacity shapes in its own allocating rows and those declarations are part of every unit, so a refusal that did not distinguish them would reject every no-heap program at the prelude rather than at the writer's text, instead of excluding the prelude from the unit, which [PRE-1] forbids, or moving the refusal to a later pass that sees only source declarations.

Rejected:
- Refusing the allocating rows by their declared effect row instead of by name: rejected because [STOR-8] gives allocation no effect entry, so the row carries nothing to test; the five names are what the rule itself enumerates.
