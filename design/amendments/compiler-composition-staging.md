Decision: Module verdicts, which form, resolve and check one module's records against its dependencies' interfaces and record the graph facts and the declarations of other interfaces their checks read, and function proof analyses, which record their canonical inputs as receipts, are deterministic dependency-recording queries over stable resolved module/declaration identities, while in this first stage an entry's composition forms, resolves, type-checks, instantiates, summarizes and lowers its whole closure again whenever that closure's records change, a check reading implementation records by their bytes and interface records by their declarations and a build reading every record by its bytes, reusing unchanged receipts and fragment objects, and gains persistent formation, lookup, instance, summary and lowering queries of its own once a one-body edit build of a program a current experiment builds exceeds one second, as the [composition staging](../../research/investigations/modular-compilation/DESIGN.md#composition-staging) plans, because graph or alias spelling edits can preserve identities and claims while changing the selected package input identity, deleting an edge, retargeting an alias or introducing a collision can invalidate a use without changing target APIs, while a composition rerun keeps current edit builds within that budget and finer composition queries need module-level checked results the whole-closure checker does not yet retain, instead of row positions, textual pkg-qualified paths, alias spellings or whole alias-table/root/interface/graph/module hashes selecting whether a module verdict, a proof analysis or an object is reused, or finer composition queries built before an edit-latency measurement calls for them.

Rejected:
- Replaced first decision beginning "Interface/source formation, path/directory inventories": rejected because it made formation, lookup, instances, summaries and lowering inside every composition persistent queries from the first stage, which needs module build units, an instance-only check mode and fact-based entry checks over a checker that retains no module-level checked result, a larger change than any current experiment's edit latency calls for; the staged decision keeps its stable identities, still refuses whole-hash keys for module verdicts, proof analyses and objects, accepts whole-closure keys only for rerunning a composition as a whole, and reopens the finer composition queries by its measurement.
