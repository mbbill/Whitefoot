either pushed to the working branch, measured and recorded in the repository,
or decided by the owner in the discussions of 2026-09-10 to 2026-09-13; the
open items are marked as open. Nothing here is a specification amendment.
The owner decides; this file records.

Working line: [PR #30](https://github.com/mbbill/Whitefoot/pull/30) (draft),
branch `codex/container-foundation-research`, head `c4967e7c`, last merged
`main` at `8909feb1`. At this snapshot the branch was behind `main` by PR #51
(`ci/gate-placement`) and later merges, and merging `main` produced two
content conflicts, in `research/experiments/compute-bench/Makefile` and

## 1. The goal and the owner's rulings

The goal, in the owner's words (2026-09-10, translated): a high-performance
container interface that lets upper layers describe the container capability
systems programming needs. Whitefoot has no pointers and no unsafe, so the
language must provide a base API flexible enough for users to compose the
containers they need, and those composed containers must reach very high
performance. Avoid the situation where a container can only do one thing and
using it forces a low performance ceiling.

Rulings the owner made or reaffirmed during this line:

- Performance first, then expressiveness; proved safety remains a hard
  constraint. Containers are not forced onto the heap. Container and backing
  storage are separate concerns.
- The language stays simple and function-centric. It is not a Rust clone;
  no trait system, no method dispatch, minimal new mechanisms. Verbosity is
  acceptable because AI writes the code; synchronized duplication and
  error-prone forms are not.
- Function interfaces are fixed and determinate: the effect row is visible in
  the signature and a program can be split across modules without inferring
  rows from bodies.
- Language decisions are the owner's. An agent proposes options with one
  recommendation, records the alternatives and their reasons, and stops for
  the ruling. Text that presumes a ruling is retracted.
- The absolute rule (2026-09-12): anything that crosses the host boundary is,
  inside the language, an ordinary value or an ordinary function. No rule,
  table, summary, kind, diagnostic, grammar production, checker path, or
  lowering hook may exist because something is external. Every such thing is
  a violation and is removed. The constitution's section "External
  interaction through ordinary objects" is unconditional; C2 deleted its
  departure clause.

## 3. The stages: what was done, why, and the data

### D1: foundation (2615338)

The foundation research selected the container/backing separation and the
rule that a container is a source-level composition over ordinary storage
(inline run, `Box`, arena, heap) rather than a compiler-known layout. Inline
run helper transfer costs were measured to fix the comparison criterion used
by every later stage: a WF helper is compared with a C helper of the same
boundary shape (retained and inlined), never with a whole-program C control.

### D2: owning sparse growth (b2a50dd, d45ad27)

An owning open-addressing map with growth, refusal paths and resource-owning
slots was written over ordinary values, with 1,808 matched executions per
lowering mode, 1,504 injected allocation refusals and 2,736 resource releases
checked by an observer. Retained-helper medians at capacity 4,096 (ns):

| Operation | WF | C interleaved | C split |
| --- | ---: | ---: | ---: |
| lookup | 2.917 | 2.774 | 2.785 |
| insert | 9.249 | 2.897 | 3.075 |
| rehash (one doubling) | 14807 | 13641 | 10130 |

Insert was 3.2 times C. The attribution found the cause in the language, not
the algorithm: a mutation helper had to receive the run by value and return
it (BLK-4 refused `&uniq` parameters that reach a run through
`UniqueParameterReachesContainer`), so every insert paid a run round trip.
The recorded alternative, a compiler-known projected layout, was rejected:
the measurements did not justify a mechanism.

### D5: exclusive two-state contracts, specification v0.56 (245f932, 415ff30, 5942341, 85fce15)

Mutation helpers take the run as `&uniq` and state both states in the
contract: `ensures len_of(deref(values)) == len_of(deref(entry(values))) + 1_u64`,
where `entry(...)` applied to the `&uniq` parameter name denotes the value at
entry. The kernel rows `place_back(vector: &uniq V, value: own T)` and
`take_back(vector: &uniq V) -> value: own T` already carried this mechanism;
the amendment made it available to source functions and removed the BLK-4
refusal outright. Calls kill overlapping facts by the projected effect row,
then publish the verified exit relations. The owner chose the `entry(...)`
spelling over the record notation `len_of(store at the call)` and ruled that
`entry` wraps the parameter name, not the whole measure.

interleaved):

### D6 and D6b: behavior parameterization research (0a7167f, cd3e946)

A map needs a hash and an equality supplied by the user, and a heap needs an
ordering. The first proposal reused older `contract`/`conform` declarations
(a trait-shaped protocol) plus an `effects` splice that forwarded the
callee's row into the instantiating function's row. The owner rejected it:
the language is not to grow a trait system; merged rows are ugly; a row that
depends on instantiation makes the interface indeterminate and breaks module
splitting. The comparison study (D6b, `BEHAVIOR.md`) then compared
function-kind generic parameters against the protocol form and against a
struct-of-functions form, on three witnesses
(`behavior-baseline.wf`, `behavior-nominal.wf`, `behavior-expanded.wf`).
Forwarding cost was shown identical in every form. The owner selected named
function groups: a `formal` names a group of function-kind parameters with
their rows and contracts; an `actual` names a group of concrete functions
that satisfies one formal; the formal's row is authoritative and the actual's
row must be covered path-prefix-wise; contracts must be structurally equal.
Calls are written `Key::hash(env: env, key: key)` (the owner's spelling:
hash is a bare function in the shape, not a method) and instantiation is
`find::<SeedKey>`.

### D7: static behavior parameters, specification v0.57 (6614c03, a0e1dbe, 2004372)

Implemented as one mechanism: `formal Key<K: linear, E: linear> { fn hash(env: &E, key: &K) -> hash: own u64 reads(env, key); ... }`
and `actual SeedKey : Key<u64, Seed> { hash = seed_hash; equal = seed_equal; }`,
monomorphized to direct calls. `contract`, `conform` and `law` were removed;
`Int` and `Float` became built-in bounds; the formal header carries no region
parameters (members carry their own, so an actual may capture a brand). The
FN-6 cycle rule was extended to function-kind parameters. Blockers resolved
on the way: the formal header region question and an allocation-fit
predicate for run element types (`2004372`).

### The diagnosis: identity-based effects exist only to follow a tag

The v0.54 model attributed effects to value identity: a read of
`deref(slot).n` after `install(slot: &uniq deref(slot), fresh: move fresh)`
was a read of `fresh`, because the callee's routing summary said the value in
`slot` came from `fresh`. Compiled evidence with the branch compiler
(2026-09-12): the caller was required to declare
`reads(slot.n, fresh.n), writes(slot.n)`, and the callee `install` itself
needed only `reads(slot.n), writes(slot.n)`. ENT-5 never consumes a read
entry (kills come from projected writes on storage), and PAR-1 already puts
a consumed `own` argument in the written footprint, so the extra entry
changed no verdict anywhere.

What the machinery did buy was resource release attribution. With
`struct Holder { file: ReadFile; }`, `pack(file: own ReadFile) -> own Holder`
is `pure`, and `drop_it(file: own ReadFile)` that binds `pack(...)` and
returns was required to declare `writes(file)` (diagnostic
`ReleaseEffectMismatch { owner: "holder" }`); the same for a local `Slot`
enum filled through `&uniq` by `install_file` (`writes(fresh)` required,
owner `slot`). Both requirements come from one table row in the
specification: `ReadFile | at most one native close attempt | writes(owner)`,
with `close_read(file: own ReadFile) ... writes(file)`. The close effect was
attributed to the file object itself, so the compiler had to know which
object sat in every place at every point: through moves (EFF-2 identity),
through calls (v0.37's result-state routing summary), through `&uniq`
referents (v0.54), and it could not through a formal call (the D8 blocker).
`state_origins.rs` (1,235 lines) and `result_state_origin.rs` (1,382 lines)
existed for that one tag. The owner's ruling: the tag is the violation; a
file is an ordinary object and the host state it changes is a value passed
as a parameter.

## 4. The language model the branch carries now (v0.55)

- Effects are rows over parameter-rooted places. A callee's row projects
  onto the caller's actual places; a value moved into local storage adds no
  effect root for its history. Facts die at projected writes on storage and
  are republished by verified `ensures`.
- Mutation through `&uniq` states entry and exit with `entry(...)`; kernel
  and source helpers share the form.
- Behavior comes in through `formal`/`actual` groups, monomorphized to direct
  calls, with authoritative formal rows and structurally equal contracts.
- Everything from the host is an ordinary prelude declaration: opaque
  nominals (`linear` where the owner selected), public structs, enums, and
  `fn_sig`s with ordinary rows and contracts. Host state that an operation
  changes is a parameter (`&uniq HandleFactory`, `&uniq ReadFile`, ...).
  Closing is an ordinary consuming call. Dropping an affine opaque value does
  nothing; a `linear` one must be consumed on every exit.
- The entry is an ordinary function; the build calls it with `Inputs` and
  `Heap` arguments and proves its requirements.
- One callable ABI for WF and linked bodies; loans last until return; the
  native completion engines are implementation detail with no source
  permission. PAR-1 and PAR-2 remain, formed from rows and loans only.
- The design tree under `design/` is the decision record. The live tree
  still records the pre-C2 system interface; the reconciliation is the
  unapplied `TREE.patch` (see open items).

## 7. How this line is directed

- One goal per stage. A goal states the objective, acceptance, constraints
  and the three stop conditions; the method is the agent's. The agent's goal
  text is fed back to it whenever it stops, so a goal must cover one stage.
- Language decisions stop for the owner: options, one recommendation,
  alternatives with reasons; nothing written as accepted before the ruling.
  Rulings enter `design/` only through the design-tree skill; an agent's own
  decision is an amendment until ruled.
- Every stage pushes to PR #30 and refreshes the description with actual
  validation results (CLAUDE.md). Verdicts are never weakened to get green;
  an impossible-case branch added to satisfy the checker is a defect; a
  compiler gap is not a source rejection.
- Evidence is cited by rule ID, case, or measured result; RESULTS.md records
  the criterion before a measurement is used to choose.
- Tooling: the GitHub connector token lacks `actions: write` and
  `pull_requests: write`, so re-runs and description edits are done by the
  owner; the corpus jobs occasionally exceed the 8-minute workflow limit and
  have passed on one retry each time.
- Reports to the owner in Chinese, facts first.
