# x0 interaction matrix: rows 13-24

This batch applies the frozen R1-R16 rule sheet to axes 13 through 24. Each
status concerns the demonstrated interaction only.

Unless a cell overrides them, `a` and `b` are distinct live full arrays of
length `N`, `0 <= n <= N`, all shown indices and ranges have discharged bounds,
and `c` is an evaluated Boolean. `observe(p)` (also written `read_a` or
`read_b`) has body `return read(p)` and a verified `reads(P)` row.
`take_put(p)` has body `let x = take(p); put(p, x)` and a verified `writes(P)`
row with full entry and exit. `write_one(p)` is the direct wrapper
`write(p, 1)`. `fill(v)` requires a live, full, bounded view and has the body
`for k in 0..len(v) invariant { Live(P), Full(P[0..len(v)]), 0 <= k <= len(v) }
{ write(loc(v[k]), 0) }`; writes preserve fullness, R13 supplies each proved
bound, and R10 checks one symbolic iteration. Its verified row is
`writes(P[0..len(v)])`. Aliases may exist; cells requesting iteration overlap
also require R15's proved adjacent-range formation and complete loan/effect
conflict checks. The helper supplies no lifetime-long exclusion or broader
PAR-2 permission.

## Row 13 — arrays and ranges

### 13-13: captured array elements remain parts of one backing

```text
slot a: [Int; 4] = [1, 2, 3, 4]
let i = 1
let p = loc(a[i]); take(p); put(p, 9)
```

**Result: D.** **Reason:** R13 uses the captured index and proved bound to select one element of `a`; R4 preserves that element's live-but-empty state between `take` and `put`. **Boundary:** another locator to `a[1]` sees the same hole, while `a[2]` remains full. **Cost:** proof facts scale with selected parts, without occupancy bits. **Dependencies:** R1, R4, R8, R13.

### 13-14: disjoint payload ranges may share provider metadata

```text
let x = provider_alloc(pool, 4)  // effects meta(pool), payload(X)
let y = provider_alloc(pool, 4)  // effects meta(pool), payload(Y)
write(loc(x[0]), 1); write(loc(y[0]), 2)
```

**Result: U.** **Reason:** the written provider primitive promises fresh X/Y payloads and shared metadata effects, but R1 only defines ordinary `alloc`; no frozen formation/accounting rule verifies this provider contract. **Boundary:** conditional on such a verified primitive, metadata writes deny allocator overlap while payload writes separate. **Cost:** provider representation and dependency accounting remain unstated. **Dependencies:** R1, R12-R14 and provider gap.

### 13-15: a range view needs a checked container relation

```text
fn slice<C>(c: &C, lo: Int, hi: Int) -> View<P, Int>
    requires Repr(C, P), 0 <= lo <= hi <= length(P)
```

**Result: U.** **Reason:** R13 can check bounds once `Repr(C,P)` is available, but x0 supplies no general predicate definition or fold/unfold rule for establishing that private container relation. **Boundary:** the analogous direct fixed-array view is derivable. **Cost:** the missing facility affects checker/writer proof work, not view runtime layout. **Dependencies:** axis 15 and the predicate-rule gap.

### 13-16: a guarded index preserves target and state alternatives

```text
let i = if c { 0 } else { 1 }
let p = loc(a[i])
if c { write(loc(a[0]), 7); read(p) }
```

**Result: D.** **Reason:** R9 retains `(c,i=0,p=a[0])` and `(!c,i=1,p=a[1])`; the guarded arm selects the first, so R13 resolves the write and read to the same full element. **Boundary:** an unguarded access must succeed in both alternatives. **Cost:** finite guarded enumeration can grow exponentially. **Dependencies:** R8, R9, R13.

### 13-17: restored per-iteration holes need no dynamic family

```text
for i in 0..n
    invariant { Live(a), Full(a) }
{ let v = take(loc(a[i])); put(loc(a[i]), v) }
```

**Result: D.** **Reason:** whole-array fullness supplies the selected element's fullness, and R4 restores it before the backedge; R10 carries one fixed-object invariant, including zero iterations. No per-element state survives. **Boundary:** retaining distinct holes or duties for earlier indices would require the missing quantified-family rules. **Cost:** one symbolic iteration plus ordinary bounds proofs suffices. **Dependencies:** R4, R10, R13.

### 13-18: a range contract substitutes the caller's captured backing

```text
fn fill2<P>(v: View<P, Int>)
    requires len(v) == 2, Full(P[0..2])
    accesses writes(P[0..2])
{ write(loc(v[0]), 0); write(loc(v[1]), 0) }
let w = view(a, 1, 3)
fill2(w)
```

**Result: D.** **Reason:** the shown two-write body verifies its exact range row; R11 then substitutes P with A and R12 projects writes to `a[1..3]`. **Boundary:** the contract neither implies fresh storage nor authorizes release of A, and a body touching a third element would fail verification. **Cost:** direct substitution retains two target facts. **Dependencies:** R11-R13, R16.

### 13-19: generic distinct roots do not prove disjoint element access

```text
fn f<P,Q>(p: Loc<P, Int>, q: Loc<Q, Int>) {
    write(p, 1); write(q, 2)
}
```

**Result: D.** **Reason:** R11 checks the body for aliased actuals because `P` and `Q` are merely parameters. Sequential writes remain defined and the second wins when equal. **Boundary:** a caller seeking independence must establish separation explicitly. **Cost:** conservative abstraction loses optimization but adds no runtime check. **Dependencies:** R11, R13, R14, R16.

### 13-20: adjacent range separation uses the fixed numeric family

```text
for i in 0..chunks {
    let v = view(a, s*i+b, s*i+b+s)
    fill(v)
}
```

**Result: D.** **Reason:** R15 admits the exact adjacent-range family when bounds, `0 <= s`, and `0 <= b` are already derived by the fixed arithmetic machinery. **Boundary:** nonlinear or unavailable endpoint images deny loop overlap without rejecting sequential execution. **Cost:** retained affine facts increase checker state only. **Dependencies:** R13, R15 and current PAR-2.

### 13-21: an element hole is visible in the whole-range effect

```text
fn rotate<P>(v: View<P, Int>)
    requires 0 < len(v), Full(P[0])
    accesses reads(P[0..len(v)]), writes(P[0..len(v)])
    events take(P[0], content -> x), put(P[0], x -> content) {
    let x = take(loc(v[0])); put(loc(v[0]), x)
```

**Result: D.** **Reason:** the explanatory `events` line records R12's required intermediate Empty/Full transitions and both directions of content transfer in addition to reads/writes; it is contract content, not proposed syntax. **Boundary:** omitting either events or the length/fullness premises makes the summary incomplete. **Cost:** checker event records erase without a runtime state flag. **Dependencies:** R3, R4, R12, R13.

### 13-22: disjoint subrange calls may overlap

```text

request_overlap(fill(l), fill(r))
```

**Result: D.** **Reason:** proved bounds and structural half-open separation make the projected whole-call writes noninterfering under R14. **Boundary:** unknown endpoints make the overlap request fail, while the two calls may still execute sequentially. **Cost:** precise range effects preserve parallel opportunity at proof-table cost. **Dependencies:** R11-R14 and PAR-1.

### 13-23: same affine map preserves current loop overlap

```text
for i in 0..n { a[2*i+1] = a[2*i+1] +wrap 1 }
```

**Result: D.** **Reason:** R15's nonzero affine map proves distinct iterations select distinct elements, and the read uses the identical map as the write. Source-order within each iteration is preserved. **Boundary:** reading `a[2*i]` beside this write is a different map and denies permission. **Cost:** a deliberately narrow family sacrifices parallel cases for deterministic checking. **Dependencies:** R13, R15, PAR-2.

### 13-24: range proofs lower without uniqueness claims

```text

fill(v)
```

**Result: U.** **Reason:** R16 fixes erasure and forbids unconditional pointer-wide `noalias`, but the complete physical lowering and access-scoped metadata semantics for a proved subrange are an explicit gap. **Boundary:** ordinary offset/length fields are allowed and sequential executable lowering is still expected. **Cost:** missed metadata can lose optimization; unsound metadata could miscompile. **Dependencies:** R13, R16 and lowering gap.

## Row 14 — providers and shared management

### 14-14: provider release waits for dependent allocations

```text
let pool = open_provider()
let a = provider_alloc(pool, 8)
release(a); close_provider(pool)
```

**Result: U.** **Reason:** x0 requires dependent allocations to block provider ending, but R1-R16 do not supply a general resource-family rule that derives and consumes the provider's dependent-allocation count or set. **Boundary:** a bespoke fixed contract with one explicit child duty can be checked directly. **Cost:** no runtime generation map may be smuggled in as proof state. **Dependencies:** R6, R12 and family-rule gap.

### 14-15: container allocation exposes provider effects


**Result: U.** **Reason:** the effect row can expose management access, but verifying `push` against a general container representation requires missing predicate fold/unfold and allocation-family rules. **Boundary:** a fixed one-buffer record with explicit fields and duties is derivable. **Cost:** precise contracts burden library authors while avoiding hidden allocator synchronization. **Dependencies:** R11, R12, axis 15 gaps.

### 14-16: branch-specific provider duties stay guarded

```text
let a = if c { provider_alloc(p, 1) } else { provider_alloc(q, 1) }
if c { release_with(p, a) } else { release_with(q, a) }
```

**Result: D.** **Reason:** R9 keeps the allocation identity, provider association, and disposal duty together under the captured guard; each source arm consumes its matching duty. **Boundary:** reassigning `c` later does not refine the old choice. **Cost:** alternative states retain separate management effects and duties. **Dependencies:** R1, R6, R9, R12.

### 14-17: loop-created provider children need symbolic duties

```text

    invariant { Children(pool, owned_list) }
{ owned_list.push(provider_alloc(pool, 1)) }
```

**Result: U.** **Reason:** an unbounded runtime number of fresh allocation identities and duties must be related to the provider across the backedge. R10 names this as a missing general dynamic-family rule. **Boundary:** a loop reusing one already allocated child can carry its single duty. **Cost:** any runtime count would be program data, not an erased proof substitute. **Dependencies:** R10, R12, family gap.

### 14-18: provider effects participate in contract substitution

```text

    accesses writes(S), allocates(S)
request_overlap(make(pool), make(pool))
```

**Result: D.** **Reason:** R11 substitutes both actuals to the same management target; R12 includes allocation metadata, so R14 denies overlap on write/write conflict. **Boundary:** distinct proved provider targets may permit overlap if payload duties are also independent. **Cost:** accurate indirect rows may serialize allocator-heavy code. **Dependencies:** R11, R12, R14.

### 14-19: passed allocators need independently verified effects

```text
fn twice<F,S>(f: F, p: Loc<S, Meta>)
    where F: fn(Loc<S, Meta>) accesses writes(S), allocates(S)
{ f(p); f(p) }
```

**Result: D.** **Reason:** R11 checks the symbolic body using the written function contract and each concrete function argument against the identical contract. Calls remain source ordered. **Boundary:** accepting a purportedly narrower generic refinement lacks rules and is unresolved. **Cost:** complete higher-order effects restrict interchangeable callbacks. **Dependencies:** R11, R12.

### 14-20: provider dependency families exceed fixed propagation

```text

```

**Result: U.** **Reason:** the written `use` cannot create its own theorem; x0 has not defined introduction, elimination, or finite certificate checking for `ProviderOwns` over a dynamic set. **Boundary:** direct transfer of one named child's duty uses R1-R6. **Cost:** a future certificate language must terminate and avoid runtime bookkeeping. **Dependencies:** R10, R20 gap.

### 14-21: management state is part of allocation effects

```text
fn alloc_one<S>(p: Loc<S, Meta>) -> Owner<A>
    accesses writes(S), allocates(S)
{ let n = read(p); write(p, n +wrap 1); return alloc(0) }
```

**Result: U.** **Reason:** the body derives a fresh ordinary allocation and metadata read/write, but no frozen rule relates that allocation's duty or lifetime to provider S; even its row omits the shown read. **Boundary:** R12 can reject this incomplete contract, but cannot manufacture provider dependency accounting. **Cost:** the missing formation rule blocks provider abstraction. **Dependencies:** R1, R8, R12 and provider gap.

### 14-22: shared provider writes deny call overlap

```text

                provider_alloc(pool, 8))
```

**Result: D.** **Reason:** payload identities are fresh and disjoint, yet both executions write shared provider metadata; R14 therefore denies the overlap. **Boundary:** denial adds no lock and does not reject the sequential program. **Cost:** parallel allocation needs a provider contract that actually proves disjoint management accesses, not a hidden synchronized implementation. **Dependencies:** R12, R14.

### 14-23: provider traffic inside iterations blocks counted overlap

```text

```

**Result: D.** **Reason:** R15 incorporates whole-call effects, and each iteration writes the same provider metadata, so cross-iteration independence fails even if every payload is fresh and discharged locally. **Boundary:** source-order execution remains acceptable. **Cost:** this excludes common parallel allocation unless the provider exposes separable metadata. **Dependencies:** R12, R14, R15.

### 14-24: provider implementation is not erased proof metadata


**Result: U.** **Reason:** R16 forbids hiding a runtime allocation table, generation map, or synchronization behind ghost identities, while the allocation/provider implementation is explicitly outside the supplied rules. **Boundary:** inherited primitive contracts specify observable effects and duties. **Cost:** representation fields and synchronization must be stated and costed before x0 is complete. **Dependencies:** R12, R16 and provider-lowering gap.

## Row 15 — containers and library invariants

### 15-15: general container invariants lack fold and unfold

```text

invariant VecRep(self) { 0 <= len <= cap; Buffer(owner, cap) }
```

**Result: U.** **Reason:** the invariant has plausible concrete content, but R1-R16 define neither predicate ownership nor checked opening and closing. Treating `VecRep` as an axiom would hide liveness, bounds, and duties. **Boundary:** clients can use an explicitly expanded fixed record. **Cost:** representation abstraction remains unavailable until a finite rule is fixed. **Dependencies:** predicate-rule gap.

### 15-16: finite variants can carry explicit container states


**Result: D.** **Reason:** when constructors expose their concrete states, R9 preserves the variant, payload identity, and duty per guard; each arm discharges its represented case. **Boundary:** replacing these facts with an opaque `BufRep` returns to the missing predicate rules. **Cost:** explicit variants expose representation and may enlarge guarded state. **Dependencies:** R6, R9, R12.

### 15-17: mutating containers across loops needs a quantified invariant

```text

    invariant { VecRep(v), initialized(v, 0..i) }
```

**Result: U.** **Reason:** both `VecRep` opening and the runtime-sized initialized-prefix family lack rules. R10 cannot prove the backedge from a merely written invariant. **Boundary:** fixed arrays with every element fact listed are derivable. **Cost:** writer certificates may be verbose unless the future family calculus composes ranges. **Dependencies:** R10, R13 and predicate/family gaps.

### 15-18: abstract container methods need relational contracts

**Result: U.** **Reason:** the nonempty decomposition states exactly which element leaves, and the result receives h plus any non-Copy duty; however, no rule unfolds `SeqRep` to justify that transfer or closes it over `rest`. **Boundary:** a concrete one-slot record can use direct `take` and return `Some(h)`. **Cost:** abstraction is blocked at checking. **Dependencies:** R4, R11 and predicate gap.

### 15-19: higher-order container traversal lacks contract refinement

**Result: U.** **Reason:** direct identical callback contracts are supported, but a useful generic `map` also needs a container element-family invariant and often refinement of callback effects over each selected element. Both general mechanisms are gaps. **Boundary:** mapping a fixed tuple with explicitly named calls is derivable. **Cost:** rejecting abstraction loses reuse and parallel opportunity. **Dependencies:** R11, R13, predicate/refinement gaps.

### 15-20: an explicit invariant step needs a defined predicate calculus

**Result: U.** **Reason:** `use` is only notation for a checked finite step; no frozen rule defines these predicate transformations or their resource accounting. **Boundary:** direct facts such as `Live(A)` and `Full(A[0])` can be consumed under R1-R13. **Cost:** checker determinism requires a bounded, specification-fixed step language. **Dependencies:** R20 and predicate gap.

### 15-21: container effects must expose representation access

**Result: D.** **Reason:** for a concrete record implementation, R12 checks the body against its actual field read; merely returning a copy does not erase access. **Boundary:** an opaque container must connect its abstract effect name to representation targets through a checked relation, which remains unresolved generally. **Cost:** precise read rows preserve read/read overlap. **Dependencies:** R3, R11, R12.

### 15-22: opaque container calls cannot claim overlap by assertion


**Result: D.** **Reason:** once verified rows project both calls to overlapping backing or metadata, the write/read conflict denies overlap. If representation projection is unavailable, R14 treats the target as unresolved and still denies permission. **Boundary:** the sequential calls remain admissible if their ordinary preconditions hold. **Cost:** abstraction may hide parallelism until relations become provable. **Dependencies:** R11, R12, R14.

### 15-23: disjoint container shards need more than distinct descriptors


**Result: U.** **Reason:** descriptors at distinct indices do not alone prove that their hidden backing allocations or provider metadata are disjoint. A quantified representation family connecting every shard to distinct targets is missing. **Boundary:** direct affine writes into one known array remain admitted by R15. **Cost:** conservative denial loses data parallelism without affecting sequential semantics. **Dependencies:** R13-R15 and family/predicate gaps.

### 15-24: container proof erasure leaves concrete descriptors

**Result: U.** **Reason:** R16 says proofs erase and ordinary owner/view fields remain, but complete lowering of an abstract invariant into scoped alias and bounds facts is unspecified. **Boundary:** it must not attach pointer-wide uniqueness to `p`, and required length/capacity fields are runtime data. **Cost:** representation and optimizer consequences cannot yet be compared. **Dependencies:** predicate and lowering gaps.

## Row 16 — branch joins

### 16-16: guarded union retains correlated duties

```text

```

**Result: D.** **Reason:** R9 preserves each fresh identity and its duty under the evaluated condition, rather than intersecting duties away. ### 16-17: a loop head may carry a finite guarded state

The stated substitution swaps the alternatives correctly. **Boundary:** exit cleanup must handle the actual final alternative in source control. **Cost:** finite case checking grows with guards. **Dependencies:** R4, R9, R10.

### 16-18: conditional actual targets substitute as alternatives

**Result: D.** **Reason:** R11 substitutes the guarded target union and checks `Live` and `Full` for both alternatives; the call reads only the selected target. **Boundary:** proof for `a` alone is insufficient. **Cost:** contract checking repeats across remaining alternatives, with one runtime indirect access already inherent in `p`. **Dependencies:** R2, R9, R11.

### 16-19: generic recursion preserves contract-level joins

### 16-20: Boolean guarded checking is fixed but numeric case proof is bounded

### 16-21: state effects publish a guarded exit relation


### 16-22: conditional disjointness must hold in every alternative

### 16-23: loop overlap cannot depend on a per-iteration unresolved branch

**Result: D.** **Reason:** both branches write the same admitted affine element `a[i]`, so each iteration's union stays within its own range and R15 proves cross-iteration separation. **Boundary:** choosing between `a[i]` and `a[i+1]` introduces different maps and denies permission. **Cost:** branch checking duplicates local proof work. **Dependencies:** R9, R13, R15.

### 16-24: erased branches retain ordinary runtime control


**Result: D.** **Reason:** ghost alternative identities erase, while the ordinary conditional and locator value remain sufficient to select the runtime address. R16 forbids turning branch-local separation into unconditional `noalias`. **Boundary:** only facts valid in the selected scope may become access-scoped metadata. **Cost:** no proof tag is emitted. **Dependencies:** R9, R16.

## Row 17 — loops and exits

### 17-17: one fixed resource can circulate through a loop

```text

    let x = take(loc(*a)); put(loc(*a), x)

```

**Result: D.** **Reason:** R10 checks entry and one backedge; R4 restores fullness and retains the same allocation duty. ### 17-18: early exits carry their actual resource state

**Result: D.** **Reason:** R10 checks the return edge separately: it consumes the duty before leaving, while the normal backedge preserves it and the loop continuation releases it once. **Boundary:** omitting the return-arm release leaves an undisposed obligation. **Cost:** exit-specific checking adds control-flow states, no runtime flags. **Dependencies:** R6, R7, R10.

### 17-19: recursive traversal needs a stable declared resource relation

### 17-20: dynamic allocation families need explicit certificate rules

```text
for i in 0..n invariant { owns_exactly(prefix, 0..i) } {
```

**Result: U.** **Reason:** x0 promises explicit finite proof steps for symbolic families, but R10 supplies no syntax or checking semantics for creating the next fresh member and proving the backedge. **Boundary:** statically unrolled two-allocation code follows R1 and R9. **Cost:** acceptance must remain terminating and machine-independent. **Dependencies:** R1, R10, R20 gap.

### 17-21: loop effects include intermediate holes and exits

```text
while c invariant { Full(A) } {
    let x = take(loc(*a)); use(x); put(loc(*a), x)
```

**Result: D.** **Reason:** the invariant establishes exit fullness, while R12 still records the body's take/put state changes and writes over A. An error exit between them would carry A empty and x's duty. **Boundary:** exit state does not summarize away whole-execution access. **Cost:** effect summaries are larger than postconditions. **Dependencies:** R4, R10, R12.

### 17-22: a call pair across uncertain loop iterations has no PAR-1 window

```text

```

**Result: D.** **Reason:** current call overlap applies to eligible statements of one block and preserves all intervening control; it does not overlap an unknown loop execution with its successor. R14 supplies no broader scheduling rule. **Boundary:** calls inside one iteration can be judged as an ordinary pair. **Cost:** restriction leaves inter-iteration pipelining unavailable. **Dependencies:** R10, R14, current PAR-1.

### 17-23: counted loops preserve admitted reductions

```text

for i in 0..n { set sum = sum +wrap a[i] }
```

**Result: D.** **Reason:** R15 admits the affine read and wrapping-add reduction; arbitrary recombination preserves the specified modular result. Zero iterations keeps the initial value. **Boundary:** checked addition and strict floating addition lack the fixed law and deny recombination. **Cost:** parallel scheduling is optional and unobservable. **Dependencies:** R10, R15, PAR-2.

### 17-24: loop proof state erases while source exits remain

```text

```

**Result: U.** **Reason:** R16 erases the invariant and identities, but complete lowering of established iteration-scoped alias facts and their optimizer metadata remains unspecified. **Boundary:** runtime binder, bounds, and source exit behavior remain ordinary program state. **Cost:** conservative lowering is executable but may miss vectorization. **Dependencies:** R10, R15, R16 and lowering gap.

## Row 18 — function contracts

### 18-18: equal actual targets combine access but not duties

```text

```

**Result: D.** **Reason:** R11 permits aliasing absent a separation precondition, and sequential writes compose. By contrast, two consumed-duty formals could not both bind A because R5 forbids duplicating a linear obligation. **Boundary:** contracts must state separation when their bodies require it. **Cost:** alias-polymorphic bodies may inhibit optimization. **Dependencies:** R5, R11, R12.

### 18-19: identical passed-function contracts are checkable

```text
fn apply<F,P>(f: F, p: Loc<P,Int>)
    where F: fn(Loc<P,Int>) accesses writes(P)
{ f(p) }
```

**Result: D.** **Reason:** R11 allows a symbolic identical function contract and checks each concrete callback independently before substitution. **Boundary:** variance or semantic refinement from a different contract is not defined and is unresolved. **Cost:** exact matching is predictable but rejects useful adapters. **Dependencies:** R11, R12.

### 18-20: a contract declaration is not body evidence

```text
fn bad<P>(p: Loc<P,Int>) accesses reads(P) {
    write(p, 1)
}
```

**Result: D.** **Reason:** R11 verifies every body and R12 observes the write, so the declaration is rejected rather than trusted. **Boundary:** proof steps can discharge premises but cannot relabel a write as a read. **Cost:** modular checking requires complete effects once per definition. **Dependencies:** R11, R12, R20.

### 18-21: access and exit state are independent contract dimensions

```text
fn peek_replace<P>(p: Loc<P,Int>) -> Int
    accesses writes(P) ensures Full(P)
{ let x = replace(p, 7); replace(p, x); return x }
```

**Result: D.** **Reason:** R4 restores the original full state, but R12 records intermediate writes for the whole execution. **Boundary:** the postcondition cannot justify a read-only effect or overlapping reader. **Cost:** separate summaries increase signature size and retain optimization-relevant truth. **Dependencies:** R4, R11, R12.

### 18-22: verified contract projection decides call overlap

```text
request_overlap(observe(loc(a)), observe(loc(a)))
```

**Result: D.** **Reason:** both verified calls project only reads of A, which R14 declares compatible; argument evaluation merely forms locators and does not read contents. **Boundary:** any hidden write, transfer, end, or conflicting loan in either complete row denies overlap. **Cost:** precise summaries enable optional concurrency without runtime tests. **Dependencies:** R2, R11, R12, R14.

### 18-23: helper effects preserve adjacent-range permission

```text
fn fill<P>(v: View<P,Int>) accesses writes(P[0..len(v)])
for i in 0..n { fill(view(a, 4*i, 4*i+4)) }
```

**Result: D.** **Reason:** R15 projects the helper's verified row onto each admitted adjacent assignment; identical range images are cross-iteration disjoint. **Boundary:** a whole-backing effect in `fill` denies permission even if its implementation happens to touch less. **Cost:** range-polymorphic contracts demand precise library annotations. **Dependencies:** R11-R15.

### 18-24: contracts can authorize scoped facts, not pointer-wide attributes

```text
fn bump<P>(p: Loc<P,Int>) accesses writes(P) { write(p, read(p)+wrap 1) }
bump(loc(a))
```

**Result: U.** **Reason:** contract checking establishes the call's scoped access, and R16 forbids unconditional locator uniqueness; however, complete rules mapping this proof to backend alias scopes are missing. **Boundary:** straightforward loads/stores remain lowerable without such metadata. **Cost:** conservative code generation may lose optimization. **Dependencies:** R11, R12, R16 and lowering gap.

## Row 19 — generics, recursion and function arguments

### 19-19: recursion uses declarations rather than expansion

```text
fn count<P>(p: Loc<P,Node>) -> Int
    requires TreeShape(P) { return 1 +wrap count(child(p)) }
```

**Result: U.** **Reason:** R11 supports recursive contract assumptions, but `TreeShape` unfolding and the child's hidden target packaging are missing. The call cannot be accepted by infinite expansion or by trusting the predicate name. **Boundary:** numeric recursion over Copy integers with a direct contract uses existing WF rules. **Cost:** abstraction awaits finite predicate certificates. **Dependencies:** R11 and predicate/existential gaps.

### 19-20: generic separation cannot be inferred from type names

```text
fn g<P,Q>(p: Loc<P,Int>, q: Loc<Q,Int>) {
    use separate(P,Q)
    write(p,1); write(q,2)
}
```

**Result: D.** **Reason:** R13 and R16 reject the invented step: distinct parameters provide no separation evidence. The body may still be accepted sequentially if it removes the false requirement. **Boundary:** a declared and caller-proved separation precondition can support the step by direct substitution. **Cost:** callers must carry real relational evidence. **Dependencies:** R11, R13, R16.

### 19-21: passed functions carry complete access and transfer rows

```text
fn use_twice<F,P>(f: F, p: Loc<P,T>)
    where F: fn(Loc<P,T>) transfers none accesses reads(P)
{ f(p); f(p) }
```

**Result: D.** **Reason:** the identical checked function contract proves neither invocation consumes P's duty or mutates its state, so sequential reuse is valid. **Boundary:** an unknown or incompletely represented indirect effect must invalidate conservatively. **Cost:** function values need compile-time contract identity; no runtime proof object follows. **Dependencies:** R11, R12.

### 19-22: indirect calls overlap only through verified summaries

```text
request_overlap(f(loc(a)), g(loc(b)))
// f and g are function parameters with checked read-only rows
```

**Result: D.** **Reason:** if their written function contracts project reads to proved-disjoint or even identical targets, R14 permits read/read overlap without expanding call trees. **Boundary:** missing effects or generic refinement cannot be guessed; unresolved targets deny permission. **Cost:** exact function contracts constrain higher-order APIs. **Dependencies:** R11, R12, R14.

### 19-23: generic callbacks in counted loops require per-element projection

```text
for i in 0..n { f(loc(a[i])) }
// F: fn<P>(Loc<P,Int>) accesses writes(P)
```

**Result: C.** **Reason:** R15 admits a direct affine `set_stmt`, but does not lift an arbitrary helper's element effect into that family. Rewrite the callback to accept a proved adjacent one-element view, or inline the set. **Boundary:** even that rewrite fails if the callback touches shared captured state. **Cost:** the restriction loses abstraction or requires view construction. **Dependencies:** R11, R12, R15.

### 19-24: erased target parameters do not imply runtime uniqueness

```text
fn id<P>(p: Loc<P,Int>) -> Loc<P,Int> { return p }
let q = id(loc(a))
```

**Result: D.** **Reason:** P erases, and the returned locator is the ordinary copied address representation; R2 preserves its captured target while R16 forbids uniqueness metadata. **Boundary:** layout may include declared locator fields only, never a proof identity or alias flag. **Cost:** zero proof-runtime overhead, conservative alias optimization. **Dependencies:** R2, R11, R16.

## Row 20 — proof mechanism

### 20-20: written steps cannot fill the family-rule gap

```text
invariant { owns_family(F, 0..n) }
use split_family(F, 0, n)
```

**Result: U.** **Reason:** x0 promises explicit finite certificates, but the frozen sheet intentionally omits the grammar, premises, and resource transformations of general family steps. A helper name is not a derivation. **Boundary:** fixed Boolean splitting and existing numeric families are defined. **Cost:** future rules must guarantee termination independent of time budgets. **Dependencies:** R9, R10 and family gap.

### 20-21: invalidation precedes publication of replacement facts

```text
write(loc(a), 2)
use old_fact_about_value_of_a
```

**Result: D.** **Reason:** R8 forgets mutable facts supported by A when the write occurs, and R12 publishes only verified exit facts afterward. The old fact cannot authorize the `use`. **Boundary:** proved separation can retain facts about B. **Cost:** dependency-indexed invalidation consumes checker memory but adds no runtime action. **Dependencies:** R8, R12, R20.

### 20-22: absent separation proof denies overlap deterministically

```text
request_overlap(write_one(p), write_one(q))
// no equality or separation relation between targets
```

**Result: D.** **Reason:** R14 treats possible write/write conflict as denial; R20 starts no unbounded alias search and inserts no runtime guard. **Boundary:** this is an optimization verdict, not rejection of the ordered calls. **Cost:** incomplete static relations sacrifice parallel opportunity while keeping acceptance deterministic. **Dependencies:** R14, R20.

### 20-23: fixed affine derivation is sufficient for counted overlap

```text
for i in 0..n { a[3*i+2] = 0 }
```

**Result: D.** **Reason:** R15 consumes already checked bounds and the canonical nonzero affine image; it does not rerun arithmetic proof or search for injectivity. **Boundary:** `i*i` may be mathematically injective on a domain but is outside the fixed family and denies overlap. **Cost:** predictable checking trades away admissible loops. **Dependencies:** R13, R15, R20.

### 20-24: proof erasure needs a defined scoped-metadata bridge

```text

write(p, 1); write(q, 2)
```

**Result: U.** **Reason:** direct separation may justify source operations, and R16 says proofs erase, but the precise scope and backend encoding of that alias fact are not supplied. **Boundary:** no runtime alias check or proof object may appear. **Cost:** omitting metadata is safe but may forgo vectorization; emitting it unsafely risks miscompilation. **Dependencies:** R16 and lowering gap.

## Row 21 — access and state effects

### 21-21: restored state does not erase execution effects

```text
let x = take(loc(a))
put(loc(a), x)
```

**Result: D.** **Reason:** exit state is again Full(A), while R12 records the hole, transfers, and writes during execution. **Boundary:** a postcondition alone cannot serve as the effect row. **Cost:** separate event/effect accounting increases checker data; the exchange needs no runtime occupancy flag. **Dependencies:** R4, R8, R12.

### 21-22: intermediate holes conflict with overlapping readers

```text
request_overlap(take_put(loc(a)), observe(loc(a)))
```

**Result: D.** **Reason:** `take_put` has a write/state-change effect on A throughout the call despite restoring fullness; `observe` reads A, so R14 denies overlap. **Boundary:** ordered sequential calls are valid when A is full at each call boundary. **Cost:** conservative whole-call effects preserve safety and source observables. **Dependencies:** R12, R14.

### 21-23: reduction effects separate accumulator and element reads

```text
for i in 0..n { sum = sum +wrap a[index[i]] }
// every index[i] bound is proved; a is never written
```

**Result: D.** **Reason:** R15 recognizes the sole external whole-place write as an admitted accumulator reduction. Proved-safe accesses to A are read-only, so iterations may read the same or arbitrary elements; identical-map restrictions apply when a root is also mapped-written. **Boundary:** writing A introduces those restrictions. **Cost:** retained bounds evidence suffices without needless affine normalization. **Dependencies:** R12, R14, R15.

### 21-24: state effects erase but runtime data changes remain

**Result: D.** **Reason:** ghost Full/Live facts and duties erase, while the actual load/store and cleanup required by the value remain. Argument evaluation and loans are included. **Boundary:** unresolved writes or ends deny permission; no scheduler behavior is observable. **Cost:** optional overlap may improve execution without changing sequential semantics. **Dependencies:** R11, R12, R14, PAR-1.

## Row 23 — loop overlap and reductions

## Row 24 — lowering and optimization facts

## Higher-order witnesses

1. **Guarded range callback:** a callback chosen by a Boolean, each branch carrying an identical `writes(P[0..len])` contract, can be projected through a proved adjacent-range view and retain PAR-2. A branch with a hidden provider write denies overlap in every iteration. This combines axes 13, 14, 16, 19, 21, and 23.
2. **Container shard allocation:** a loop that mutates distinct shards but allocates from one provider needs both a quantified shard-disjointness invariant and a provider-family account. Even perfect payload separation does not remove shared metadata conflict. This combines axes 14, 15, 17, 20, 21, and 23 and remains unresolved.
3. **Conditional take through a generic call:** a guarded locator passed to an alias-polymorphic `take_put` preserves each alternative's duty and exit fullness, but its intermediate hole denies overlap with a reader in any conflicting alternative. This combines axes 16, 18, 19, 21, and 22 and is derivable for finite alternatives.
4. **Parallel reduction lowering:** an admitted wrapping reduction plus affine element reads has a derived source-level equivalence, yet trustworthy vector/parallel metadata remains unresolved until lowering scopes and retained-storage semantics are defined. This combines axes 20, 21, 23, and 24.
5. **Backing/suballocation identity challenge:** suppose a future primitive forms live suballocation B within still-live backing A, assigns B a fresh logical identity, and gives both target names to effects and lowering. R1 proves disjointness only for the separate allocations its current transition creates, while R16 says A/B identity inequality alone cannot prove disjoint bytes. Because no rule defines suballocation formation, extent, or ancestor access, x0 cannot derive either safe simultaneous access or a contradiction: the interaction is **U**. The missing rule must distinguish sibling disjointness from ancestor/descendant overlap and connect provider effects to lowering scopes without silently narrowing R1.

## Possible axis splits

- Split axis 14 into provider dependency accounting and provider access/synchronization effects: the former hits the missing family calculus, while the latter is already decisive for overlap.
- Split axis 15 into representation predicates and collection element families: fixed predicate opening and quantified family manipulation have different proof obligations.
- Split axis 20 into automatic fixed derivations, written predicate steps, and written quantified-family steps; only the first is presently specified.
- Split axis 24 into executable representation lowering and optimizer metadata semantics: conservative execution is often derived while metadata remains unresolved.

## Concrete defects exposed

1. No introduction, elimination, framing, or resource-accounting rules exist for general representation predicates.
2. No finite certificate language is defined for quantified dynamic allocation, element, or provider-dependency families.
3. Hidden existential target packaging and unpacking is promised for stored heterogeneous structures but has no checking rules.
4. Generic function-contract refinement beyond exact matching is unspecified.
5. Provider dependency discharge and provider implementation representation are not connected by a defined rule.
6. Access-scoped alias metadata and parallel/vector lowering lack complete physical semantics, even where source-level separation is derived.
7. Conditional cleanup of arbitrary partially initialized aggregates remains unavailable without writer-expressed control flow.
8. Suballocation formation has no rule that relates fresh child identity, ancestor extent, sibling separation, provider duties, and access-scoped lowering; R1 freshness and R16's ancestor warning therefore cannot yet be composed.
