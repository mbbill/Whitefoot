# x0 interaction matrix: rows 1–5

Shared fixtures below abbreviate only facts supplied by R1–R16. `a` and `b`
are distinct fresh live allocations, `x` and `y` are inline local slots, and
`Int` is Copy. A descriptor owns an allocation duty; a locator owns none.
`cond` is one immutable evaluated Boolean atom. `affine_value` and
`linear_value` are incoming full values carrying, respectively, a verified
affine cleanup obligation and a linear obligation that must be discharged.

```text
let a = alloc(10); let b = alloc(20)
slot x: Int = 1; slot y: Int = 2
let pa = loc(*a); let pb = loc(*b); let px = loc(x)
```

## Row 1 — Storage identity

### 1-1: fresh and permanent allocation identities
```text
let c = alloc(30)
let pc = loc(*c)
release(c)
let d = alloc(40)
read(pc)
```
**Result: D. Reason:** R1 gives `c` a fresh identity and R6 permanently ends it; later allocation `d` cannot revive it even if bytes are reused. **Boundary:** the final read through previously formed pc is rejected; attempting `loc(*c)` only after release would fail earlier while reading the dead descriptor/referent. **Cost:** ordinary allocation/release plus erased identity tracking. **Dependencies:** physical reuse and optimizer facts remain governed by R16.

### 1-2: descriptor storage differs from referent identity
```text
let owner_slot = loc(a)
let referent = loc(*a)
let c = move(a)
read(referent)
```
**Result: D. Reason:** R1–R2 distinguish the local descriptor slot from allocation A; R5 moves the descriptor into c while A remains fixed. **Boundary:** `take(owner_slot)` fails because that slot is empty, while `referent` remains usable and c retains A's duty. **Cost:** a descriptor move plus two proof identities, with no extra safety field. **Dependencies:** axis 3 transfer and axis 9 validity.

### 1-3: heap transfer preserves target identity
```text
let p = loc(*a)
let c = move(a)
write(p, 11)
release(c)
```
**Result: D. Reason:** R5 transfers the owner value and disposal duty but not allocation A, so `p` still names A and the write is valid. **Boundary:** moving inline `x` instead would not make `px` follow the value. **Cost:** constant proof-state substitution. **Dependencies:** disposal consumes the transferred duty under R6.

### 1-4: class does not manufacture identity separation
```text
fn pair<P,Q>(p: Loc<P,Int>, q: Loc<Q,Int>) { read(p); read(q) }
pair(pa, pa)
read(pa)
```
**Result: D. Reason:** R11 substitutes A for both P and Q; Copy classification permits observation but different parameter symbols never prove distinct targets. **Boundary:** a contract requiring `Separate(P,Q)` rejects this call, while a read/read contract can accept it. **Cost:** equality substitution in the checker. **Dependencies:** axis 18 contracts and R14 overlap compatibility.

### 1-5: a hole belongs to the captured target
```text
let q = pa
let v = take(pa)
read(q)
put(q, v)
```
**Result: D. Reason:** R2 preserves q’s target A and R4 changes A’s content state, so every alias observes the same hole. **Boundary:** the read is rejected; restoring through q succeeds and does not create a new identity. **Cost:** one target-state update and alias fact invalidation. **Dependencies:** branch-correlated holes use R9.

### 1-6: replacement keeps storage identity
```text
let q = pa
let old = replace(pa, 12)
let now = read(q)
```
**Result: D. Reason:** R4 exchanges contents at A without ending or retargeting A, and R8 invalidates old value facts while preserving liveness and identity. **Boundary:** `old` contains 10 and `now` is 12; replacement after `release(a)` is rejected. **Cost:** ordinary exchange plus proof-state update. **Dependencies:** non-Copy replacement also transfers content duties.

### 1-7: copied locators preserve one identity
```text
let q = pa
write(pa, 13)
let n = read(q)
```
**Result: D. Reason:** R2 says locator copying preserves A and grants no independent lifetime or exclusion. Sequential write then read is therefore 13. **Boundary:** copying q does not duplicate A’s disposal duty or prove it distinct from pa. **Cost:** a runtime pointer copy and checker alias equality. **Dependencies:** overlapping write/read remains denied by R14.

### 1-8: stored target identity needs packaging rules
```text
slot box = Some(pa)
let hidden = load_locator(box)
write(box, Some(pb))
read(hidden)
```
**Result: U. Reason:** the concrete loaded copy clearly remains A by R2, but x0 lacks existential target packaging and unpacking rules for the general heterogeneous stored form. **Boundary:** a monomorphic `Loc<A,Int>` field is derivable; a hidden target cannot be recovered from its type name alone. **Cost:** required checker packaging machinery is unspecified. **Dependencies:** container invariants and predicates.

### 1-9: ended identity invalidates every old path
```text
let q = pa
release(a)
let d = alloc(10)
read(q)
```
**Result: D. Reason:** R6 ends A permanently and R8 forbids deriving liveness from reused bytes or equal values. **Boundary:** the last read is rejected, while copying or discarding inert q is allowed because it does not access A. **Cost:** ghost liveness state with no generation map. **Dependencies:** lowering must not turn identity into runtime metadata.

### 1-10: disposal consumes the identity-indexed duty
```text
let q = pa
release(q)
release(a)
```
**Result: D. Reason:** q identifies A, while the context supplies A’s unique disposal duty; R6 consumes it and retires a’s authority. **Boundary:** the second release is rejected, and a locator passed without the duty cannot release. **Cost:** linear proof bookkeeping only. **Dependencies:** contracts must state duty transfer separately from locator transfer.

### 1-11: cleanup cannot guess identity state
```text
if cond { release(a) } else { skip }
scope_exit
```
**Result: C. Reason:** R7 cannot synthesize one unconditional cleanup valid when A is dead in one arm and live in the other. The rewrite is source branching that releases A only in the live arm. **Boundary:** no hidden generation or drop flag may discriminate. **Cost:** writer-visible control flow and possible code duplication. **Dependencies:** R9 retains the guarded identity states.

### 1-12: subobject identity is layout-scoped
```text
slot e = Left{v: 1}
let p = loc(e.Left.v)
e = Right{v: 2}
read(p)
```
**Result: D. Reason:** R8 retires the old payload identity when the active layout switches, even if the new payload reuses its bytes. **Boundary:** the read is rejected; switching back to `Left` creates no revival. **Cost:** static variant-state tracking, with the runtime tag already required by the enum. **Dependencies:** whole-layout operations use R13.

### 1-13: indices select parts of one backing identity
```text
let p0 = loc(arr[0])
let p1 = loc(arr[1])
write(p0, 3)
read(p1)
```
**Result: D. Reason:** with proved bounds and unequal fixed indices, R13 derives distinct parts beneath the same live backing allocation. **Boundary:** symbolic `i` and `j` names alone do not establish separation, and reallocation retires the old backing identity. **Cost:** captured index data may be runtime data; equality facts are ghost. **Dependencies:** numeric separation uses existing WF derivations.

### 1-14: provider and payload identities are separate
```text
let u = provider_alloc(pool, 8)
let v = provider_alloc(pool, 8)
request_overlap(write(loc(*u), 1), write(loc(*v), 2))
```
**Result: U. Reason:** the earliest gap is `provider_alloc`: x0 supplies neither its checked body nor its payload-duty, pool-dependency, and metadata-effect contract. If those calls establish fresh disjoint payloads, the shown payload writes separate locally, but that does not settle shared metadata. **Boundary:** identity inequality cannot erase a possible pool conflict. **Cost:** provider traffic may serialize work. **Dependencies:** axes 21–22.

### 1-15: container identity abstraction lacks general rules
```text
bag.push(move(a))
let p = bag.loc_at(0)
bag.remove(0)
read(p)
```
**Result: U. Reason:** safe rejection after removal requires a checked representation invariant relating element identity, backing storage, mutation, and retired targets. General predicate fold/unfold and dynamic resource-family rules are missing. **Boundary:** no container exemption or assertion supplies them. **Cost:** checker proof language and library annotations are unspecified. **Dependencies:** axes 13, 17, and 20.

### 1-16: branch retains identity correlation
```text
let p = if cond { pa } else { pb }
if cond { write(p, 4) }
```
**Result: D. Reason:** R9 keys p’s target to the evaluated condition atom, so the guarded write selects A in the true branch rather than both members of a may-set. **Boundary:** reassigning `cond` later does not rewrite the captured atom. **Cost:** guarded alternatives can grow exponentially. **Dependencies:** state changes apply only to the selected identity under R8.

### 1-17: dynamic identity families lack proof rules
```text
while more invariant { owns_each(nodes) } {
  nodes.push(alloc(0))
}
release_each(nodes)
```
**Result: U. Reason:** each allocation must be fresh and carry its own duty, but `owns_each` would require the missing quantified resource-family and predicate rules. **Boundary:** a fixed finite set of allocations can be enumerated and derived; one reused symbolic identity is unsound. **Cost:** explicit family certificates and checker representation remain unspecified. **Dependencies:** loop invariant establishment under R10.

### 1-18: call substitution may unify identities
```text
fn both<P,Q>(p: Loc<P,Int>, q: Loc<Q,Int>)
    accesses reads(P), reads(Q) { read(p); read(q) }
both(pa, pa)
```
**Result: D. Reason:** R11 substitutes actual A for both abstract identities and validates the combined read demands; no separation is required. **Boundary:** a transfer of A’s single duty through both parameters would be rejected as duplication. **Cost:** direct symbolic substitution. **Dependencies:** generic refinement beyond such direct substitution remains a stated gap.

### 1-19: recursive identity abstraction is contractual
```text
fn visit<P>(p: Loc<P,Int>) requires Live(P), Full(P) {
  if more { visit(p) }
}
```
**Result: D. Reason:** R11 checks the body against its declared contract and recursive calls reuse that contract without unfolding; P continues to denote the substituted captured target. **Boundary:** the declaration is not proof of its body, and hidden existential descendants need missing packaging rules. **Cost:** finite body checking. **Dependencies:** complete effects must accompany the contract.

### 1-20: identity facts have bounded automatic strength
```text
let c = alloc(1)
use fresh(c)
request_overlap(write1(pa), write1(loc(*c)))
```
**Result: D. Reason:** R1 directly establishes distinct fresh live allocations, and R14 can use that separation for these whole-allocation writes. **Boundary:** `use P != Q` for arbitrary parameters is not accepted without a supported proof, and ancestor/descendant identities do not imply byte disjointness. **Cost:** deterministic structural proof. **Dependencies:** R16 limits machine alias claims.

### 1-21: effects name actual identities
```text
fn bump<P>(p: Loc<P,Int>) accesses reads(P), writes(P)
    { let n = read(p); write(p, wrapping_add(n, 1)) }
bump(pa)
read(pb)
```
**Result: D. Reason:** R11 substitutes A into the effect and R12 records its actual read/write, leaving independent fresh B facts intact by R8 separation. **Boundary:** an effect naming only the locator variable’s storage would be incomplete. **Cost:** target-indexed effect sets and invalidation. **Dependencies:** indirect provider state must also be named where applicable.

### 1-22: logical separation permits local overlap
```text
fn bump<P>(p) accesses reads(P), writes(P)
    { let n = read(p); write(p, wrapping_add(n, 1)) }
request_overlap(bump(pa), bump(pb))
```
**Result: D. Reason:** R1 establishes A and B as distinct fresh live allocations, and complete effects confined to those payloads do not conflict under R14. **Boundary:** `bump(pa), bump(pa)` is denied, as is either call if hidden provider metadata is touched. **Cost:** parallel opportunity without an alias guard. **Dependencies:** argument evaluation and duties must also be independent.

### 1-23: iteration identity needs admitted maps
```text
for i in 0..n parallel {
  arr[i] = wrapping_add(arr[i], 1)
}
```
**Result: D. Reason:** R15 admits the single-index affine map with proved bounds, giving distinct element locations for unequal iterations while preserving each same-index read-modify-write. **Boundary:** replacing `i` with an arbitrary shifted map lacks automatic independence. **Cost:** fixed numeric derivation; no runtime alias test. **Dependencies:** backing allocation identity must remain fixed.

### 1-24: ghost identity is not noalias metadata
```text
fn read_two<P,Q>(p: Loc<P,Int>, q: Loc<Q,Int>) -> Int
    requires Live(P), Full(P), Live(Q), Full(Q)
    accesses reads(P), reads(Q) { return wrapping_add(read(p), read(q)) }
read_two(pa, pa)
```
**Result: D. Reason:** R16 erases P and Q and forbids unconditional uniqueness; the aliased call is valid because both accesses are reads. **Boundary:** different symbols cannot produce `noalias`, while an established scoped separation proof may authorize narrower facts. **Cost:** zero identity runtime storage; conservative optimization otherwise. **Dependencies:** complete lowering semantics remain generally unresolved.

## Row 2 — Owned storage representation

### 2-2: inline and allocated ownership representations
```text
slot s: Int = 1
let h = alloc(2)
let ps = loc(s); let ph = loc(*h)
```
**Result: D. Reason:** R1–R2 give s lexical inline storage and h a descriptor for separate allocation H; the locator operations share syntax but their storage and disposal duties differ. **Boundary:** scope ends s, while H requires its allocation duty to be consumed. **Cost:** a pointer-bearing owner only for allocated storage. **Dependencies:** content class can add separate duties.

### 2-3: moving inline content and descriptors differs
```text
slot dst: Int
put(loc(dst), take(px))
let h2 = move(a)
```
**Result: D. Reason:** R5 leaves px targeting empty x after inline content moves to dst, whereas moving descriptor a leaves its referent A fixed. **Boundary:** neither operation retargets existing locators to the destination binding. **Cost:** inline value copy versus descriptor copy; proof duties follow content. **Dependencies:** source slots become empty under axis 5.

### 2-4: representation follows contained obligations
```text
slot s = move(linear_value)
let h = alloc(move(affine_value))
take(loc(s))
```
**Result: D. Reason:** R5 transfers the represented content and its class obligations independently of whether the slot is inline or allocated. **Boundary:** linear content cannot be silently dropped at either scope exit or release; affine content needs verified cleanup. **Cost:** composite class bookkeeping, without an occupancy bit. **Dependencies:** general aggregate cleanup remains a gap under axis 11.

### 2-5: holes do not remove storage representation
```text
let v = take(pa)
let q = loc(*a)
release(a)
```
**Result: D. Reason:** R4 empties A’s content while leaving its separately allocated storage live and addressable; R2 permits q formation without full contents. R6 then ends empty A using its allocation duty. **Boundary:** `read(q)` while empty fails, and v’s own duties survive release. **Cost:** compile-time content state only. **Dependencies:** cleanup must not double-dispose v.

### 2-6: allocated replacement preserves descriptor ownership
```text
let old = replace(pa, 7)
let n = read(pa)
release(a)
```
**Result: D. Reason:** R4 exchanges A’s content, not the owner descriptor or allocation duty; old is 10 and n is 7. **Boundary:** replacing the descriptor slot itself would exchange ownership values and duties rather than A’s contents. **Cost:** ordinary scalar exchange. **Dependencies:** contracts must distinguish descriptor storage from referent effects.

### 2-7: locator copies never become owners
```text
let q = pa
drop(q)
release(a)
```
**Result: D. Reason:** R2 makes q a copyable locator containing no allocation duty, so dropping it has no storage cleanup consequence. The owner a still supplies A’s duty. **Boundary:** q could identify A for release only if the surrounding context also made that duty available. **Cost:** pointer copy only. **Dependencies:** R16 forbids pointer-wide uniqueness assumptions.

### 2-8: storing an owner differs from storing a locator
```text
slot owner_box = move(a)
slot loc_box = pa
let q = read(loc_box)
```
**Result: D. Reason:** R5 transfers A’s descriptor and duty into owner_box, while R2 copies only A’s target into loc_box; reading the Copy locator yields q without duplicating ownership. **Boundary:** observing owner_box as a Copy value is forbidden. **Cost:** same runtime pointer size is possible, but proof classes differ. **Dependencies:** hidden heterogeneous boxes remain U.

### 2-9: local lifetime is not extended by ownership movement
```text
slot inner: Int = 1
let p = loc(inner)
move(inner)
leave_scope
read(p)
```
**Result: D. Reason:** R5 moves inline content but not inner’s lexical storage; R6 ends that storage at scope exit. **Boundary:** the final read fails even if the moved content remains live elsewhere. Moving an allocated descriptor instead preserves its separately allocated referent. **Cost:** lexical lifetime tracking. **Dependencies:** captured locators may persist inertly.

### 2-10: allocation duty is separate from content
```text
let v = take(pa)
release(a)
consume(v)
```
**Result: D. Reason:** R4 transfers A’s content duties to v, and R6 consumes only A’s independently disposable storage duty when releasing the empty allocation. **Boundary:** releasing full A requires verified disposition of content; releasing a field never gains authority over A. **Cost:** separate resource ledgers. **Dependencies:** content class and automatic cleanup determine disposition.

### 2-11: representation does not supply conditional cleanup
```text
if cond { let v = take(pa) } else { skip }
scope_exit
```
**Result: U. Reason:** an arbitrary aggregate or hidden non-Copy v existing only in one runtime arm needs a source-represented discriminant or a general conditional-partial cleanup rule, which x0 lacks. **Boundary:** cleanup written inside each branch is derivable. **Cost:** writer control flow today; general checker and representation costs unknown. **Dependencies:** R7 and guarded joins.

### 2-12: whole representation requires full parts
```text
slot r = Pair{left: owner1, right: owner2}
let l = take(loc(r.left))
move(r)
```
**Result: D. Reason:** R13 permits field transfer without emptying right, but R5 requires the relevant full layout for moving whole r. **Boundary:** the final move is rejected while left is empty; moving r.right separately remains possible. **Cost:** per-part proof state, no runtime occupancy map. **Dependencies:** general aggregate cleanup is unresolved when partial states branch.

### 2-13: views do not own backing storage
```text
let view = slice(*a, 0, 1)
let q = view[0]
release(a)
read(q)
```
**Result: D. Reason:** R13 treats the view as a descriptor over A rather than fresh element storage; only a carries A’s duty. R6 ends A and invalidates q. **Boundary:** copying or moving view never extends A’s lifetime or authorizes disposal. **Cost:** ordinary offset/length fields. **Dependencies:** bounds proofs and target liveness remain required.

### 2-14: payload owners may share provider representation
```text
let u = provider_alloc(pool, 8)
let v = provider_alloc(pool, 8)
release(u); release(v)
```
**Result: U. Reason:** x0 requires each descriptor to own a distinct payload duty while both depend on pool, but allocation/provider implementation and dependency accounting are explicit gaps. **Boundary:** neither payload owner may release pool, and pool cannot end early. **Cost:** real provider metadata accesses must be represented. **Dependencies:** axes 10, 14, and 21.

### 2-15: container representation must expose ownership invariant
```text
vec.push(move(a))
let h = vec.pop()
release(h)
```
**Result: U. Reason:** the intended transfer is clear, yet the general container predicate that relates vector slots, allocation duties, partial capacity, and returned ownership has no fold/unfold or resource-family rules. **Boundary:** a fixed hand-written aggregate can derive the same transfer fieldwise. **Cost:** missing proof infrastructure, not hidden runtime flags. **Dependencies:** axes 17 and 20.

### 2-16: guarded descriptors preserve alternative duties
```text
let h = if cond { move(a) } else { move(b) }
release(h)
```
**Result: D. Reason:** R9 retains the joint alternatives `(h→A, duty A)` and `(h→B, duty B)`; R6 validates release in each. **Boundary:** intersecting duties at the join would wrongly lose both, while duplicating them would be unsafe. **Cost:** guarded proof states can expand. **Dependencies:** cleanup after release must retire the corresponding old descriptor authority.

### 2-17: loop-owned descriptor families are unresolved
```text
while more invariant { owns_all(items) } {
  items.push(alloc(1))
}
```
**Result: U. Reason:** runtime-many descriptors and duties need a quantified resource family plus a checked container invariant, both missing. **Boundary:** a loop rotating one fixed descriptor through slots is derivable with an explicit fixed-object invariant. **Cost:** unknown certificate and checker scaling; no runtime duty table is allowed. **Dependencies:** R10 and axis 15.

### 2-18: contracts distinguish owner and locator parameters
```text
fn consume<P>(h: Owner<P>) transfers duty(P) { release(h) }
fn observe<P>(p: Loc<P,Int>) accesses reads(P) { read(p) }
consume(move(a))
```
**Result: D. Reason:** R11 validates a resource transfer for the owner call separately from an access-only locator contract. **Boundary:** calling consume with pa is rejected because identical target knowledge supplies no duty. **Cost:** richer checked signatures, no representation change. **Dependencies:** generic direct substitution suffices for this case.

### 2-19: generic representation cannot imply ownership
```text
fn f<T,P>(x: T, p: Loc<P,Int>) { read(p) }
f(a, pa)
```
**Result: D. Reason:** T’s runtime representation and P’s target parameter do not by themselves connect x to P; the read is justified by p’s explicit `Live/Full` contract, not by x being pointer-shaped. **Boundary:** transferring or releasing P needs an explicit resource contract. **Cost:** abstraction preserves separate parameters. **Dependencies:** contract refinement beyond direct substitution is unresolved.

### 2-20: proof accounting stays separate from machine layout
```text
let h = move(a)
use owns(h, A)
release(h)
```
**Result: D. Reason:** R5 and R6 structurally transfer and consume A’s duty; `owns` is a checked fact derived from the move, not a runtime bit. **Boundary:** a writer cannot assert it for pa, and a type parameter alone cannot create it. **Cost:** erased proof bookkeeping. **Dependencies:** complete optimizer metadata semantics remain outside this local derivation.

### 2-21: descriptor and referent effects are distinct
```text
fn move_owner(slot) accesses reads(slot), init_change(slot)
    { return take(slot) }
move_owner(loc(a))
read(pa)
```
**Result: D. Reason:** moving the owner changes descriptor-slot state but not A’s payload state, so a preexisting pa can still read A while its duty resides elsewhere. **Boundary:** the call’s transfer effect must name the duty, and releasing A adds an end effect on A. **Cost:** larger effect vocabulary. **Dependencies:** R12 complete execution effects.

### 2-22: disjoint payloads can still conflict on owner slots
```text
request_overlap(move_owner(loc(a)), read_owner(loc(a)))
```
**Result: D. Reason:** both calls touch the same descriptor storage even though the owned payload is a separate identity; R14 therefore denies overlap. **Boundary:** operations confined to distinct fresh payloads may overlap if argument evaluation and provider state are also disjoint. **Cost:** lost parallel opportunity required to preserve source order. **Dependencies:** complete descriptor effects under axis 21.

### 2-23: parallel element work cannot move one owner twice
```text
for i in 0..2 parallel {
  out[i] = move(a)
}
```
**Result: D. Reason:** R15 may separate `out[i]` destinations, but R5 exposes both iterations consuming the same owner descriptor and A duty, so cross-iteration resource accounting rejects the loop. **Boundary:** moving distinct `owners[i]` with admitted affine maps can be accepted. **Cost:** static restriction, no locks or runtime claiming. **Dependencies:** bounds and input-element separation.

### 2-24: equal pointer shapes do not justify optimizer attributes
```text
let p = pa
let h = move(a)
backend_use(h, p)
```
**Result: D. Reason:** the owner and locator may both contain A’s address, but only h carries its duty; R16 erases proof ownership and refuses unconditional uniqueness on p. **Boundary:** backend code must preserve their allowed aliasing until A ends. **Cost:** conservative alias metadata, with no extra ownership tag. **Dependencies:** full physical lowering remains an explicit gap.

## Row 3 — Value and ownership transfer

### 3-3: repeated handoff preserves one duty
```text
let c = move(a)
let d = move(c)
release(d)
```
**Result: D. Reason:** R5 transfers A’s descriptor and unique duty at each move, emptying each source; R6 consumes the duty once. **Boundary:** reuse of a or c is rejected, while pa continues to target A until release. **Cost:** linear proof-state updates and ordinary descriptor copies. **Dependencies:** no target retargeting or runtime move flag.

### 3-4: transfer follows value class
```text
let c = move(affine_value)
let d = move(linear_value)
scope_exit
```
**Result: D. Reason:** R5 transfers both values and contained obligations; R7 may clean c only through verified affine cleanup, while d’s linear duty must be explicitly discharged or transferred. **Boundary:** Copy duplication is allowed only when no resource obligation is duplicated. **Cost:** class-indexed exit checking. **Dependencies:** composite classes follow their contents.

### 3-5: take is content transfer, not storage transfer
```text
let v = take(pa)
let q = pa
put(q, v)
```
**Result: D. Reason:** R4 transfers A’s content and duties to v while leaving A live and empty; put transfers them back into the same target. **Boundary:** q never follows v to its temporary binding, and reading q during the hole fails. **Cost:** target-state and duty movement in proof state. **Dependencies:** storage duty remains with a.

### 3-6: replacement transfers old obligations
```text
let old = replace(pa, move(new_affine))
cleanup(old)
release(a)
```
**Result: D. Reason:** R4 installs the new content and transfers the old content and its duties into old without changing A. **Boundary:** discarding old without verified cleanup is rejected; replace on an empty A is rejected rather than treated as put. **Cost:** exchange plus resource substitution. **Dependencies:** argument evaluation precedes the checked exchange.

### 3-7: aliases do not follow moved inline values
```text
let p = loc(x)
slot z: Int
put(loc(z), take(p))
read(p)
```
**Result: D. Reason:** R5 says physical inline transfer does not retarget locators, so p still names the now-empty x rather than z. **Boundary:** the final read fails; a locator explicitly formed for z succeeds. **Cost:** no locator fixups at runtime. **Dependencies:** R2 captured-target semantics and R4 holes.

### 3-8: moving a stored locator copies no owner
```text
slot cell = pa
let q = move(cell)
release(a)
read(q)
```
**Result: D. Reason:** moving the locator transfers only its captured target value and empties cell; A’s duty remains with a. **Boundary:** q cannot keep A live after release, and the final read fails. **Cost:** pointer transfer and slot-state update. **Dependencies:** existentially hidden locator storage remains unresolved, but this monomorphic witness is direct.

### 3-9: transfer cannot extend inline storage lifetime
```text
slot inner = linear_value
let p = loc(inner)
let v = take(p)
leave_scope
use(v)
```
**Result: D. Reason:** taking transfers content and its obligation to v, while scope exit ends inner’s storage; v remains independently usable. **Boundary:** p is invalid after exit and cannot access v’s new storage. **Cost:** lexical lifetime and resource tracking. **Dependencies:** v’s linear obligation still requires explicit discharge.

### 3-10: owner transfer carries disposal authority
```text
let c = move(a)
release(c)
release(a)
```
**Result: D. Reason:** R5 moves A’s disposal duty with the owner descriptor, and R6 consumes it through c. **Boundary:** a is empty immediately after the move and has no second authority; pa alone never acquired the duty. **Cost:** erased linear bookkeeping. **Dependencies:** calls moving c must declare the transfer.

### 3-11: moved resources constrain cleanup
```text
if cond { let c = move(a) }              // c cleans at true-arm exit
else { let c = move(a) }                 // c cleans at false-arm exit
scope_exit
```
**Result: C. Reason:** the original one-arm move leaves outer a empty/dead on the true path and full/live on the false path, so R7 supplies no single unconditional outer cleanup. The shown rewrite moves a into a branch-local c in both written arms; each c is unconditionally full at its own arm exit and can run verified affine cleanup. **Boundary:** no compiler-hoisted cleanup or hidden moved flag discriminates the join. **Cost:** duplicated source control. **Dependencies:** R7 and R9.

### 3-12: partial field transfer blocks whole move
```text
slot r = Pair{left: linear1, right: linear2}
let l = take(loc(r.left))
move(r)
```
**Result: D. Reason:** R5 permits the selected field transfer but requires a full relevant layout for whole-r move, so the final line is rejected. **Boundary:** right remains full and may be moved independently; l owns left’s obligation. **Cost:** per-field state. **Dependencies:** cleanup of arbitrary guarded partial aggregates remains U.

### 3-13: moving a view preserves backing association
```text
let v = slice(*a, 0, 1)
let w = move(v)
```

### 5-5: take and put preserve live storage

### 5-6: replacement cannot commit over a hole

### 5-9: holes remain addressable but not readable

### 5-10: empty allocation may be released

**Result: D. ## High-order witnesses and follow-up

The strongest cross-axis witness is the parent/suballocation case:

```text
let parent = alloc_run(64)
let child = reserve_suballocation(parent, 0, 16)
request_overlap(write_all(*parent), write_all(*child))
```

R1 says each allocation or suballocation has a fresh identity and says distinct
fresh live allocations are disjoint, while R16 says logical inequality does not
prove disjoint bytes for ancestor/descendant storage. **Status: U.** The frozen
rules do not define whether R1's “allocations” excludes nested suballocations or
whether its disjointness is storage-domain rather than byte-range disjointness.
Treating it as byte disjoint would conflict with R16; treating it narrowly needs
an explicit scope rule. Provider reservation and lowering therefore cannot use
identity inequality here.

Other high-order witnesses are guarded owner transfer followed by locator-based
release (axes 1/3/10/16), a temporary hole restored before a requested overlap
(5/18/21/22), and parallel movement of per-element linear duties
(3/4/15/17/23). They show that target identity, content state, and duties must
remain separate yet correlated throughout calls and joins.

Proposed axis splits:

- Split axis 1 into allocation identity freshness and physical byte-range
  separation, explicitly covering ancestor/descendant suballocations.
- Split axis 14 into provider lifetime resources and provider management-state
  access effects.
- Split axis 15 into fixed-shape abstraction predicates and quantified dynamic
  container families.
- Split axis 24 into proof erasure, concrete owner/locator lowering, and scoped
  optimizer alias metadata.

Actionable defects:

1. Define R1's disjointness domain relative to suballocations and R16.
2. Supply checked predicate fold/unfold rules for representation invariants.
3. Supply finite quantified resource-family rules for loops and containers.
4. Define existential target packaging/unpacking and mutation invalidation.
5. Specify provider dependency resources and complete management-state effects.
6. Define cleanup rules for conditionally partial arbitrary aggregates without
   hidden flags.
7. Specify physical lowering and the exact scope of emitted alias metadata.
