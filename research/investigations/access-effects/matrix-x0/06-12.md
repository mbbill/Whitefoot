## Higher-order witnesses

- A stored locator loaded before its field is rebound, then used after a branch-selected release, combines axes 8, 9, 10, 16, 21, and 22. R2 preserves the old target and R9 preserves alternatives, but the general hidden-target package is still unresolved.
- A loop that removes affine elements from a container, exits early, and cleans the remainder combines axes 11, 13, 15, 17, 20, and 23. Fixed arrays can be written branch-by-branch; dynamic families and partial aggregate cleanup lack rules.
- Switching an enum payload while an old payload locator is stored in another object, then requesting overlap with a reader, combines axes 8, 12, 18, 21, 22, and 24. The switch ends the payload identity and its end/access conflict denies overlap.

## Proposed axis splits

- Split axis 8 into concrete statically named stored targets and existential heterogeneous target packages; the former is often derivable while the latter repeatedly depends on the explicit packaging gap.
- Split axis 11 into structurally complete affine cleanup and conditionally partial aggregate cleanup; current verdicts otherwise hide the difference between a fixed unconditional sequence and a missing state discriminator.
- Split axis 17 into fixed-object loop invariants and dynamically allocated resource families; R10 handles the first, while the second needs quantified family rules.
- Split axis 24 into proof erasure/runtime representation and backend alias/optimizer metadata. R16 settles many erasure negatives but explicitly leaves complete lowering semantics open.

## Actionable defects

1. Define introduction, elimination, mutation, and repack rules for existential target packages, including which liveness and disposal relations may cross the package boundary.
2. Define cleanup derivation for partially initialized aggregates without compiler-inserted flags, or state the source control required to discriminate every represented exit state.
3. Supply finite certificate rules for dynamic resource families across loop entry, backedges, breaks, returns, and errors.
4. Specify predicate fold/unfold authority and invalidation dependencies so container invariants can be checked rather than asserted.
5. Define function-contract refinement for generic and passed functions, including contravariant access assumptions and invariant resource transfers.
6. Specify lowering of ended identities, scoped access facts, and optimizer metadata, including when physical alias facts are valid and how provider metadata effects survive erasure.
