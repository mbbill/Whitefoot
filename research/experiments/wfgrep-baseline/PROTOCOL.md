## Question

What is the honest end-to-end cost of the frozen first-slice `wfgrep`
relative to the host's production fixed-string grep on equivalent work, and
which layer carries the first material divergence?

No direction is assumed. Practical parity, a win, an attributed loss, and a
preregistered-precision failure to attribute are all successful outcomes.
Per task 0016's correction, the preregistered first attribution suspect is
the scalar newline scan retaining its bounds trap; the profile confirms or
refutes it — it is never assumed.

## Comparator

`/usr/bin/grep` invoked as `grep -h -F PATTERN FILE...`:

- `grep (BSD grep, GNU compatible) 2.6.0-FreeBSD`, macOS 26.5.2 (25F84)
  system binary, SHA-256
  `569588bf23c56895f046b63b029285217e442d46bec1b18498b58fefb50d8f1f`.
- Why this binary: `grep -h -F` is the frozen semantic contract wfgrep
  implements (task 0015), so it is the only comparator whose *work* is the

  and needs no comparator-selection protocol of its own. GNU grep would add
  an unpinned third-party build to the boundary, and ripgrep performs
  different work (parallel traversal, mmap) — RG-BASE also demonstrated that
  a ripgrep comparator selection needs its own owner-reviewed protocol.
- What the comparison can claim: the end-to-end product ratio of the frozen
  first-slice wfgrep against this host's production fixed-string grep on the
  pinned warm-cache, explicit-file-list workloads, and (via profile) which
  layer of the wfgrep side carries the first material divergence.
- What it cannot claim: any language-versus-C machine-quality statement
  (the two sides run different algorithms and buffer shapes by design — an
  upstream ratio supports only the scoped product comparison, per
  `docs/WORKFLOW.md`); anything about ripgrep, GNU grep, regex, traversal,
  cold-cache or device I/O, other hosts, or the eventual flagship claim.

## Corpus

Deterministically generated by `runner.rs` (xorshift64, fixed seeds; lines of
60–120 bytes from lowercase letters and space, every line `\n`-terminated;
the only uppercase bytes are injected `XQWFNEEDLE` needles at column 20 of
selected lines). Terminated lines and NUL-free printable content keep the
comparison inside the zone where BSD grep and wfgrep's frozen contract agree
byte-for-byte; disagreement zones (unterminated final lines, binary
detection) are excluded by construction and belong to the oracle harness,
not to timing. All digests are pinned in `MANIFEST.txt`; the `verify` phase
recomputes and enforces them before any timed phase.

The `many` list is explicit because the frozen slice has no directory
traversal; both sides receive the identical 4,096-entry argv. The corpus
(~450 MiB) is far below the 16 GiB host RAM, so warm-cache residence is
plausible for every case and is enforced by the warm pass below.

## Equivalent work

- wfgrep: `wfgrep PATTERN FILE...`; comparator: `grep -h -F PATTERN FILE...`;
  identical pattern, file list, order, and working directory (the corpus
  root); environment cleared except `LC_ALL=C`.
- Before any timing, the `verify` phase requires byte-identical stdout and
  equal exit codes per case, pinned in `MANIFEST.txt` (output SHA-256 and
  exit code). Any mismatch stops the run.
- Timed invocations send stdout to `/dev/null` on both sides and require
  empty stderr and the pinned exit code; any violation invalidates the run.

## Timed phases and the process floor

The timed quantity is end-to-end wall time from `spawn` to exit, measured by
the runner around the child process. This includes process start on both
sides — the honest program-level cost. To separate the known ~2–3.5 ms
process floor (buffer-initialization-cost measured 1.76 ms for the emitted
module alone; the pilot observed ~3.3 ms spawn-to-exit through the shell),
the `floor` case measures each binary's own empty-input whole-process cost
under the identical harness. RESULTS reports, per case, the floor share
(floor median / case median) and a descriptive floor-adjusted ratio
`(comparator median − comparator floor) / (wfgrep median − wfgrep floor)`;
classification uses only the unadjusted primary ratio.

Single-sided pilot (wfgrep only, two passes, disclosed; no comparator was
timed before the freeze): `large` ≈ 310 ms, `nomatch` ≈ 320 ms, `dense`
≈ 195 ms, `many` ≈ 580–810 ms, `floor` ≈ 3.3 ms. Every classified case sits
two orders of magnitude above the floor, so process start cannot decide a
classification at the thresholds below.

## Noise controls (the RG-BASE lesson)

RG-BASE failed its 3% precision gate because the first process in a round
paid a cache-position cost regardless of binary identity; order alternation
alone did not symmetrize it. This protocol therefore:

1. **Warms explicitly.** Before every round, the runner itself reads every
   case file completely, so both positions in the round run against the same
   warm page cache; three discarded invocations of each binary precede each
   case's first round.
2. **Balances order.** 30 rounds per case; wfgrep runs first in 15 and the
   comparator first in 15, alternating. Position-specific medians are
   reported as the position-effect diagnostic.
3. **Demonstrates precision instead of assuming it.** A null comparison —
   the wfgrep binary against itself under the full harness — runs before
   *and* after the comparative phase (`null-before`, `null-after`). Per
   classified case, each null must produce a 95% interval containing 1.0
   with relative half-width ≤ 2%. The demonstrated precision `w` for a case
   is the larger of its two null half-widths.
4. **Records the host state.** `pmset` power source and Low Power Mode are
   recorded at every phase start and end. A phase is valid only if Low Power
   Mode is off and the power source does not change mid-phase. The house
   default is AC power; at authoring the host runs on battery (100%), which
   is disclosed, recorded per phase, and covered by the null gates — if
   battery operation degrades precision, the null gate fails and the case is
   handled by the degradation rule rather than silently trusted.
5. **No CPU pinning.** macOS offers no user-space affinity control; this is
   disclosed rather than simulated. Repetition, balanced order, warm design,
   and the null gates are the controls.

Samples are never deleted, extended, or rerun after a result is observed.
The run id is `wfgrep-baseline-1`; all phases append to
`raw/wfgrep-baseline-1.jsonl`.

## Statistic and interpretation

Per case: within-round ratio = comparator elapsed / wfgrep elapsed (below
1.0 means wfgrep is slower). Point statistic: median of the 30 within-round
ratios. Uncertainty: deterministic 10,000-resample bootstrap over rounds,
seed 20260806, descriptive 95% percentile interval. Bands, fixed in advance:

- **practical parity**: the whole interval lies within `[0.95, 1.05]`;
- **material wfgrep loss**: the whole interval lies below `0.90`;
- **material wfgrep win**: the whole interval lies above `1.10`;
- **directional only**: the interval excludes 1.0 but clears no material
  threshold;
- otherwise **inconclusive**.

Precision rules, fixed in advance:

- A comparative interval with relative half-width above 5% is
  precision-inconclusive regardless of its position.
- If a case's demonstrated null precision `w` exceeds 2%, parity and
  directional classifications are unavailable for it; a material
  classification remains available only if the whole comparative interval
  clears the material threshold widened by `w` (loss below `0.90 × (1 − w)`,
  win above `1.10 × (1 + w)`).
- If no classified case passes its null gate, the recorded result of the
  attempt is the precision failure itself, as in RG-BASE.

The `floor` case is a diagnostic: reported, never classified, exempt from
the null gate.

## Attribution plan

If any case classifies as material, the attribution phase runs on the
dominant divergence: the material case whose ratio median is farthest from
1.0 (largest `|ln ratio|`). The PERF-1 layer chain is walked with these
instruments, all defined before any number was seen:

1. **Counters** (`/usr/bin/time -l`, 5 repetitions per binary per case,
   medians, descriptive): real/user/sys split, instructions retired, cycles
   elapsed, peak footprint. A divergence dominated by *system* time is
   routed to the source-shape/IO boundary (the frozen 4096-byte read chunk
   implies ≈ `bytes/4096` read calls plus per-file open/close — checked
   arithmetically); one dominated by *user* time is routed into the compute
   layers.
2. **Profile** (`/usr/bin/sample`, 10 s, on a profile-only enlarged
   workload: the case's file list repeated `ceil(15 s / wfgrep case median)`
   times in argv, capped so argv stays under 900 KB; both binaries). The
   enlarged workload is never timed comparatively. Because the emitted
   `main` is fully inlined (task 0016), in-`main` localization escalates to
   `xctrace record --template "Time Profiler"` on the same enlarged
   workload, mapping hot addresses to the retained module assembly.
3. **Case algebra** (descriptive): `large` and `nomatch` share the identical
   scan work and differ in match/output work; `dense` maximizes the output
   path; `many` adds per-file open/close and argv handling; `floor` isolates
   startup. Differences between case ratios bound the layer shares.
4. **Code shape**: the retained optimized LLVM and assembly of the frozen
   module; the §9.1 cost-shape gates (four callocs, one read site, five
   write sites, scalar newline scan with retained bounds trap) are the
   already-standing source-shape evidence.

Suspect and falsifier, preregistered: the suspect is confirmed only if the
profile localizes the dominant user-time share of the wfgrep excess to the
newline-scan region of `main` and the assembly shows that region as the
scalar byte loop with its retained trap. It is refuted if system time
dominates (source-shape/IO chunking), if the dominant user-time region is
the inlined `line_matches` literal-match loop (algorithm layer — the
comparator's search algorithm is simply better), if the output/publication
path dominates (`dense`), or if startup dominates (runtime layer).

A layer is named the first material divergence only when the instruments
agree it carries more than half of the wfgrep-side excess. If no layer
reaches that share, or the instruments disagree, the recorded result is the
preregistered inability to attribute within this protocol's precision —
that inability is a successful outcome, not a defect to be argued away.

## Phase order and stop condition

`build → gen → verify → null-before → bench → null-after → counters →
profile (conditional) → RESULTS.md`. The experiment stops when every
classified case has a recorded classification (or the precision-failure
outcome), the floor share is reported, and — for any material case — the
first divergence is attributed or the inability recorded. RESULTS.md then
states the ratio table with intervals, the profile evidence, and exactly
what the numbers do and do not mean.

## Out of scope

No `wfgrep` change, no compiler or language change, no optimizer fact, no
