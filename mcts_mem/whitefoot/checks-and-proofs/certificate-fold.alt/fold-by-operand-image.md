- A nonlinear monomial folded to the value image of an admitted exact multiplication by matching the **operand images** the multiplication was formed over against the images the certificate's multiplicity expands to.
- Shipped as v0.48 and superseded by v0.49 in the same batch.

## Facts

- 2026-09-05 measurement: the feature was admitted and then refused wherever it mattered. A local's image is transparent, so `let stride = width + padding;` gives `stride` the image `width + padding`; a product formed over `stride` and a certificate scaling by `stride` reached the fold as different arithmetic and nothing matched. Held to one shape, only a stride copied straight from a parameter accepted; `width + padding`, `width + 4` and `2 * width` all rejected. (sourced)
- 2026-09-05 rationale: this was not a narrow gap. A stride is definitionally derived, so the rule reached exactly one case in its own domain — matrix multiply, where the stride happens to be a parameter — and a nineteen-program sweep of padded-bitmap, DIB, alignment, tiling, volume and interleaved-audio programs found no other. The only workaround was an extra function per stride, to make the checker hold the operand opaquely.

## Moves

- 2026-09-05 replaced by [[certificate-fold]]: an operand and a multiplicity name the same value when they name the same declaration, not when their images coincide (sourced)
