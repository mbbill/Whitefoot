## Rules the owner has stated for this work

These are the ones a fresh session would not find in `CLAUDE.md`.

- **Keep implementing on PR #13 and do not merge.** Merging now is a
  half-product. Expect the design documents to be revised as implementation
  reveals problems; fold each finding into the plan and the batch record
  (the way `docs/done/0106-backed-file-permit.md` §7 does), never edit a
  conformance verdict or delete a test to go green.
- **T4 is the test for every device API**: if overlap can invent an outcome
  the sequential program never produces, a resource is missing from the API,
  and the answer is on the API, never in the scheduler. The error is the
  system's, so the operation keeps it; the resource is ours, so it comes back
  where the checker can see it.
- **The runtime allocates nothing at run time**: fixed capacities, one
  reservation at entry, deterministic refusal; no growth, no per-operation
  blocking fallback.
- **Judge a runtime paradox by one observable**: no completed I/O's
  continuation is ever buried. The state machine gets exhaustive tests before
  it merges (§11), not after.
- **Wording**: never write the words attack, adversarial, or 攻击 in
  repository text or in replies; say "walk the schedule", "check the case",
  "review".
- **Tests**: never plain `cargo test`; always `cargo test --profile gate`.
  The whole gate stays under five minutes per host; cut test cost by
  structure, never by weakening. Background long runs and read the log; a
  foreground wait stalls the session.
- **Reporting to the owner**: Chinese, code first — a concrete example and
  the real lines quoted verbatim with the file named, then the rule; no
  invented terminology, no em-dashes; say what was verified by running and
  what was only read or compiled.

## Facts a fresh session tends to get wrong

- The spec digest is pinned in `compiler/src/spec.rs` (a byte array and a
  string) and `compiler/src/spec_identity.rs`; after any edit of
  `spec/kernel-spec.md`, recompute with `shasum -a 256` and re-pin both, or
  the `spec::tests` fail.
- `spec-archive-integrity` refusing is not a defect on this branch; at merge
  the v0.41 bytes are archived to `spec/kernel-spec-v0.41.md`, the ACTIVE
  v0.42 record is installed in `governance/APPROVALS.md`, and the
  digest-sync prose updated.
- [GRAM-10] forbids a match binder equal to its field name; that is why the
  opened variants' field is `value`.
- `propagate` no longer applies to an open (its outcome is not a `Result`);
  the [PAR-3] fixtures propagate a `Result`-returning helper instead.
- The completion harness (`compiler/src/backend/completion/harness.c`) is
  built by `make -C compiler completion-test`; the scheduler core's smoke run
  is `make -C compiler sched-smoke`; both are under the `compiler` stage.
- Scratch goes under `~/do_not_scan`, never `/tmp`.
- The enumerator's reference search (`--search dfs`, every interleaving by
  re-execution) is feasible at one thread only; the gate's search is
  `--search state`. A failure prints the state, the trace and a `replay:`
  line whose pick sequence `--replay '…'` re-executes with `--verbose`.
- The enumerator does not run under the address sanitizer: its coroutine
  stacks defeat the sanitizer's stack model. The smoke does (gcc,
  `-fsanitize=address,undefined`, Linux).
- `WF_SCHED_LANE_SLOTS`, `WF_SCHED_MAX_THREADS` and `WF_SCHED_MAX_STACKS`
  are overridable; the enumerator builds with 2, 4 and 8.
