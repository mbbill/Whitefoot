## 两行代码能不能同时跑

先看一对最普通的调用。程序在处理一棵树，左右子树互不相干：

```
let a = layout(node: move l, inh: h);   // 处理左子树，结果存进 a
let b = layout(node: move r, inh: h);   // 处理右子树，结果存进 b
```

直觉告诉我们，这两行可以同时执行：第二行不需要第一行的结果，两棵子树各写各的内存。编译器现在能把这个直觉变成一条判定。它把前一条语句叫 s1、后一条叫 s2，逐对检查四个条件，四条全过，才承认"同时执行不会被察觉"。

下面每次只改动这对语句的一处，看编译器在哪一条上改口。

### 条件一：后一条不能用前一条的结果

把 b 的参数改成 a：

```
let a = layout(node: move l, inh: h);
let b = layout(node: move r, inh: a);   // ← 这里用了 a
```

b 需要 a 的值才能开始，而同时执行意味着 a 还没算完，b 就要动身。这不是快慢问题，是根本无法执行。编译器的拒绝理由写作 `an argument of s2 uses the result of s1`：s2 的某个参数，用了 s1 的结果。

### 条件二：两条语句碰到的内存不许有交集

换一对函数。bump 把一格内存改成 15，take 只是把参数原样返回：

```
let cell = 1_u64;
let a = bump(slot: &uniq 'r cell);   // 把 cell 从 1 改成 15
let b = take(v: cell);               // 参数按值传入：调用 take 之前，要先读一次 cell
```

take 的签名声明自己不碰任何外部内存。只看签名，这两行井水不犯河水。问题藏在第三行的注释里：参数是按值传的，调用之前得先把 cell 读出来。顺序执行时，这次读发生在 bump 写完之后，take 拿到 15；同时执行时，这次读可能抢在写之前，拿到 1。同一段程序，两种结果。

所以第二条规则是：s1 写的内存，与 s2 读或写的内存不许有交集，反过来也一样；并且"读"要把参数求值这一步算进去。后半句不是设计出来的，是审计在上面这对函数里抓到一个真实的数据竞争之后补上的。

编译器怎么知道一条语句碰哪些内存？这门语言里，每个函数签名都要申报自己读写哪些区域，申报由编译器逐句核对，多报少报都编译不过。把被调函数的申报落到调用处的具体变量上，就得到这条语句碰到的内存清单。

### 条件三：不许有外部动作

再换一对。这次两个函数都往终端打印：

```
let a = print_header(out: &uniq 'o screen);   // 应当先完整打出表头
let b = print_rows(out: &uniq 'o screen);     // 再完整打出表体
```

语言向程序承诺：外部动作严格按代码顺序发生。同时执行会让两段输出的字节交错穿插，而且每次运行穿插得都不一样。所以签名里带外部动作（打印、写文件、等待输入）的调用一律不参加。这类需求属于并发，是另一个课题，没有混进这个版本。

### 条件四：前一条不能中途离场

给 s1 加一条逃生通道。propagate 的意思是：操作失败，就带着错误立刻从整个函数返回：

```
let a = propagate narrow(v: v);   // 转换失败 → 带着错误当场返回整个函数
let b = stamp(slot: move s);      // 往内存里写一个 9
```

顺序执行时，narrow 一失败，stamp 根本不会运行，内存保持原样。同时执行时，stamp 的 9 已经写进去了，函数却带着错误返回了。调用者看到一个"失败了、内存却被改了"的世界，这在顺序语义里不存在。所以第一条语句不许有任何提前离开的路径：错误返回、return、break，有一条就整对否决。

### 第五关：一路上不能有 claim

前四条回答"同时执行是否合法"。第五条回答另一个问题：这个版本敢不敢真的做。要求是：两个被调函数，连同它们直接间接调用的每一个函数，一条 claim 都没有。

claim 是一次运行时检查：条件不成立，程序当场停下，留下一条记录。两条同时执行的线各自撞上 claim 时，先报哪一条、另一条已经做完的事怎么算，需要一整套裁决机制。这个版本的选择是不造这套机制：含 claim 的调用一律照旧顺序执行，一行代码都不用改。这也不是永久除名。检查器每学会证明一类事实，对应的 claim 就可以删掉；删掉的那一刻，这段代码自动获得同时执行的资格。

到这里，五个条件都齐了。前四条保证同时执行与顺序执行在结果上无法区分，第五条把可能在运行中喊停的代码暂时留在场外。每一对语句的判定结果和理由，编译器都打印在一份清单里（编译时加 `--par-ledger`），哪一对过了、哪一对没过、差在哪一条，逐行可查。
